## 第 1 课:毫米波雷达是什么

### 1.1 一句话原理

雷达发出 60GHz 的电磁波(毫米波),打到人身上反射回来,通过分析反射波的**频率、相位变化**,就能"看出"这个人在做什么——在不在、动不动、呼吸多快、心跳多快、甚至是不是摔倒了。

关键:**它"看"的是人体的微动**。

- 人呼吸时,胸腔一起一伏 → 雷达能测出呼吸频率
- 人心脏跳动,胸口微微震动 → 雷达能测出心率
- 人站立 vs 平躺,身体高度不一样 → 雷达能判断跌倒

### 1.2 为什么适合养老院

| 特点 | 好处 |
|---|---|
| 无感 | 不戴手环、不装摄像头,老人没负担 |
| 不侵犯隐私 | 看不到图像,只输出数字 |
| 不受环境影响 | 不怕黑、不怕热、不怕水汽 |

所以它适合放在**卫生间(跌倒)**和**卧室(睡眠呼吸)**这两个最私密、最需要照护、又最不方便装摄像头的地方。

### 1.3 探测范围

- 跌倒雷达:运动探测半径 3 米,跌倒判定半径 2 米
- 呼吸雷达:装在床头,探测范围覆盖整张床

## 第 2 课:两台雷达的分工

| | 跌倒雷达 R60AFD1 | 呼吸心率雷达 R60ASM1 |
|---|---|---|
| 装在哪 | 卫生间天花板 | 卧室床头 |
| 干什么 | 检测人摔倒 | 测呼吸、心率、睡眠 |
| 核心字段 | fallStatus(跌倒) | breathValue(呼吸)、heartRateValue(心率) |
| 上报特点 | 事件触发(摔倒才报) | 持续上报(躺着就报) |

**记一个关键区别**:跌倒雷达是"出了事才喊",呼吸雷达是"一直在报"。

## 第 3 课:MQTT 协议(数据怎么传)

### 3.1 用邮局来理解

MQTT 像一个**邮局**,有三个角色:

1. **发布者(雷达)**:把数据打包成邮件,投递到某个"主题(Topic)"
2. **Broker(服务器)**:邮局,负责收发所有邮件
3. **订阅者(你的脚本)**:告诉邮局"我要订阅某主题",有邮件就收到

### 3.2 Topic(主题)是什么

Topic 是一串路径,像文件夹地址:

```
/Radar60FL/E438192584AA/sys/property/post
 前缀(型号)   设备ID        固定   上报
```

- `Radar60FL` = 跌倒雷达(FL=Fall)
- `Radar60SP` = 睡眠呼吸雷达(SP=Sleep)
- 最后的 `post` = 上报主题,`set` = 下发主题

**订阅了哪个 topic,就收到哪个设备的数据。**

### 3.3 数据长什么样(JSON)

雷达发的每条数据是 JSON 格式:

```json
{
  "version": "1.0",
  "method": "post",
  "params": { "breathValue": "18" }
}
```

- `method: post` = 主动上报
- `params` 里就是具体数据,比如呼吸 18 次/分

**注意:数值是字符串** `"18"`,不是数字 18,代码里要转换。

## 第 4 课:数据怎么从雷达到你眼前

```
雷达 →(发MQTT消息)→ Broker服务器 →(订阅)→ Python脚本 → 屏幕显示
```

四步:
1. 雷达检测到数据(呼吸18)
2. 打包成 JSON,发到 Broker 的 `/Radar60SP/xxx/post` 主题
3. 你的脚本订阅了这个主题,Broker 把消息推给你
4. 脚本解析 JSON,把"呼吸=18"打印出来

**你写的脚本,本质就是一个"订阅者",等着收邮件。**

## 第 5 课:数据字段解读

### 5.1 跌倒雷达的关键字段

| 字段 | 含义 | 取值 |
|---|---|---|
| someoneExists | 有人/无人 | 0无人 / 1有人 |
| motionStatus | 运动状态 | 0无 / 1静止 / 2活跃 |
| movementSigns | 体动幅度 | 0~100 |
| **fallStatus** | **跌倒报警** | 0未跌倒 / 1跌倒 |
| residentStatus | 静止驻留 | 0/1 |

### 5.2 呼吸雷达的关键字段

| 字段 | 含义 | 取值 |
|---|---|---|
| breathValue | 呼吸数值 | 次/分 |
| heartRateValue | 心率 | 次/分 |
| sleepStatus | 睡眠状态 | 0深睡/1浅睡/2清醒/3无 |
| getIntoBed | 入离床 | 0离床/1入床 |
| sleepScore | 睡眠评分 | 0~100 |

### 5.3 一个重要机制:状态变化才上报

"有人/无人"不是每秒报,而是**状态变了才报一次**:
- 无人→有人:0.5 秒内报
- 有人→无人:30 秒后报

所以监控脚本平时安静,状态翻转时才冒出一行,这是正常的。

## 第 6 课:三个必须搞懂的参数

| 参数 | 作用 | 跌倒雷达 | 呼吸雷达 |
|---|---|---|---|
| sceneMode 场景模式 | 告诉雷达你装哪个房间,算法匹配环境 | 3=卫生间 | 2=卧室 |
| installHeight 安装高度 | 告诉雷达自己离地多高,判断高度差 | 230cm | 实际层高 |
| fallDuration 跌倒确认时长 | 躺多久才确认是跌倒 | 最小 5 秒 | 无 |

**为什么场景模式重要**:卫生间有淋浴、排风、振动干扰,卧室没有。雷达要知道自己在哪,才能正确过滤干扰、降低误报。不设场景,跌倒雷达容易把淋浴当成人、把排风当成活动。

## 第 7 课:配网为什么要"长按两次"

雷达没屏幕、没键盘,只有一个按键。它靠**长按时长**切换模式:

1. **长按 10 秒** → 开 WiFi 热点 → 你用手机连它,填"数据发到哪个服务器"
2. **长按到灯闪** → 开蓝牙 → 你用 APP 通过蓝牙把"WiFi 密码"喂给它

核心记忆:**灯闪了才松手**。很多人"灯一灭就松",太早,进不去蓝牙配网模式。

## 小结(一页记住)

1. 雷达"看"人体微动,测呼吸、心跳、跌倒
2. 数据走 MQTT:雷达发布 → Broker 中转 → 脚本订阅
3. 跌倒雷达"出事才报",呼吸雷达"一直报"
4. 配网两次长按:10 秒填服务器,灯闪松手连 WiFi
5. 三参数:场景模式、安装高度、跌倒确认时长
