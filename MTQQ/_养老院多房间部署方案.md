# 养老院多房间雷达部署方案

> 场景:养老院/护理院,多房间(101、102、103...)+ 卫生间,每房部署睡眠/跌倒雷达
> 版本:v1.0,2026-08-16
> 关联:《_HomeAssistant接入方案.md》《_使用手册.md》

---

## 0. 核心结论

养老院部署的第一要务**不是接 Home Assistant,而是建立「设备ID ↔ 房间号」台账**。有了台账:

- 配置由脚本自动生成(不手敲 YAML)
- 房间/老人变动只改台账、重跑脚本
- 每台设备数据按房间隔离

一句话流程:**建台账 → 逐台配网记录设备ID → 脚本生成配置 → HA 按楼层/房间组织 → 自动化告警到护士站**。

---

## 1. 台账设计(命脉)

CSV 格式,一行一台设备。字段:

| 字段 | 含义 | 示例 | 说明 |
|---|---|---|---|
| `device_id` | 雷达设备 ID | `RadarID_ABC123` | 配网时从 192.168.0.1 页或 MQTT topic 获取 |
| `room` | 房间号 | `101` | 核心标识 |
| `floor` | 楼层 | `1` | 用于 HA 楼层分组 |
| `bed` | 床位号 | `01` | 可选,多床间区分 |
| `resident` | 老人姓名 | `张三` | 可选,用于告警文案 |
| `product` | 产品型号 | `R60ABD1` / `R60AFD1` | 决定协议前缀和字段 |
| `scene_mode` | 场景模式 | `2` | 1客厅/2卧室/3卫生间 |
| `install_height` | 安装高度(cm) | `220` | 170~310 |

`device_list.csv` 示例:

```csv
device_id,room,floor,bed,resident,product,scene_mode,install_height
RadarID_ABC123,101,1,01,张三,R60ABD1,2,220
RadarID_DEF456,102,1,01,李四,R60ABD1,2,220
RadarID_GHI789,101卫生间,1,,,R60AFD1,3,240
```

> 同房间多设备(睡眠雷达 + 跌倒雷达)就是两行,`room` 相同、`product` 不同、`device_id` 不同。

## 2. 部署流水线(7 步)

| 步 | 动作 | 产出 |
|---|---|---|
| 1 | 建台账 `device_list.csv`(先只填房间号/产品/楼层,device_id 留空) | 台账骨架 |
| 2 | 部署 MQTT Broker(EMQX 推荐,养老院并发高) | broker 地址+账号 |
| 3 | **逐台配网**,按房间顺序,配完立刻在台账回填 device_id | 完整台账 |
| 4 | 逐台下发 `sceneMode` + `installHeight`(场景算法校准) | 设备校准 |
| 5 | 跑脚本 `gen_ha_config.py` 生成 `mqtt_sensors.yaml` | 配置片段 |
| 6 | 粘贴进 `configuration.yaml`,重载 | 实体生成 |
| 7 | 建楼层/房间 Area,配自动化告警 | 可运营 |

---

## 3. 配置生成脚本

同目录 `gen_ha_config.py`。用法:

```bash
python gen_ha_config.py device_list.csv > mqtt_sensors.yaml
```

生成结果贴进 HA 的 `configuration.yaml`。脚本自动:

- 按产品映射协议前缀(`R60ABD1`→`/Radar60SP/`,`R60AFD1`→`/Radar60FL/`)
- 用具体 `device_id` 拼 topic(多房间隔离,不用通配符)
- 每个实体带 `device` 块归组,设备名 = `{房间}_{产品}`
- 自动生成全部传感器字段

## 4. HA 房间组织

```
楼层1(Floor)
├── 101(Area)
│   ├── 设备:101_睡眠雷达(R60ABD1)
│   └── 设备:101卫生间_跌倒雷达(R60AFD1)
├── 102(Area)
│   └── 设备:102_睡眠雷达
└── ...
楼层2(Floor)
└── 201 / 202 ...
```

操作:设置 → 区域与地点 → 先建"楼层1""楼层2"楼层 → 每个房间建 Area 并归属楼层 → 给设备分配 Area。

脚本生成的 `device.name` 已带房间号,分配 Area 时一眼能对上。

## 5. 养老院专属自动化

养老院告警**不送到老人手机,送到护士站 + 值班人员**。

### 5.1 告警分级

| 级别 | 事件 | 通知对象 | 方式 |
|---|---|---|---|
| 紧急 | 跌倒、呼吸暂停、离床超 30min | 护士站大屏 + 值班手机 | 声光 + 推送 |
| 重要 | 心率异常、睡眠异常 | 值班手机 | 推送 |
| 提示 | 有人/无人状态、离床 | 护士站大屏 | 仅看板展示 |

### 5.2 跌倒告警模板(带房间号定位)

```yaml
automation:
  - alias: "跌倒告警_全楼"
    trigger:
      - platform: state
        entity_id:
          - binary_sensor.101weijian_die_dao
          - binary_sensor.102weijian_die_dao
        to: "on"
    action:
      - service: notify.mobile_app_值班手机
        data:
          title: "⚠️ 跌倒告警"
          message: "{{ trigger.to_state.attributes.friendly_name }} 触发跌倒,请立即查看!"
```

> `friendly_name` 已带房间号(脚本生成),告警文案自动定位到房间。

### 5.3 护士站大屏

HA 的 Lovelace 仪表盘跑在护士站显示器上,用「楼层 → 房间 → 卡片」分组,跌倒/离床用醒目颜色卡片。可用 `auto-entities` 卡片按状态自动排序(报警房间置顶)。

## 6. 需要你确认的关键点

| 问题 | 影响 |
|---|---|
| 房间总量(几十/上百?) | 决定 Broker 选 EMQX 还是 Mosquitto |
| 告警送到哪(护士站大屏?值班手机?企业微信/钉钉?) | 决定通知通道 |
| 是否对接 KangxiaobanAI 护工端 | 决定 MQTT 是否同时喂给护工端 |
| 是否已有养老院管理系统 | 决定是独立 HA 还是集成 |

确认后我再帮你把告警通道、护士站大屏、护工端对接细化。
