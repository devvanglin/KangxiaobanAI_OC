## 0. 目录是什么

`MTQQ` 目录名是 **MQTT** 的谐音,本质是 **60G 毫米波雷达的对接资料包**,服务养老看护场景。共 6 个文件,2 个产品系列:

2. **UART 串口协议**(对上位机/嵌入式主机,二进制帧,适合本地控制)

外加一份配网教程和一个安卓配网 APP。

## 1. MQTT 协议通则(文件 1、2 共有)

### 1.1 传输格式

- 数据以 **JSON 文本** 通过 MQTT 传输
- 每个雷达设备在 MQTT broker 上注册后,持有 2 个 Topic

### 1.2 Topic 命名规则

| 产品 | 上报主题(设备 → 云) | 下发主题(云 → 设备) |
|---|---|---|
| R60ABD1 睡眠 | `/Radar60SP/{设备ID}/sys/property/post` | `/Radar60SP/{设备ID}/sys/property/set` |
| R60AFD1 跌倒 | `/Radar60FL/{设备ID}/sys/property/post` | `/Radar60FL/{设备ID}/sys/property/set` |

注意 Topic 前缀差异:`Radar60SP`(Sleep)vs `Radar60FL`(Fall)。`{设备ID}` 在配网时由设备分配。

### 1.3 三种方法(method)

每条消息 JSON 顶层有 `version`、`method`、`params` 三个字段:

```json
{
  "version": "1.0",
  "method": "post | get | set",
  "params": { ... }
}
```

| method | 含义 | 触发方 | 响应方回复的 `opt` |
|---|---|---|---|
| `post` | 主动上报(状态变化或周期性) | 设备 | — |
| `get` | 查询属性 | 客户(云) | `get` |
| `set` | 设置属性 | 客户(云) | `set` |
| `limit_get` / `limit_set` | 查询/设置禁止上报开关 | 客户 | `limit_get` / `limit_set` |
| `qos_get` / `qos_set` | 查询/设置 QoS | 客户 | `qos_get` / `qos_set` |
| `ota set` / `ota post` | OTA 升级下发 / 进度上报 | 客户/设备 | `otaInform` |

响应消息结构:

```json
{
  "version": "1.0",
  "opt": "get | set | ...",
  "res": "success | fail",
  "params": { ... }
}
```

### 1.4 属性上报模式分类

文档中每个属性都明确标注以下两类:

- **主动上报**:设备 → 云,触发方式分为"状态变化时上报"或"周期性上报"
- **不支持主动上报**:客户必须 `get` 查询才能拿到

**禁止上报机制**(高频属性屏蔽):部分高频上报属性(workDuration/someoneExists/motionStatus/movementSigns/humanDistance/humanPosition/heartBeat/proportionOfHeight)可用 `limit_set` 关闭,值为 1 禁止、0 允许。

### 1.5 字段值规范

- **数值统一字符串化**:即使数值型字段,JSON 中也用字符串传输,例如 `"breathValue": "1"` 而非 `1`。解析时必须做字符串→数值转换。
- **多字节字段**:数组形式,例如呼吸波形 `"breathWave": [128,128,128,128,128]`(5 个字节,1s 内 5 个采样点)。
- **三维坐标**:`humanPosition` 和 `installAngle` 是 `{x, y, z}` 对象,各轴 0~65535,cm 单位。

|---|---|---|---|

| `someoneExists` | 0=无人,1=有人 | 状态变化 | 人体存在状态 |

### 2.3 呼吸域(breath*)

| 属性 | 取值 | 上报方式 |
|---|---|---|
| `breathSwitch` | 0/1 | 否,可设 |
| `breathInform` | 1=正常,2=过高,3=过低,4=探测中 | 状态变化 |
| `breathValue` | 0~40 次/min | 状态变化 |
| `breathIntensity` | 0~100 | 状态变化 |
| `breathConfidence` | 0~100 | 状态变化 |
| `breathWave` | 5 个 0~255 整数数组,中轴 128 | 周期性 1s |

| `breathConfidenceReportFrequency` | 0~200 | 否,可设 |

### 2.4 心率域(heartRate*)

结构与呼吸域完全对称,范围不同:

- `heartRateSwitch` 0/1
- `heartRateInform` 1=正常/2=过高/3=过低/4=探测中
- `heartRateValue` 60~120 次/min
- `heartRateIntensity` 0~100
- `heartRateConfidence` 0~100
- `heartRateWave` 5 个 0~255 整数数组(正弦波,中轴 128)
- 4 个 `*ReportFrequency` 0~200

### 2.5 睡眠域(sleep*)

| 属性 | 取值 | 上报方式 | 说明 |
|---|---|---|---|
| `sleepSwitch` | 0/1 | 否,可设 | 睡眠功能开关 |
| `sleepStatus` | 0=深睡,1=浅睡,2=清醒,3=无(离床) | 主动 | 睡眠状态 |
| `getIntoBed` | 0=离床,1=入床 | 状态变化 | 入离床状态 |
| `awakeDuration` | 0~65536 分钟 | 主动 | 清醒时长 |
| `lightSleepDuration` | 0~65536 分钟 | 主动 | 浅睡时长 |
| `deepSleepDuration` | 0~65536 分钟 | 主动 | 深睡时长 |
| `sleepScore` | 0~100 分 | 主动 | 睡眠评分(4≤h≤12 才输出有效) |
| `*ReportFrequency` | 0~200 | 否,可设 | 各时长上报频率 |

#### 复合上报字段(关键)

**`sleepComprehensiveStatus`** — 8 字节数组,10 分钟一次:

```json
"sleepComprehensiveStatus": [存在, 睡眠状态, 平均呼吸, 平均心跳, 翻身次数, 大幅度体动占比, 小幅度体动占比, 呼吸暂停次数]
```

**`sleepQualityAnalysis`** — 12 字节数组,睡眠过程结束时上报:

```json
"sleepQualityAnalysis": [睡眠评分, 睡眠总时长高8位, 睡眠总时长低8位, 清醒占比, 浅睡占比, 深睡占比, 离床时长, 离床次数, 翻身次数, 平均呼吸, 平均心跳, 呼吸暂停次数]
```

注意"睡眠总时长"占 2 字节,需高 8 位+低 8 位合并计算。

**`abnormalSleep`** — 0=时长不足 4h,1=时长大于 12h,2=长时间异常无人,3=无。

**`reportMode`** — 0=实时数据传输,1=睡眠状态传输(注:UART V3.1 已取消,但 MQTT 文档仍保留)。

**`breathMode`** — 01=正常,02=高频。

### 2.6 限制上报(limit_*)与 QoS

可屏蔽的高频属性:workDuration、locationOutOfBounds、someoneExists、motionStatus、movementSigns、humanDistance、humanPosition、heartBeat。

```json
// 查询
{"version":"1.0","method":"limit_get","params":{"someoneExists":"?", ...}}

// 设置(1=禁止上报,0=允许)
{"version":"1.0","method":"limit_set","params":{"someoneExists":"1", ...}}
```

QoS 默认 1,可设 0/1/2:

```json
{"version":"1.0","method":"qos_set","params":{"Qos post":"1"}}
```

### 2.7 OTA

```json
// 1. 选择升级模组(0=WiFi 模组,1=雷达模组,默认 0)
{"version":"1.0","method":"ota set","params":{"module":"0"}}

// 2. 下发固件 URL + 端口(客户需自建 web 服务器)
{"version":"1.0","method":"ota set","params":{"otaInform":{"firmwareUrl":"http://192.168.31.88/app.rbl","port":"8090"}}}

// 3. 升级进度上报(0~100)
{"version":"1.0","method":"ota post","params":{"downloadProgress":"50"}}
```

失败返回:`{"opt":"otaInform","res":"fail","msg":"ota failed!"}`

| 字节 | 含义 |
|---|---|

| 3B | 0~0.5m 高度占比 |

## 4. UART 串口协议通则(文件 3、4 共有)

### 4.1 串口参数

| 项 | 值 |
|---|---|
| 接口电平 | TTL |
| 波特率 | 115200 bps |
| 数据位 | 8 |
| 停止位 | 1 |
| 奇偶校验 | 无 |

### 4.2 帧结构

```
帧头(2B) | 控制字(1B) | 命令字(1B) | 长度标识(2B) | 数据(nB) | 校验码(1B) | 帧尾(2B)
0x53 0x59 | Control   | Command   | LenH LenL    | Data     | Sum        | 0x54 0x43
```

- **帧头**:固定 `0x53 0x59`(ASCII "SY")
- **帧尾**:固定 `0x54 0x43`(ASCII "TC")
- **长度标识**:大端 2 字节,等于数据字段字节数
- **校验码**:Sum = (帧头 + 控制字 + 命令字 + 长度标识 + 数据)求和后取低 8 位

### 4.3 控制字(Control)分配

| 控制字 | R60ABD1 含义 | R60AFD1 含义 |
|---|---|---|
| `0x01` | 心跳包标识 | 心跳包标识 |
| `0x02` | 产品信息 | 产品信息 |
| `0x03` | OTA 升级 | OTA 升级 |
| `0x05` | 工作状态 | 工作状态 |
| `0x06` | — | 安装方式 |
| `0x07` | 雷达探测范围信息 | — |
| `0x80` | 人体存在 | 人体存在 |
| `0x81` | 呼吸检测 | — |
| `0x83` | — | 跌倒检测 |
| `0x84` | 睡眠监测 | — |
| `0x85` | 心率监测 | — |

### 4.4 命令字(Command)约定

- `0x00~0x7F`:主动上报 / 设置下发
- `0x80~0xFF`:查询下发(查询命令字 = 设置命令字 + 0x80)
- `0x0F`:常用查询请求占位符

### 4.5 校验码计算示例

例:查询人体存在信息(命令 `5359 80 81 0001 0F sum 5443`)

```
Sum = 0x53 + 0x59 + 0x80 + 0x81 + 0x00 + 0x01 + 0x0F = 0x01BD
取低 8 位 = 0xBD
完整指令 = 53 59 80 81 00 01 0F BD 54 43
```

## 5. R60ABD1 UART 串口协议详解(文件 3)

### 5.1 硬件设计规范

- **额定电压**:4.9~6V
- **额定电流**:≥ 200mA
- **电源纹波**:≤ 100mV
- **PCBA**:雷达贴件高度比其他器件 ≥ 1mm
- **外壳结构**:天线面距外壳 2~5mm
- **外壳探测面**:非金属,平直避免弯曲
- **静电防护**:运输/存储/操作全程防静电,戴防静电手套,只触摸边角

### 5.2 功能点(DP1~DP20)

| DP | 功能 | 上报方式 | 数值范围 |
|---|---|---|---|
| DP1 | 有人/无人 | 状态变化(无人→有人 0.5s,有人→无人 40s) | 0/1 |
| DP2 | 有人静止/活跃 | 状态变化,0.5s 内 | 0/1 |
| DP3 | 人体距离 | 2s 一次 | 0~65535 cm |
| DP4 | 体动幅度 | 1s 一次 | 0~100 |
| DP5 | 人体方位 | 2s 一次,6B(x,y,z 各 2B) | 有正负(首位 0=负,1=正) |
| DP6 | 心跳数值 | 3s 一次 | 60~120 |
| DP7 | 心率波形 | 1s 一次,5B | 0~2(真实值+128) |
| DP8 | 呼吸数值 | 3s 一次 | 0~35 |
| DP9 | 呼吸信息 | 状态变化 | 过高>25,过低<10,正常 10~25,无 |
| DP10 | 呼吸波形 | 1s 一次,5B | 0~153(真实值+128) |
| DP11 | 入床/离床 | 状态变化 | 离床→入床满足能量条件,入床→离床 30s |
| DP12 | 睡眠状态 | 入床下 10min 一次 | 深睡/浅睡/清醒 |
| DP13 | 清醒/浅睡/深睡时长 | 跟随 10min 睡眠状态 | 0~65535 分钟 |
| DP14 | 睡眠质量评分 | 睡眠过程结束 | 0~100,异常=0,需 4≤h≤12 |
| DP15 | 睡眠综合状态 | 10min 一次,8B | 见下方 |

### 5.6 OTA 流程(UART)

1. **开始 OTA**:`5359 03 01 0004 4B固件包大小 sum 5443`(大端在前,例如固件 150KB=0x00025800 → `00 02 58 00`)
2. **回复每帧大小**:`5359 03 01 0004 4B每帧传输大小 sum 5443`
3. **升级包传输**:`5359 03 02 len+4 {4B包偏移地址 + lenB数据包} sum 5443`,回复 `01`=接收成功,`02`=失败
4. **结束 OTA**:`5359 03 03 0001 {01完成\|02未完成} sum 5443`,回复 `00`/`01`

## 7. 配网流程(文件 5 + 文件 6)

### 7.1 整体流程

雷达设备对接客户平台分两步:

1. **MQTT 配置**(配置 broker 地址等,只需一次)
2. **WiFi 模组配网**(连接路由器,可重复)
3. **(可选)静态 IP 配置**

### 7.2 步骤一:MQTT 配置

1. 长按按键 **10s 以上**,模组起 AP: `RadarConfig-xxxxxxxxxxxx`
2. 手机连接该 AP,浏览器访问 `192.168.0.1`
3. 在配置界面填写 MQTT 服务器信息:
   - 服务器地址格式:`tcp://broker.emqx.io:1883`
   - clientID、用户名、密码
4. 点击"修改"提交,页面自动刷新
5. 点击"设置完成,退出",模组重启

### 7.3 步骤二:WiFi 模组配网

> **前置条件**:指示灯必须闪烁。不闪烁 = 失败,需重新开始。

1. 长按按键 **5s 左右**,LED 灯灭即可松开,LED 开始闪烁
2. WiFi 模组起 BLE 蓝牙: `Radar_BLE`
3. 手机打开蓝牙,使用安卓 APP **"BK BLE WIFI"** 配网(目前**仅支持安卓**)
4. 准备一个 2.4G 路由器或手机热点:
   - 频段必须 **2.4G**(5G 不支持)
   - SSID 和密码须与最终配置一致
5. 打开 BK BLE WIFI APP,操作:
   - `CHOOSE BLUETOOTH` 选择蓝牙(数量为 0 时等十几秒)
   - `CHOOSE SSID` 选择热点名
   - 填写热点密码
   - 点击 `START CONFGURING NETWORK`
   - 提示 `Network configuration successful` = 配网成功
6. **配网超时 90s**,超时需重新长按按键

### 7.4 步骤三:静态 IP 配置(可选)

1. 关闭热点,雷达与热点断开
2. 长按按键 **10s 以上**,起 AP `RadarConfig-xxxxxxxxxxxx`
3. 手机连接,浏览器访问 `192.168.0.1`
4. 选择"配置静态地址"
5. 填写静态 IP 地址等信息
6. 勾选"开启静态 IP 功能"为"开"
7. 完成后,再次长按按键 5s 进 BLE 配网模式
8. 用 BK BLE WIFI APP 重新配网(选择目标 WiFi)

### 7.5 配网 APP(文件 6)

- 文件名:`BK_BLE5.apk.1`(BEKEN 芯片厂 BLE 配网工具)
- 使用前需**改名为 `BK_BLE5.apk`**(去掉 `.1` 后缀)
- 仅安卓,2.4MB+
- 安装后可能需授予蓝牙、位置权限

### 7.6 配网常见坑

| 问题 | 原因 | 解决 |
|---|---|---|
| AP 搜不到 | 长按时间不够 10s | 重新长按,确保 ≥ 10s |
| BLE 搜不到 Radar_BLE | 进入模式时间不够 | 等十几秒再扫描 |
| 配网提示失败 | 路由器是 5G | 切 2.4G,或开双频合一 |
| 配网超时 | 超过 90s | 重新长按 5s 进配网模式 |
| 配网后无法上线 | MQTT broker 信息错误 | 重做步骤一,核对地址/账号/密码 |
| 静态 IP 不生效 | 未勾"开启" | 进 AP 配置页确认勾选"开" |

### 8.4 数值解析注意事项

1. **MQTT 数值都是字符串**:`"heartRateValue": "75"` 而非 `"heartRateValue": 75`。解析务必 `parseInt()`。
2. **波形是数组**:`"breathWave": [128,128,128,128,128]`,5 个字节代表 1s 内 5 个采样点,中轴 128(即 0 强度时显示为 128)。
3. **三维坐标**:`humanPosition` 是 `{x, y, z}` 对象,不是数组。
4. **多字节字段拼接**:UART 16 位数值大端在前;`sleepQualityAnalysis` 的"睡眠总时长"占 2B,需 `(高8位 << 8) | 低8位`。
5. **UART 方位符号位**:16 位数据,首位 0=负,1=正,剩余 15 位为数值(注意:R60ABD1 用户手册中 6.1 章节正文写"14 位",但实际为 15 位,文档原文存在笔误)。
6. **OTA 起始指令长度**:R60ABD1 V3.3 为 `0004`,R60AFD1 V1.1 文档第 13 页写 `0013`(4B+15B 固件版本号),实施前必须核对当前固件版本对应文档。
