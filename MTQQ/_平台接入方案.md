# 平台接入方案:房间绑定设备 → 实时看数值

> 目标:在自己的平台里,把某房间绑定某台毫米波雷达,实时看到该房间的呼吸/心率/睡眠/跌倒等数值
> 版本:v1.0,2026-08-16
> 前置:已跑通雷达配网,数据能发到 MQTT Broker(见《_HomeAssistant接入方案.md》第 3 节)

---

## 0. 结论

自己平台接入,本质是三条链路 + 一张绑定表:

1. **订阅**:后端订阅 MQTT,拿到所有雷达数据
2. **路由**:从消息里认出是"哪台设备",查绑定表定位"哪个房间"
3. **推送**:把数据实时推给前端,前端按房间展示

「为房间绑定设备」这个功能,在数据层就是一张**绑定关系表**。表建对,其余都是流水线。

---

## 1. 总体架构与数据流

```
┌──────────────┐    MQTT(JSON)    ┌──────────────┐   订阅       ┌──────────────────────┐
│ 雷达(各房间)  │ ───────────────► │ MQTT Broker   │ ──────────► │ 你的后端服务           │
│ R60ABD1/FL   │                  │ (EMQX)        │             │ ①订阅 /Radar60SP/#   │
└──────────────┘                  └──────────────┘             │ ②topic提取device_id  │
                                                                │ ③查绑定表→房间        │
                                                                │ ④解析数值            │
                                                                │ ⑤写库 + WebSocket推   │
                                                                └──────────┬───────────┘
                                                                           │ WebSocket / REST
                                                                           ▼
                                                              ┌──────────────────────┐
                                                              │ 前端(护工端/Web后台)  │
                                                              │ 按房间展示:101房间  │
                                                              │  呼吸18 心率72 深睡  │
                                                              └──────────────────────┘
```

## 2. 数据模型(核心)

「房间绑定设备」落到数据库就是三张表 + 一张关系表:

### 2.1 设备表 device

| 字段 | 类型 | 说明 |
|---|---|---|
| device_id | string PK | 雷达唯一 ID(配网时从 192.168.0.1 抄) |
| product_type | enum | R60ABD1 / R60AFD1 |
| scene_mode | int | 1客厅/2卧室/3卫生间 |
| install_height | int | 安装高度 cm |
| install_angle | int | 0 或 45 |

### 2.2 房间表 room

| 字段 | 类型 | 说明 |
|---|---|---|
| room_id | string PK | 内部 ID |
| room_no | string | "101" / "101卫生间" |
| floor | int | 楼层 |
| bed_no | string | 床位号(可选) |
| resident_name | string | 老人姓名(可选) |

### 2.3 绑定关系表 room_device(核心)

| 字段 | 类型 | 说明 |
|---|---|---|
| room_id | string FK | 房间 |
| device_id | string FK | 设备 |
| 联合主键 (room_id, device_id) | | 一个房间可绑多台(睡眠+跌倒) |

> **这就是"为房间绑定设备"功能的全部**。前端点"绑定",就是往这张表插一行;点"解绑",就是删一行。数据路由全靠它。

### 2.4 实时状态存储(可选)

- 实时值 → Redis(`room:{room_id}:{field} = value`)
- 历史值 → 时序库(InfluxDB / TimescaleDB)或 MySQL 分表,按 room_id + 时间索引

## 3. 后端关键逻辑

```python
# 伪代码:一条雷达消息的处理
def on_radar_message(topic, payload):
    device_id = topic.split("/")[2]              # /Radar60SP/{device_id}/sys/property/post
    data = json.loads(payload)
    params = data.get("params", {})

    binding = get_binding(device_id)             # 查 room_device 表
    if not binding:
        log("未绑定的设备", device_id); return
    room = binding.room

    for field, value in params.items():          # 一条消息可能含1个字段
        update_state(room, field, value)         # 写 Redis
        push_to_frontend(room, field, value)     # WebSocket 推送
```

要点:
- **topic 里自带 device_id**,不用依赖消息内容,天然可靠
- **绑定表是唯一路由依据**,未绑定设备直接忽略
- 一条消息通常只含 1 个字段(状态变化上报),遍历 `params` 即可

## 4. 最小可运行 Demo

同目录给了三个文件,可直接跑通「数据 → 房间」的完整链路:

| 文件 | 作用 |
|---|---|
| `room_device_map.json` | 绑定表(JSON 版,生产换数据库) |
| `mqtt_bridge_demo.py` | 订阅 MQTT → 路由 → 打印房间数值 |

用法:

```bash
# 真连 broker(把地址改成你的)
python mqtt_bridge_demo.py --host 192.168.1.100

# 无 broker 时用模拟消息验证路由逻辑
python mqtt_bridge_demo.py --mock
```

`--mock` 模式会本地生成几条假消息走一遍路由,你立刻能看懂"数据怎么归到房间"。

## 5. 与 KangxiaobanAI 衔接(重点)

你的主产品 KangxiaobanAI(HarmonyOS NEXT 护工端)目前是**纯本地 mock,无网络层**。要接真雷达,需要补两块:

| 缺口 | 现状 | 要做的事 |
|---|---|---|
| 后端服务 | 不存在 | 新建:MQTT 订阅 + 绑定路由 + WebSocket 推送(本方案) |
| 前端网络层 | 无,数据全内联 mock | 加 WebSocket 客户端,替换 `humanDistance`/`humanPosition` 等 mock 字段 |

衔接路径:
1. 后端提供 WebSocket 端点,按房间推送实时值
2. HarmonyOS 端用 `@ohos.net.webSocket` 订阅
3. 把现有 `TabPageView` / `WideResidentPage` 里的雷达 mock 数据换成真实推送
4. `humanPosition`/`humanDistance`/`motionStatus` 字段语义与雷达协议**完全同名**,映射成本极低(这正是当初 mock 取名取自雷达协议的收益)
