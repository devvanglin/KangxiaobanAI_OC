# 老师简明逐字稿：照着做就能上

建议课时：60 分钟。

老师不用先学完整的“一次开发、多端部署”理论。本课只让学生看到一个结果：

```text
窗口窄：两张卡片上下排列
窗口宽：两张卡片左右排列
```

全课只填写 4 个 TODO。

---

## 一、老师课前只做这 5 件事

### 1. 新建练习工程

使用 DevEco Studio 新建 ArkTS Empty Ability 工程。

### 2. 修改设备配置

打开：

```text
entry/src/main/module.json5
```

找到 `deviceTypes`，改成：

```json5
"deviceTypes": [
  "phone",
  "tablet",
  "2in1"
],
```

如果不改，运行 Tablet 时会出现：

```text
Required device type: tablet
current module device type: phone
```

这个报错和 `Index.ets` 无关，是工程只允许手机运行。

### 3. 放入学生代码

用 `starter/Index.ets` 整体替换新工程的入口 `Index.ets`。

### 4. 准备教师答案

把 `teacher/Index.completed.ets` 放在旁边。课堂代码乱了，可以直接用它恢复。

### 5. 亲自运行一次

确认：

- 窄窗口上下排列；
- 宽窗口左右排列；
- 顶部文字会变化。

---

## 二、老师只需要记住这 3 句话

1. 同一份 `Index.ets` 可以在手机和平板运行。
2. 窗口窄时上下排，窗口宽时左右排。
3. 我们不复制两套页面，只修改卡片占几列。

如果学生问什么是断点，老师只说：

> 断点就是窗口宽度的分界线。窗口跨过分界线，页面就换一种排列方式。

不需要继续解释底层原理。

## 三、60 分钟课堂逐字稿

## 第 1 步：先看结果，0～5 分钟

老师操作：打开教师完成版，先显示窄窗口，再把窗口拉宽。

老师说：

> 今天我们不写两个工程，只用一份页面代码。现在窗口比较窄，两张卡片上下排列。我把窗口拉宽以后，两张卡片会左右排列。

> 大家今天只需要完成 4 个 TODO。其他样式代码不用修改。

## 第 2 步：说清今天学什么，5～10 分钟

老师说：

> 手机空间比较窄，适合上下排列。平板或电脑窗口比较宽，适合左右排列。

> 我们不根据设备名字死记布局，而是看当前窗口宽不宽。平板如果缩成小窗口，也应该使用上下排列。

板书：

```text
窄窗口 → 上下排列
宽窗口 → 左右排列
```

## 第 3 步：检查设备配置，10～15 分钟

老师让学生打开：

```text
entry/src/main/module.json5
```

老师说：

> 请确认 `deviceTypes` 中有 `phone`、`tablet` 和 `2in1`。如果这里只有 `phone`，Tablet 会在编译页面之前直接报错。

屏幕展示：

```json5
"deviceTypes": [
  "phone",
  "tablet",
  "2in1"
],
```

老师说：

> 修改后保存。我们现在允许同一个练习工程运行在三种设备形态上。

## 第 4 步：找到 4 个 TODO，15～20 分钟

老师操作：打开学生起始版 `Index.ets`，搜索 `TODO`。

老师说：

> 请按两次 Shift 搜索 TODO，或者按 Ctrl+F 搜索 TODO。我们只改这四处，其他代码先不碰。

让学生确认能看到：

```text
TODO 1：保存当前窗口档位
TODO 2：设置左边卡片占几列
TODO 3：设置右边卡片占几列
TODO 4：设置页面边距
```

## 第 5 步：填写 TODO 1，20～25 分钟

找到：

```typescript
.onBreakpointChange((breakpoint: string) => {
  // TODO 1
})
```

老师说：

> 当窗口宽度变化时，系统会把当前档位放进 `breakpoint`。我们把它保存起来。

让学生填写：

```typescript
this.currentBreakpoint = breakpoint;
```

老师说：

> 这一行填完后，顶部的“手机单列”和“宽屏双栏”才能跟着窗口变化。

## 第 6 步：填写 TODO 2，25～30 分钟

找到左侧卡片的 `span`。

老师说：

> `span` 可以先理解为卡片占几格。请直接填写下面这一行。

```typescript
span: { xs: 4, sm: 4, md: 3, lg: 4, xl: 4 }
```

老师只需要补充一句：

> 前面两个 4 负责窄窗口，后面的数字负责宽窗口。

## 第 7 步：填写 TODO 3，30～35 分钟

找到右侧卡片的 `span`。

让学生填写：

```typescript
span: { xs: 4, sm: 4, md: 5, lg: 8, xl: 8 }
```

老师说：

> 窄窗口时，两张卡片都占满一行，所以会上下排列。宽窗口时，左卡和右卡能放进同一行，所以会左右排列。

不需要让学生背所有数字。

## 第 8 步：填写 TODO 4，35～40 分钟

找到：

```typescript
private pagePadding(): number {
  // TODO 4
  return 16;
}
```

替换成：

```typescript
private pagePadding(): number {
  return this.isWideLayout() ? 32 : 16;
}
```

老师说：

> 宽窗口空间多，边距使用 32；窄窗口空间少，边距使用 16。

## 第 9 步：运行窄窗口，40～47 分钟

老师说：

> 现在先检查窄窗口。请把窗口缩窄，或者选择 Phone 预览。

检查三件事：

1. 顶部显示“当前布局：手机单列”；
2. 长者信息卡在上；
3. 今日任务卡在下。

老师说：

> 三项都对，就截一张窄窗口图片。

## 第 10 步：运行宽窗口，47～55 分钟

老师说：

> 接下来把窗口拉宽，或者选择 Tablet 预览。

检查三件事：

1. 顶部显示“当前布局：宽屏双栏”；
2. 长者信息卡在左；
3. 今日任务卡在右。

老师说：

> 三项都对，再截一张宽窗口图片。

## 第 11 步：总结和提交，55～60 分钟

老师说：

> 今天我们只维护了一份 `Index.ets`。窗口窄时上下排列，窗口宽时左右排列，这就是本课要理解的“一次开发、多端部署”。

> 请提交完成后的 `Index.ets`、窄窗口截图、宽窗口截图和提交单。

最后让全班一起回答：

> 窗口窄怎么排？

学生回答：上下排。

> 窗口宽怎么排？

学生回答：左右排。

本课结束。

## 四、课堂最常见的 5 个问题

### 1. Tablet 编译时报“current module device type: phone”

原因：`module.json5` 只有 `phone`。

处理：改成：

```json5
"deviceTypes": ["phone", "tablet", "2in1"]
```

### 2. 顶部文字一直不变

检查 TODO 1 是否为：

```typescript
this.currentBreakpoint = breakpoint;
```

### 3. 宽屏仍然上下排列

检查 TODO 2 和 TODO 3，直接对照速记卡复制。

### 4. 代码被学生改乱了

直接使用：

```text
teacher/Index.completed.ets
```

整体替换后重新运行。

### 5. 老师也不知道怎么解释

只说：

> `GridRow` 是一排格子，`GridCol` 表示卡片占几格。窄窗口放不下两张卡片，就上下排；宽窗口放得下，就左右排。

说到这里就够了。
