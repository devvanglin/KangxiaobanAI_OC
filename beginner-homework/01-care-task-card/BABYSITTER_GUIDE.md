# 保姆级上课手册：老师半懂也能讲

这份手册不是知识百科，而是一份“照着准备、照着点、照着说”的课堂操作稿。老师不需要先掌握完整的 HarmonyOS 架构，只要课前把流程亲自走一遍，就可以带学生完成第一份作业。

建议先不要讲 HDS、网络、数据库、导航、权限或 AI。本课只解决一件事：**点击按钮后，状态变化，界面自动更新。**

---

## 1. 老师先记住这 7 句话

上课前，能说清下面 7 句话就够了：

1. **ArkTS 是写鸿蒙应用所用的语言。**
2. **ArkUI 是用 ArkTS 描述界面的框架。**
3. **组件就是一块界面，组件可以嵌套组件。**
4. **`build()` 描述这个组件现在应该显示什么。**
5. **`@Local` 是组件自己拥有、改变后会影响界面的数据。**
6. **`@Param` 是父组件传给子组件的只读数据。**
7. **`@Event` 是子组件通知父组件“用户做了某件事”的方法。**

本课的总口诀：

> 数据向下传，事件向上传；父组件改状态，ArkUI 刷界面。

如果学生继续追问“底层怎么做到的”，可以回答：

> ArkUI 会跟踪被界面使用的可观察状态。状态改变后，它会重新计算受影响的界面。第一课先掌握使用方法，底层更新机制后面再讲。

## 2. 老师课前 30 分钟准备清单

不要第一次上课时才第一次运行代码。提前按顺序做完：

- [ ] 打开 DevEco Studio；
- [ ] 新建一个独立的 Empty Ability 练习工程；
- [ ] 确认使用 ArkTS 和 Stage 模型；
- [ ] SDK/API 尽量选择 API 24；若界面只显示 SDK 名称，选择与 API 24 兼容的版本；
- [ ] 找到入口页面 `Index.ets`；
- [ ] 用 `starter/Index.ets` 整体替换入口页面；
- [ ] 成功看到静态任务卡；
- [ ] 亲自填写两个 TODO；
- [ ] 验证杯数可以从 0 变成 3；
- [ ] 验证任务可以在待完成和已完成之间来回切换；
- [ ] 把教师完成版留在旁边备用；
- [ ] 放大编辑器字号，确保最后一排能看清。

教师完成版位于：`teacher/Index.completed.ets`。

### 上课前需要准备的窗口

建议只保留三个窗口或标签：

1. DevEco Studio 的 `Index.ets`；
2. 运行预览或模拟器；
3. 本手册。

不要同时打开正式产品的大型页面，避免学生误以为第一课需要理解几千行代码。

## 3. 如果老师连 DevEco 工程都不熟

不同 DevEco Studio 版本的按钮文字可能略有差异，但流程基本一致。

### 3.1 创建练习工程

1. 启动 DevEco Studio；
2. 在欢迎页点击 `Create Project`；如果已经打开其他工程，使用 `File > New > Create Project`；
3. 选择应用模板中的 `Empty Ability`；
4. 点击 `Next`；
5. 工程名可填 `CareTaskHomework`；
6. 包名可保留自动生成值；
7. 开发语言选择 `ArkTS`；
8. 模型选择 `Stage`；
9. 设备选择 Phone 即可；
10. SDK/API 优先选择 24；
11. 选择一个容易找到的保存位置；
12. 点击 `Finish`，等待依赖同步和索引完成。

老师可以这样说：

> 我们今天另建一个练习工程，不直接改康小伴产品。这样写错了也不会影响正式代码。

### 3.2 找到入口页面

左侧工程树通常可以按下面路径寻找：

```text
entry
  └── src
      └── main
          └── ets
              └── pages
                  └── Index.ets
```

有些模板的模块名或目录显示方式略有不同。找不到时：

1. 按两次 `Shift` 打开全局搜索；
2. 输入 `Index.ets`；
3. 打开位于 `src/main/ets/pages` 下的文件。

### 3.3 放入起始代码

1. 打开本作业的 `starter/Index.ets`；
2. 全选并复制；
3. 回到练习工程的入口 `Index.ets`；
4. 全选原内容；
5. 整体粘贴替换；
6. 保存文件。

强调“整体替换”，因为模板可能使用 V1 的 `@State`。本课统一使用 V2，不要拼接两套代码。

### 3.4 第一次运行

优先使用老师已经验证过的方式：

- Previewer：打开预览面板并刷新；
- 模拟器：选择可用模拟器后运行；
- 真机：确认签名和设备连接后运行。

第一次成功时应看到：

- 顶部标题“康小伴 · 新手作业”；
- 一张“李奶奶”的任务卡；
- 饮水记录为 0 杯；
- 状态为待完成；
- 两个按钮可以点击，但因为 TODO 还没写，所以数据暂时不会改变。

老师需要主动说明：

> 按钮现在能被点击，但点击后没有结果，这是正常的。按钮已经把事件送到 TODO 位置，我们马上补上状态修改。

## 4. 代码地图：老师不用逐行全讲

先让学生只看四个区域：

```text
第 1 区：CareTaskInfo        规定一项任务有哪些数据
第 2 区：CareTaskCard        显示任务卡的子组件
第 3 区：Index 的 @Local     页面真正拥有的可变状态
第 4 区：两个 TODO           本节课需要学生完成的代码
```

### 4.1 `interface CareTaskInfo` 是什么

老师说：

> `interface` 可以先理解为数据填写规范。它规定一项照护任务必须有姓名、房间床位、任务标题和计划时间。

不需要在第一课讲结构化类型、DTO、序列化或接口继承。

### 4.2 `CareTaskCard` 是什么

老师说：

> 这是任务卡子组件。它负责把数据摆好、显示好，并在按钮被点击时发出通知。它不拥有杯数和完成状态。

### 4.3 `Index` 是什么

老师说：

> `Index` 是入口页面，也是这节课的父组件。杯数和任务状态都归它管理。

### 4.4 `build()` 是什么

老师说：

> `build()` 不是让我们手动一步步画屏幕，而是声明“现在应该显示哪些组件”。状态变化后，ArkUI 会根据新的状态更新显示。

## 5. 正式上课逐字稿（约 90～100 分钟）

下面的“老师说”可以直接照读，不必逐字背诵。

### 第 0 步：开场，5 分钟

老师操作：展示教师完成版，点击三次记录饮水，再点击完成任务。

老师说：

> 大家今天只做一个很小的鸿蒙页面：一张照护任务卡。初始是 0 杯、待完成。每点一次记录饮水，数字加一；点击完成任务，状态和按钮文字一起变化。这个小练习会带我们认识鸿蒙声明式 UI 最核心的数据流。

老师问：

> 刚才哪些东西发生了变化？

学生可能回答：杯数、状态、按钮文字。

老师接话：

> 对，这些会变化的内容背后都有“状态”。今天我们的目标就是让状态正确地变化。

### 第 1 步：认识页面结构，10 分钟

老师操作：打开学生起始代码，折叠具体样式或快速滚动展示全貌。

老师说：

> 这份代码虽然有一百多行，但真正需要大家填写的只有两个 TODO。其他代码是给我们搭好的界面。现在先找 `Index` 和 `CareTaskCard`。

在代码中指出：

```typescript
@ComponentV2
struct CareTaskCard
```

和：

```typescript
@Entry
@ComponentV2
struct Index
```

老师说：

> `Index` 是父组件和入口页面，`CareTaskCard` 是子组件。父组件使用子组件，就像一个页面里放进了一张卡片。

课堂动作：让学生用鼠标指出 `Column`、`Row`、`Text`、`Button`。

老师给出简单答案：

- `Column`：里面的东西从上往下排；
- `Row`：里面的东西从左往右排；
- `Text`：显示文字；
- `Button`：显示可点击按钮。

### 第 2 步：找到状态，10 分钟

老师操作：定位到：

```typescript
@Local waterCups: number = 0;
@Local isDone: boolean = false;
```

老师说：

> `waterCups` 是饮水杯数，类型是数字，初始值是 0。`isDone` 表示任务是否完成，类型是布尔值，只有真和假，初始是假。

> 前面的 `@Local` 表示这两个状态由 `Index` 自己拥有，而且它们变化时会影响界面。

老师操作：临时把 `waterCups` 初始值改为 `2`，刷新预览，再改回 `0`。

老师问：

> 我们有没有找到显示“饮水记录”的 Text，然后手动改它？

期望答案：没有。

老师总结：

> 我们只改状态。界面读取状态后，会显示最新结果。这就是声明式 UI 的基本感觉。

### 第 3 步：看懂值是怎样传给子组件的，10 分钟

老师操作：先指出父组件使用卡片的位置：

```typescript
CareTaskCard({
  task: this.task,
  waterCups: this.waterCups,
  isDone: this.isDone,
  // ...
})
```

然后指出子组件接收的位置：

```typescript
@Param @Require task: CareTaskInfo;
@Param @Require waterCups: number;
@Param @Require isDone: boolean;
```

老师说：

> 父组件把当前杯数和当前完成状态交给任务卡。子组件用 `@Param` 接收。`@Require` 表示父组件必须提供这些值。

> 重点是：`@Param` 是输入，子组件不能把它当成自己的状态直接修改。

老师可以画箭头：

```text
Index.waterCups ──@Param──> CareTaskCard.waterCups
Index.isDone    ──@Param──> CareTaskCard.isDone
```

### 第 4 步：看懂子组件如何报告点击，10 分钟

老师操作：指出：

```typescript
@Event onAddWater: () => void = () => {};
@Event onToggleDone: () => void = () => {};
```

再指出按钮调用：

```typescript
this.onAddWater();
```

和：

```typescript
this.onToggleDone();
```

老师说：

> 子组件不能直接改父组件的数据，所以它通过 `@Event` 发通知。`onAddWater` 可以读成“有人要求记录饮水”，`onToggleDone` 可以读成“有人要求切换完成状态”。

> 子组件负责报告点击，父组件决定数据怎么改。

老师画反方向箭头：

```text
CareTaskCard 点击按钮 ──@Event──> Index 处理状态
```

### 第 5 步：完成 TODO 1，10 分钟

老师让学生找到：

```typescript
onAddWater: () => {
  // TODO 1：让饮水杯数加 1。
},
```

先不显示答案，老师问三个问题：

1. 杯数变量叫什么？答案：`waterCups`；
2. 它属于哪个对象？这里写在组件方法里，所以用 `this.waterCups`；
3. 加一可以怎么写？`++` 或“原值加一再赋值”。

让学生填写：

```typescript
this.waterCups++;
```

完整结果：

```typescript
onAddWater: () => {
  this.waterCups++;
},
```

老师说：

> 这行代码修改的是父组件自己的 `@Local`。不是在子组件里修改 `@Param`，所以方向是正确的。

立即运行验证：

- 点击一次应为 1 杯；
- 再点两次应为 3 杯。

如果没变化，先看第 8 节的排错表。

### 第 6 步：完成 TODO 2，10 分钟

老师让学生找到：

```typescript
onToggleDone: () => {
  // TODO 2：在“待完成”和“已完成”之间切换。
},
```

老师先解释 `!`：

```text
!false 变成 true
!true  变成 false
```

让学生填写：

```typescript
this.isDone = !this.isDone;
```

完整结果：

```typescript
onToggleDone: () => {
  this.isDone = !this.isDone;
}
```

老师说：

> 等号右边先取当前值的相反值，再把结果放回 `isDone`。因此它可以来回切换，不是只能完成一次。

立即验证：

1. 点击完成任务；
2. 状态应变成已完成；
3. 按钮应变成恢复待办；
4. 再点一次，应恢复待完成。

### 第 7 步：完整验收，10 分钟

让学生从头按下面动作操作，不允许只说“刚才成功过”：

1. 重新加载页面；
2. 确认是 0 杯、待完成；
3. 点击三次记录饮水；
4. 确认是 3 杯；
5. 点击完成任务；
6. 确认显示已完成和恢复待办；
7. 再次点击；
8. 确认恢复待完成。

老师巡视时重点检查代码中有没有：

- `@State`；
- 在子组件里直接给 `@Param` 赋值；
- 写成 `this.waterCups + 1` 却没有赋值；
- 把 `isDone` 永久写成 `true`。

### 第 8 步：让学生说出数据流，5 分钟

老师让学生填空：

> 父组件用 ______ 保存杯数，通过 ______ 把杯数交给子组件。子组件点击按钮后，通过 ______ 通知父组件。父组件修改数据后，ArkUI ______。

答案：

```text
@Local、@Param、@Event、自动更新界面
```

学生能说出这句话，本课最重要的目标就达成了。

## 6. 老师逐段解释代码时可以怎么说

### `@Entry`

一句话解释：

> 这是可以作为页面入口加载的组件。

第一课不要讲完整路由表和 Ability 生命周期。

### `@ComponentV2`

一句话解释：

> 这是一个使用 ArkUI V2 状态规则的自定义组件。

如果学生问为什么不用 `@Component`：

> 那是另一代状态规则。本项目统一使用 V2，第一课不要混用。

### `@Local`

一句话解释：

> 组件自己拥有、能影响界面的可变数据。

### `@Param @Require`

一句话解释：

> 父组件必须传进来的只读参数。

### `@Event`

一句话解释：

> 子组件用来通知父组件的回调函数。

### `this`

一句话解释：

> 当前这个组件实例本身。

例如 `this.waterCups` 就是“当前 `Index` 组件的饮水杯数”。

### `${...}`

一句话解释：

> 把变量放进一段文字中。

例如：

```typescript
Text(`今日饮水记录：${this.waterCups} 杯`)
```

当 `waterCups` 是 3 时，界面显示“今日饮水记录：3 杯”。

### `condition ? A : B`

一句话解释：

> 条件成立显示 A，否则显示 B。

例如：

```typescript
this.isDone ? '已完成' : '待完成'
```

## 7. 学生提问时的简短答案

### “为什么不用一个组件全写完？”

> 小练习当然可以全写在一起，但拆出任务卡可以练习真实项目常用的父子组件通信，也方便以后重复使用任务卡。

### “为什么子组件不能直接改 `@Param`？”

> 因为数据归父组件管理。如果父子都能随意修改同一份数据，数据来源会变得混乱。V2 用只读参数和事件把责任分清楚。

### “为什么改变量后 Text 自动变了？”

> Text 的内容使用了这个可观察状态。状态改变后，ArkUI 会更新依赖该状态的界面。

### “数据保存到哪里了？”

> 只保存在当前组件的内存状态里。页面销毁或应用重开后会丢失。本课没有数据库和服务器。

### “这是康小伴正式功能吗？”

> 不是。这是独立教学练习，只借用了智慧养老的业务情境。

### “能不能用 `@State`？”

> 本课和正式项目统一采用 V2，所以用 `@Local`，不要混用 V1 的 `@State`。

### “为什么 `@Event` 后面有 `= () => {}`？”

> 它是默认空函数。即使父组件暂时没有传处理函数，子组件调用事件时也不会因为函数不存在而崩溃。

## 8. 最实用的排错表

先处理编辑器显示的**第一个错误**。后面的错误可能只是第一个错误引发的连锁反应。

### 情况 A：页面完全编译不过

依次检查：

1. 是否只复制了代码的一部分；
2. `{`、`}`、`(`、`)` 是否成对；
3. 每个属性声明后是否有分号；
4. 是否把中文标点输入进代码；
5. 是否把 V1 模板代码留在文件顶部或底部；
6. TODO 周围的逗号是否被删掉。

最省事的恢复方法：重新用 `starter/Index.ets` 整体替换，再只填两行答案。

### 情况 B：按钮能点，但杯数不变

检查是否写成：

```typescript
this.waterCups + 1;
```

这只是计算，没有把结果存回变量。改为：

```typescript
this.waterCups++;
```

或：

```typescript
this.waterCups = this.waterCups + 1;
```

### 情况 C：点完成后不能恢复

检查是否写成：

```typescript
this.isDone = true;
```

这只会永久设为完成。改为：

```typescript
this.isDone = !this.isDone;
```

### 情况 D：报错说不能修改参数

学生可能在 `CareTaskCard` 中写了：

```typescript
this.waterCups++;
```

这里的 `waterCups` 是 `@Param`。删除直接修改，保留：

```typescript
this.onAddWater();
```

真正的修改写在父组件传入的 `onAddWater` 中。

### 情况 E：提示 V1/V2 混用

搜索并删除或替换这些 V1 装饰器：

```text
@State @Prop @Link @Watch @Observed @Provide @Consume
```

本课文件应使用：

```text
@Entry @ComponentV2 @Local @Param @Require @Event
```

### 情况 F：预览一直是旧画面

1. 保存文件；
2. 查看是否存在红色编译错误；
3. 手动刷新 Previewer；
4. 仍无变化时停止并重新运行练习工程；
5. 不要为了这个问题清理或删除整个工作区。

### 情况 G：系统资源报找不到

如果新建工程的 SDK 环境与起始代码不完全一致，先确认工程使用的是 HarmonyOS ArkTS 工程，并确认 SDK/API。不要随意把正式项目签名配置复制到练习工程。

如果只为完成课堂逻辑且某个颜色资源导致预览阻塞，老师可以临时将对应颜色属性注释掉；课后再根据当前 SDK 的代码补全选择可用系统资源。不要改动两个 TODO 的数据流设计。

## 9. 老师如何判断学生是真的懂了

不要只检查截图。随机问下面三个问题：

### 问题 1

“杯数到底是谁的数据？”

合格答案：

> 是父组件 `Index` 的 `@Local` 状态。

### 问题 2

“任务卡为什么不直接把杯数加一？”

合格答案：

> 因为它拿到的是只读 `@Param`，应该通过 `@Event` 通知父组件修改。

### 问题 3

“为什么数字改了以后文字也变了？”

合格答案：

> 因为界面使用了 `@Local` 状态，状态改变后 ArkUI 会自动更新依赖它的界面。

## 13. 老师一分钟复盘稿

课程结束时可以直接说：

> 今天我们完成了一张可交互的照护任务卡。父组件 `Index` 用 `@Local` 保存杯数和完成状态，再通过 `@Param` 把值传给子组件。子组件不能直接修改参数，而是在按钮点击后通过 `@Event` 通知父组件。父组件修改状态，ArkUI 自动更新文字、状态和按钮。这个“数据向下、事件向上”的模式，会在后续列表、表单、设置页和业务组件里反复出现。
