# 康小伴开发进展

> 更新时间：2026-08-30
> 范围：Go 服务端、HarmonyOS 主端、驾驶舱和展示端；当前登录角色仅包含管理员、护工和医师。

## 当前状态

康小伴已从本地演示原型转为后端连接架构。登录用户、长者、床位、任务、体征、设备、告警、排班、
账单、用药、餐饮、消息、AI 会话和入住评估均有服务器数据模型，并通过租户和角色权限隔离。

仍未完成的部分会明确显示为空状态或“尚未开放”，不会再由客户端构造演示业务记录。管理员手机工作台和
管理端非运营总览模块仍属于待实现范围；医师手机端已提供只读健康/风险摘要，医师宽屏端已接入长者、护理协作、
风险复核、健康监测、评估记录和入住评估模块。

## 服务端

- Go、Gin、GORM；支持 SQLite 开发库和 MySQL 生产库。
- JWT 登录、RBAC、租户作用域和操作审计。
- 长者、房间/床位、护理任务、健康体征、护理计划/执行、事故和通知闭环。
- MQTT 设备接入、信号归一化、健康阈值、告警去重、离线判断和自动升级。
- 排班、交接、用药、药品库存、餐饮、账单、缴费和资金流水。
- 长者联系人和机构用户间消息；不再提供家属登录、绑定或家属端。
- AI 会话/消息持久化；远端模型失败不会伪装为本地成功答案。

以下可配置内容由数据库按租户管理，客户端不保存业务常量：

- 护理等级费用、床位费和餐费；
- 生命体征预警/危险阈值；
- 床位使用率、设备在线率和 IoT 告警时窗；
- AI 起始提示词；
- 入住评估题库、答案分值、字典、等级区间和护理方案。

默认值只在机构缺少对应记录时补齐，服务重启不会覆盖已经调整的机构配置。账单和订单中的金额保留为
历史快照，不随日后调价变化。

## 医师端入住评估

医师宽屏工作台提供四步入住流程：

1. 附录 A 基本信息、疾病用药、健康问题、联系人和近 30 天风险事件；
2. 附录 B 的 26 项能力评估，答案和分值由服务器题库下发；
3. 附录 C 的 90 分总分、五级能力结果、等级调整原因、床位和护理方案；
4. 医师复核、方案同意、费用告知、信息提供人签字后正式提交。

服务端负责重新计分，处理昏迷直接完全失能、痴呆/精神行为障碍加重一级和近 30 天风险事件达到标准
后加重一级。可选筛查包括 GAD-7、GDS-15、睡眠问题、Mini-Cog、MMSE 和 MoCA 北京版。

正式提交在一个事务中关联或创建长者档案、占用床位、保存评估、生成护理计划与任务，并写入联系人资料、
通知和审计记录。筛查结果属于照护评估参考，不替代临床诊断。

## 客户端数据边界

- `KangxiaobanAI`：登录、护工工作台、长者、任务、消息、管理总览、AI 和医师入住评估连接服务端。
- `KanxiaobanDS`：驾驶舱从 `/dashboard/cockpit` 读取机构实时快照和运营策略。
- `nurse-dashboard`、`showcase`：读取 API，不维护独立演示业务数据。

UI 文案、枚举显示名称、图标、布局尺寸和尚未提交的表单输入仍属于客户端界面状态，不属于数据库业务
数据。网络地址和签名信息属于部署/本机配置，不写入本文档。

## 本地运行

```powershell
Set-Location kangxiaoban-service
$env:KXB_DB_DRIVER = 'sqlite'
$env:KXB_DB_SQLITE_PATH = 'kangxiaoban.db'
$env:KXB_MQTT_ENABLE = 'false'
go run ./cmd/server
```

启动后，`http://127.0.0.1:8080` 仅表示当前机器上的本地服务地址。生产部署通过环境变量或私有配置注入
数据库、JWT、MQTT、AI 和客户端 API 地址；不要提交 `.env`、数据库文件、签名配置、证书或密钥。

## 验收口径

- 结构存在不等于可运行；后端以测试、静态检查、构建和真实 HTTP 登录/业务请求为准。
- HarmonyOS 每个交付端必须分别执行 `clean` 和 `assembleHap`，一个端通过不代表全部端通过。
- 远端发布后必须核对远端分支提交与本地 `HEAD` 一致。
- 真实设备交互、MySQL 实例迁移和外部 MQTT/AI 服务只有在对应环境实际验证后才能标记为通过。
