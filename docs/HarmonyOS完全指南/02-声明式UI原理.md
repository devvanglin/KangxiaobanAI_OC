# 第 02 章 · 声明式 UI 原理：build() 到底发生了什么

> 本章说明三个问题：
> 1. 「声明式」和「命令式」到底差在哪
> 2. `build()` 里能写什么、不能写什么，为什么
> 3. 数据变了，界面是**怎么**变的（渲染管线）
>
> 理解本章内容可避免「数据已修改但界面未更新」这类问题。

---

## 2.1 命令式与声明式的区别

### 命令式

你是厨师，别人告诉你每一步：

```
1. 拿一个碗
2. 倒入面粉
3. 加水
4. 搅拌
5. 如果太稠，再加水
6. 如果太稀，再加面粉
```

对应代码：

```java
// 安卓风格（伪代码）
TextView tv = findViewById(R.id.title);   // 拿到那个控件
tv.setText("你好");                        // 改它的文字
tv.setTextColor(Color.RED);                // 改它的颜色
if (count > 5) {
    tv.setVisibility(View.GONE);           // 手动隐藏
} else {
    tv.setVisibility(View.VISIBLE);        // 手动显示
}
```

**痛点**：你必须自己记住「现在界面是什么状态」，然后手动改到「想要的状态」。
状态一多，就会漏改、改错、改重复。

### 声明式（ArkUI / SwiftUI / React / Flutter）

你是点菜的人，你只说「我要一碗面」：

```
我要：一碗面，加牛肉，不要葱
```

至于怎么做出来、当前碗里有什么、要加什么减什么——**框架自己算**。

对应代码：

```typescript
// ArkUI 风格
build() {
  if (this.count <= 5) {                // 我只是「描述」：count<=5 的时候有这个文本
    Text('你好')
      .fontColor(Color.Red)
  }
}
```

**你不需要写「隐藏它」，你只需要描述「什么情况下它存在」。**
`count` 变了，框架自动重新执行这段描述，自动算出该加什么删什么。

### 核心公式

> **UI = f(State)**
>
> 界面是「状态」的函数。状态变了，界面自动跟着变。你只管改状态。

## 2.2 一个完整例子：从命令式到声明式的思维转换

**需求**：一个计数器，超过 5 显示「太多了」，并把数字变红。

### 命令式思维（在 ArkUI 中不适用）

```typescript
@ComponentV2
struct Bad {
  @Local count: number = 0;
  @Local textColor: ResourceColor = Color.Black;   // ← 想手动控制颜色
  @Local warningVisible: boolean = false;          // ← 想手动控制显示

  private add(): void {
    this.count++;
    if (this.count > 5) {              // ← 手动同步各种状态，容易漏
      this.textColor = Color.Red;
      this.warningVisible = true;
    } else {
      this.textColor = Color.Black;
      this.warningVisible = false;
    }
  }

  build() {
    Column() {
      Text(`${this.count}`).fontColor(this.textColor)
      if (this.warningVisible) { Text('太多了') }
      Button('加').onClick(() => this.add())
    }
  }
}
```

问题：`count`、`textColor`、`warningVisible` 三个状态必须手动保持一致。
哪天你加了个「减 1」按钮，忘了同步颜色，就出 bug 了。

### 声明式思维

```typescript
@ComponentV2
struct Good {
  @Local count: number = 0;         // 只有一个「真实状态」

  build() {
    Column() {
      Text(`${this.count}`)
        .fontColor(this.count > 5 ? Color.Red : Color.Black)   // ← 颜色是算出来的
      if (this.count > 5) {                                     // ← 显示与否是算出来的
        Text('太多了')
      }
      Button('加').onClick(() => { this.count++; })             // ← 只改真实状态
      Button('减').onClick(() => { this.count--; })             // ← 不用管别的
    }
  }
}
```

**核心原则**：

> **只保存「无法从其它状态推导出来的数据」（Single Source of Truth，唯一数据源）。**
> 能算出来的东西，就在 `build()` 里算，不要存成状态。

**本项目的真实体现**（`pages/LoginPage.ets`）：

```typescript
@Local account: string = '';
@Local password: string = '';
@Local isLoading: boolean = false;

// 按钮是否可点击 —— 不存状态，直接算
.enabled(!this.isLoading && this.account.length > 0 && this.password.length > 0)
.opacity((!this.isLoading && this.account.length > 0 && this.password.length > 0) ? 1 : 0.4)
```

## 2.3 `build()` 的约束规则

每个 `@ComponentV2` 组件必须有且只有一个 `build()` 方法。

### 规则 1：`build()` 里只能写 UI 描述，不能写业务逻辑

```typescript
// ❌ 错误
build() {
  const data = this.fetchDataFromServer();     // ❌ 不能做 I/O
  this.count++;                                 // ❌ 不能改状态（会死循环）
  console.log('rendering');                     // ⚠️ 能跑但会被调用很多次
  Text(`${data}`)
}

// ✅ 正确
build() {
  Text(`${this.data}`)     // 只描述 UI
}

aboutToAppear(): void {
  this.data = this.fetchData();   // 数据准备放生命周期里
}
```

**为什么**：`build()` 会被**反复执行**（每次状态变化都可能执行一次）。
在里面改状态 → 触发重新执行 → 又改状态 → 无限循环。

### 规则 2：根节点只能有一个

```typescript
// ❌ 错误：两个根节点
build() {
  Text('a')
  Text('b')
}

// ✅ 正确：用容器包起来
build() {
  Column() {
    Text('a')
    Text('b')
  }
}
```

**例外**：`@Entry` 组件的根节点如果是 `Column`/`Row` 等容器就行；某些情况下框架允许 `if/else` 分支作为根。
本项目 `MainPage` 的根是 `Stack`，`TabPageView` 的根也是 `Stack`。

### 规则 3：不能用 `for` 循环，要用 `ForEach` / `Repeat` / `LazyForEach`

```typescript
// ❌ 错误
build() {
  Column() {
    for (let i = 0; i < 10; i++) {     // ❌ build() 里不允许普通循环语句
      Text(`${i}`)
    }
  }
}

// ✅ 正确
build() {
  Column() {
    ForEach(this.items, (item: Item) => {
      Text(item.name)
    }, (item: Item) => item.id)        // 第三个参数是「唯一键」，很重要！
  }
}
```

### 规则 4：条件渲染用 `if / else if / else`，不能用 `switch`

```typescript
// ✅ 正确
build() {
  Column() {
    if (this.currentTabIndex === 0) {
      this.homePage();
    } else if (this.currentTabIndex === 1) {
      this.elderPage();
    } else if (this.currentTabIndex === 2) {
      this.messagePage();
    } else {
      this.minePage();
    }
  }
}
```

（这段就是本项目 `component/TabPageView.ets` 的 `build()` 真实代码。）

**三元表达式可以用在属性值里**：

```typescript
.fontColor(this.selected ? Color.Blue : Color.Black)    // ✅ 完全没问题
```

### 规则 5：`build()` 里可以调用「返回值的普通方法」

```typescript
build() {
  Column() {
    Text('标题')
  }
  .padding(this.pagePadding())        // ✅ 调用普通方法计算数值，可以
  .backgroundColor(this.pageBackgroundColor())   // ✅ 可以
}

private pagePadding(): number {
  return new BreakpointType<number>({ sm: 16, md: 24, lg: 28, xl: 32 })
    .getValue(this.globalInfoModel.widthBreakpoint);
}
```

**但要注意性能**：这个方法每次重渲染都会被调用。
所以里面**不能有重活**（排序大数组、复杂解析、I/O）。重活要用 `@Computed`（带缓存）。

## 2.4 组件的三种写法：内建组件 / 自定义组件 / @Builder

### ① 内建组件（系统提供的）

```typescript
Text('文字')
Button('按钮')
Column() { }
Image($r('app.media.icon'))
```

直接调用，不用 import（框架全局注入）。

### ② 自定义组件（`struct`）

**定义**：

```typescript
// component/AiTitleLabel.ets
@ComponentV2
export struct AiTitleLabel {
  @Param @Require text: string;
  @Param compact: boolean = false;

  build() {
    Text(this.text)
      .fontSize(this.compact ? 16 : 20)
  }
}
```

**使用**（要 import）：

```typescript
import { AiTitleLabel } from '../component/AiTitleLabel';

build() {
  Column() {
    AiTitleLabel({ text: '你好', compact: true })    // 像调函数一样，参数是对象
  }
}
```

**注意**：参数名必须和 `@Param` 声明的名字完全一致。

### ③ `@Builder`（UI 函数）

`@Builder` 是「组件内部的可复用 UI 片段」，比自定义组件更轻量（没有独立状态和生命周期）。

```typescript
@ComponentV2
struct Demo {
  @Local level: StatusLevel = 'warning';

  @Builder
  private statusTag(text: string, level: StatusLevel) {   // ← 可以带参数
    Text(text)
      .fontSize(12)
      .fontColor(this.statusColor(level))                  // ← 可以访问 this
      .backgroundColor(this.statusBg(level))
      .padding({ left: 8, right: 8, top: 2, bottom: 2 })
      .borderRadius(4)
  }

  build() {
    Column() {
      this.statusTag('风险', 'danger')      // ← 用 this. 调用
      this.statusTag('关注', 'warning')
    }
  }
}
```

**`@Builder` 的三种形式**：

| 形式 | 写法 | 特点 |
|---|---|---|
| 组件内 `@Builder` | `@Builder private foo() {}`，用 `this.foo()` 调 | 能访问 `this`，最常用 |
| 全局 `@Builder` | 文件顶层 `@Builder function foo() {}` | 不能访问 `this` |
| `@LocalBuilder` | `@LocalBuilder private foo() {}` | `this` 指向严格绑定到定义它的组件 |

**`@Builder` vs 自定义组件，怎么选**：

| | `@Builder` | 自定义 struct |
|---|---|---|
| 有自己的状态 | ❌ | ✅ |
| 有生命周期 | ❌ | ✅ |
| 能被独立复用到其它文件 | ❌（除非全局 Builder） | ✅ |
| 开销 | 小 | 大一点 |
| 适合 | 同一组件内重复的 UI 片段 | 独立的、有状态的 UI 单元 |

**本项目的实践**：`TabPageView.ets` 有 **60 多个 `@Builder`**，因为一个 Tab 页里有大量重复的行/卡片结构。
而 `HealthListCard` / `EventListCard` / `ResidentSummaryCard` 是独立 struct，因为它们被多个页面复用。

### ④ `@Builder` 传给别的组件：`@BuilderParam`

如果你想让父组件决定子组件的某一部分长什么样（类似 React 的 children / Vue 的 slot）：

```typescript
@ComponentV2
struct Card {
  @BuilderParam content: () => void = this.defaultContent;   // 声明一个「UI 插槽」

  @Builder
  defaultContent() { Text('默认内容') }

  build() {
    Column() {
      Text('卡片标题')
      this.content()     // ← 调用插槽
    }
  }
}

// 使用
@Builder
myContent() { Text('我的自定义内容') }

build() {
  Card({ content: this.myContent })
}
```

## 2.5 链式属性调用的顺序规则

```typescript
Text('你好')
  .fontSize(20)
  .fontColor(Color.Red)
  .width(100)
  .backgroundColor(Color.Yellow)
  .padding(10)
  .borderRadius(8)
```

### 大多数属性顺序无关

`fontSize` 和 `fontColor` 谁先谁后无所谓。

### 但这几组顺序**有关**：

**① 变换类属性（`translate` / `scale` / `rotate`）按顺序叠加**

```typescript
.scale({ x: 2 }).translate({ x: 10 })   // 先放大再位移（位移量也被放大）
.translate({ x: 10 }).scale({ x: 2 })   // 先位移再放大（结果不同）
```

**② `padding` / `border` / `backgroundColor` 的绘制层级**

```typescript
// 背景色会覆盖 padding 区域
.padding(10).backgroundColor(Color.Red)   // 背景包含 padding
```

**③ `.animation()` 只对它「前面」的属性生效**

这是最容易踩的坑：

```typescript
// ✅ 正确：animation 放最后，前面所有属性变化都有动画
Row()
  .width(this.w)
  .opacity(this.o)
  .animation({ duration: 300, curve: Curve.EaseOut })

// ❌ 错误：opacity 在 animation 后面，不会有动画
Row()
  .width(this.w)
  .animation({ duration: 300 })
  .opacity(this.o)         // ← 这个不会动画
```

**本项目的真实例子**（`component/wide/WideSlidingCapsule.ets`）：

```typescript
Row()
  .width(this.effectiveItemWidth())
  .height(38)
  .borderRadius(19)
  .backgroundColor($r('sys.color.comp_background_primary'))
  .shadow({ radius: 6, color: 'rgba(0,0,0,0.05)', offsetY: 1 })
  .translate({ x: this.selectionOffset() })      // ← 这个会动画
  .opacity(this.selectedPosition() >= 0 ? 1 : 0) // ← 这个也会
  .animation({ duration: 260, curve: Curve.Friction })   // ← 放最后
```

**④ 事件方法（`onClick` 等）建议放最后**，可读性更好。

## 2.6 渲染管线：状态变更后的处理流程

### 完整流程

```
① 你写了 this.count++
        ↓
② @Local 的 setter 被触发（装饰器在编译期给字段加了 getter/setter）
        ↓
③ 框架查「依赖表」：哪些 UI 节点在渲染时读过 count？
        ↓
④ 把这些节点标记为「脏」（dirty）
        ↓
⑤ 等到下一个 VSync 信号（屏幕刷新时机，60Hz 就是每 16.6ms 一次）
        ↓
⑥ 重新执行「脏节点」相关的 build 片段（不是整个 build()！）
        ↓
⑦ 对比新旧描述，算出最小改动（diff）
        ↓
⑧ 更新真正的渲染树 → 测量 → 布局 → 绘制 → 上屏
```

### 关键理解 1：不是整个 `build()` 重新执行

框架会精确到「用到了这个变量的那一小段 UI」。
所以 `build()` 里有 1000 行也不怕，只要状态变化影响的范围小。

### 关键理解 2：依赖是「渲染时自动收集」的

```typescript
build() {
  Column() {
    Text(`${this.a}`)     // ← 渲染这一行时，框架记下「这个 Text 依赖 a」
    Text(`${this.b}`)     // ← 记下「这个 Text 依赖 b」
  }
}
```

改 `a` 只会重渲染第一个 `Text`。

### 关键理解 3：同一帧内的多次修改会被合并

```typescript
this.a = 1;
this.a = 2;
this.a = 3;
// 只会触发一次重渲染，最终显示 3
```

所以不用担心「连续改状态会不会渲染很多次」。

### 关键理解 4：为什么改了数据界面不动

**7 大原因**（这是新手最常见的问题，务必记牢）：

| # | 原因 | 例子 | 修法 |
|---|---|---|---|
| 1 | 变量没加装饰器 | `count: number = 0` | 加 `@Local` |
| 2 | 改的是 `@Param`（只读） | 子组件里 `this.myParam = x` | 让父组件改，或用 `@Once` |
| 3 | 类字段没加 `@Trace` | `@ObservedV2 class M { x = 1 }` | 加 `@Trace x = 1` |
| 4 | 改的是嵌套对象的深层属性，而外层是普通 `@Local` | `this.obj.a.b = 1` | 外层用 `@ObservedV2 + @Trace`，或整体替换 `this.obj = {...}` |
| 5 | 数组里对象的属性变了 | `this.list[0].name = 'x'` | 数组元素类型加 `@ObservedV2 + @Trace`，或 `this.list = [...this.list]` |
| 6 | `ForEach` 的 key 没变 | key 用了 index，数据换了但 index 没变 | key 用数据的唯一 id |
| 7 | 修改发生在 `build()` 外的异步回调里，但作用域丢了 `this` | 用了 `function(){}` 而非箭头函数 | 用箭头函数 |

第 05 章会把每一条展开讲。

## 2.7 `ForEach` / `Repeat` / `LazyForEach` 对比

### `ForEach`：全量渲染

```typescript
ForEach(
  this.items,                              // ① 数据源（数组）
  (item: Item, index: number) => {         // ② 每一项怎么渲染
    Text(item.name)
  },
  (item: Item, index: number) => item.id   // ③ 唯一键（keyGenerator）★重要
)
```

**第三个参数（唯一键）为什么重要**：

框架靠它判断「这一项是不是还是原来那一项」。

```typescript
// ❌ 用 index 当 key：删除第一项后，所有项的 index 都变了，框架以为全都变了 → 全部重建
(item, index) => `${index}`

// ✅ 用数据的唯一 id：删除第一项，其余项 key 不变 → 框架知道只删了一个
(item) => item.id
```

**本项目的真实例子**（`pages/MainPage.ets`）：

```typescript
ForEach(this.wideNavGroups(), (group: WideNavGroup, groupIndex: number) => {
  this.pcNavGroup(group, groupIndex)
}, (group: WideNavGroup, groupIndex: number) => `${groupIndex}`)
```

（这里用 index 做 key 是可以的，因为导航分组是**固定不变**的静态列表。）

```typescript
// TabPageView.ets：动态数据用 id 做 key
ForEach(group.tasks, (task: CareTask, index: number) => {
  this.expandTaskRow(task, index === group.tasks.length - 1)
}, (task: CareTask) => task.id)      // ← 用 task.id
```

### `Repeat`：V2 时代的增强版 ForEach

```typescript
Repeat<HealthListCardRow>(this.cardData.rows)
  .each((repeatItem: RepeatItem<HealthListCardRow>) => {
    ListItem() {
      Text(repeatItem.item.name)        // ← 注意：数据在 .item 里
      Text(`${repeatItem.index}`)        // ← 下标在 .index 里
    }
  })
  .key((row: HealthListCardRow) => row.id)   // ← 唯一键
```

**`Repeat` 比 `ForEach` 好在哪**：

- 支持**节点复用**（`.virtualScroll()` 模式下滚动性能更好）
- 支持模板（`.template()`，不同类型的数据用不同 UI）
- 和 V2 状态管理配合更好

**本项目的真实例子**（`component/HealthListCard.ets`）：

```typescript
List({ space: 0 }) {
  Repeat(this.cardData.rows)
    .each((repeatItem: RepeatItem<HealthListCardRow>) => {
      ListItem() {
        HdsListItemCard({
          textItem: {
            primaryText: { text: repeatItem.item.name },
            secondaryText: {
              text: `${repeatItem.item.age}岁 · ${repeatItem.item.room} · ${repeatItem.item.bed}`
            }
          },
          suffixItem: new SuffixButton({ text: '查看', textColor: $r('sys.color.interactive_active') }),
          /* ... */
        })
      }
      .onClick(() => { this.onItemClick(repeatItem.item.id); })
    })
    .key((row: HealthListCardRow) => row.id)
}
```

**嵌套 `Repeat` 的例子**（`pages/HealthExpandPage.ets`，按楼层分组）：

```typescript
Repeat<ElderGroup>(this.elderGroups())
  .each((groupItem: RepeatItem<ElderGroup>) => {
    Column({ space: 0 }) {
      Text(`${groupItem.item.letter}F`)         // 楼层标题

      Repeat<HealthRowData>(groupItem.item.elders)   // ← 内层 Repeat
        .each((elderItem: RepeatItem<HealthRowData>) => {
          Row({ space: 12 }) {
            Text(elderItem.item.name)
          }
        })
        .key((item: HealthRowData) => item.id)
    }
  })
  .key((item: ElderGroup) => item.letter)
```

### `LazyForEach`：超长列表懒加载

数据上千条时，`ForEach` 会一次性创建所有节点，卡死。`LazyForEach` 只创建可见的。

```typescript
LazyForEach(
  this.dataSource,            // ← 必须实现 IDataSource 接口
  (item: CardAttr, index: number) => {
    FlowItem() { /* ... */ }
  },
  (item: string) => item      // 唯一键
)
```

`IDataSource` 需要你实现这些方法：

```typescript
class MyDataSource implements IDataSource {
  totalCount(): number { return this.data.length; }
  getData(index: number): Item { return this.data[index]; }
  registerDataChangeListener(listener: DataChangeListener): void { }
  unregisterDataChangeListener(listener: DataChangeListener): void { }
}
```

参考实现见 `transitions-collection/entry/src/main/ets/utils/commonutils/WaterFlowDataSource.ets`。

### 三者怎么选

```
数据量 < 100，且不常变      → ForEach（最简单）
数据量 100~1000，V2 项目    → Repeat（本项目首选）
数据量 > 1000，或需要分页加载 → LazyForEach
```

## 2.8 组件生命周期（V2）

### 自定义组件的生命周期

```typescript
@ComponentV2
struct MyComp {
  aboutToAppear(): void {
    // 组件即将出现在 UI 树上（build() 之前）
    // 干什么：初始化数据、启动定时器、订阅事件
  }

  aboutToDisappear(): void {
    // 组件即将从 UI 树移除
    // 干什么：清理定时器、取消订阅、释放资源
  }

  build() { /* ... */ }
}
```

**顺序**：`aboutToAppear()` → `build()` → （状态变化时反复执行 build 片段）→ `aboutToDisappear()`

**本项目的真实例子**（`component/TabPageView.ets`）：

```typescript
aboutToAppear(): void {
  this.timerId = setInterval(() => { this.currentTime = new Date(); }, 1000);
}

aboutToDisappear(): void {
  if (this.timerId !== -1) {
    clearInterval(this.timerId);
    this.timerId = -1;
  }
}
```

**更复杂的真实例子**（`pages/AiChatPage.ets`，做了 4 件事的成对处理）：

```typescript
aboutToAppear(): void {
  WindowUtil.setImmersiveMode(true);                                     // ① 开沉浸式
  this.previousKeyboardAvoidMode = this.getUIContext().getKeyboardAvoidMode(); // ② 记住原来的键盘避让模式
  this.restoreActiveSession();                                            // ③ 恢复会话
}

aboutToDisappear(): void {
  this.syncActiveSession(this.messages, false);                          // ③' 保存会话
  this.getUIContext().setKeyboardAvoidMode(this.previousKeyboardAvoidMode); // ②' 还原键盘避让模式
  this.cancelPendingWork();                                               // 清理定时器
  WindowUtil.setImmersiveMode(false);                                     // ①' 关沉浸式
}
```

**注意这个对称性**：进来时改了什么全局状态，出去时就要还原什么。这是非常好的实践。

### 页面（`@Entry`）额外的生命周期

```typescript
@Entry
@ComponentV2
struct MyPage {
  onPageShow(): void { }      // 页面显示（每次从后台回来也会调）
  onPageHide(): void { }      // 页面隐藏
  onBackPress(): boolean {    // 用户按了返回键
    return true;              // 返回 true = 我处理了，不要执行默认返回
    // 返回 false = 走默认逻辑（退出页面）
  }
}
```

**本项目的真实例子**（`pages/MainPage.ets`，用 `onBackPress` 拦截浮层关闭）：

```typescript
onBackPress(): boolean {
  if (this.isAiChatShow) {           // ① 如果 AI 聊天浮层开着
    this.closeAiChat();              //    关掉它
    return true;                     //    拦截，不退出页面
  }
  if (this.isWideLayout() && this.pathStack.size() === 0 && this.currentTabIndex !== 0) {
    this.switchTab(0);               // ② 宽屏下不在首页 → 回首页
    return true;
  }
  return false;                      // ③ 其它情况走默认（退出）
}
```

这是**浮层导航**的关键：因为浮层不是真正的页面，系统不知道要「返回」它，必须手动拦截。

### V2 新增的生命周期装饰器（API 20+，本项目未用）

SDK 里还有一组更细的生命周期方法装饰器：

```typescript
@ComponentInit    // 组件初始化
@ComponentAppear  // 出现
@ComponentBuilt   // 构建完成
@ComponentReuse   // 被复用（配合 @ReusableV2）
@ComponentRecycle // 被回收
@ComponentActive  // 激活
@ComponentInactive// 失活
@ComponentDisappear // 消失
```

这些是 API 较新的能力，本项目（API 24）用传统的 `aboutToAppear`/`aboutToDisappear` 即可。

## 2.9 `@Styles` 和 `@Extend`：样式复用

### `@Styles`：复用一组**通用**属性

```typescript
@ComponentV2
struct Demo {
  @Styles
  pcIconNormalStyle() {
    .backgroundColor($r('sys.color.comp_background_primary'))
  }

  @Styles
  pcIconPressedStyle() {
    .backgroundColor($r('sys.color.interactive_pressed'))
  }

  build() {
    Row()
      .stateStyles({                        // ← 按交互状态切换样式
        normal: this.pcIconNormalStyle,
        pressed: this.pcIconPressedStyle
      })
  }
}
```

**限制**：`@Styles` 里只能写「所有组件都有的通用属性」（宽高、背景、边框、内外边距等），
不能写 `fontSize`（那是 Text 专有的）。

**本项目大量使用**（`pages/MainPage.ets`、`component/TabPageView.ets`、`component/HealthListCard.ets`）。

### `stateStyles`：四种交互状态

```typescript
.stateStyles({
  normal:   this.normalStyle,     // 正常
  pressed:  this.pressedStyle,    // 按下
  focused:  this.focusedStyle,    // 获得焦点（键盘导航）
  disabled: this.disabledStyle,   // 禁用
  selected: this.selectedStyle,   // 选中
})
```

### `@Extend`：给**特定组件**扩展方法

```typescript
@Extend(Text)                        // ← 指明扩展哪个组件
function titleStyle() {
  .fontSize(20)                      // ← 可以用 Text 专有属性
  .fontWeight(FontWeight.Bold)
  .fontColor($r('sys.color.font_primary'))
}

// 使用
build() {
  Text('标题').titleStyle()          // ← 像内置属性一样调用
}
```

**注意**：`@Extend` 必须写在**文件顶层**（不能在 struct 里面）。

### `AttributeModifier`：动态属性修改器

当你需要**运行时**决定属性时（`@Styles` 是静态的），用 Modifier：

```typescript
// 本项目的真实用法（model/TabsBarModel.ets）
new SymbolGlyphModifier(item.normalSymbolResource)
  .renderingStrategy(SymbolRenderingStrategy.SINGLE)
  .fontColor([item.normalColor])
```

```typescript
// pages/MainPage.ets
prefixItem: new PrefixIcon({
  iconSize: IconSize.SYSTEM_ICON,
  iconValue: {
    symbol: new SymbolGlyphModifier(item.symbol)
      .fontColor([isActive ? $r('sys.color.icon_emphasize') : $r('sys.color.icon_secondary')])
  }
})
```

## 2.10 `getUIContext()`：获取 UI 上下文

在组件里，`this.getUIContext()` 返回一个 `UIContext`，它是很多能力的入口：

```typescript
const ctx = this.getUIContext();

ctx.animateTo({ duration: 300 }, () => { /* 改状态 */ });   // 显式动画
ctx.px2vp(100);                          // 单位换算
ctx.vp2px(100);
ctx.getWindowWidthBreakpoint();          // 当前宽度断点
ctx.getWindowHeightBreakpoint();         // 当前高度断点
ctx.getFocusController().clearFocus();   // 焦点控制
ctx.getKeyboardAvoidMode();              // 键盘避让模式
ctx.setKeyboardAvoidMode(KeyboardAvoidMode.RESIZE);
ctx.getPromptAction().showToast({ message: 'hi' });   // 弹 Toast
ctx.getComponentSnapshot().get('id', callback);       // 组件截图
ctx.getHostContext();                    // 拿到 Ability 的 Context
```

**重要**：老代码里有全局函数 `animateTo(...)`、`px2vp(...)`，这些是**已废弃**的写法。
新代码一律用 `this.getUIContext().xxx()`。

**本项目全部用新写法**：

```typescript
this.getUIContext().animateTo({ curve: curves.springMotion() }, () => {
  this.isSidebarCollapsed = !this.isSidebarCollapsed;
});
```

**非 UI 代码怎么拿 UIContext**：本项目把它存进了 `AppStorageV2`：

```typescript
// util/WindowUtil.ets（存）
const uiContext: UIContext = WindowUtil.windowClass.getUIContext();
AppStorageV2.connect(UIContext, StorageKey.UI_CONTEXT, () => uiContext);

// util/PreferenceManager.ets（取）
const uiContext: UIContext | undefined = AppStorageV2.connect(UIContext, StorageKey.UI_CONTEXT);
this.preferences = preferences.getPreferencesSync(uiContext.getHostContext() as Context, { name: storeName });
```

## 2.11 本章总结：声明式 UI 的 10 条准则

1. **UI = f(State)**。只改状态，不直接操作 UI。
2. 能算出来的东西**不要存成状态**（唯一数据源原则）。
3. `build()` 里**只写 UI 描述**，不做 I/O、不改状态、不做重活。
4. `build()` **只能有一个根节点**。
5. 循环用 `ForEach` / `Repeat` / `LazyForEach`，**必须给唯一 key**。
6. 条件用 `if/else if/else`，不能用 `switch`。
7. `.animation()` **放在被动画属性的后面**。
8. `aboutToAppear` 里申请的东西，`aboutToDisappear` 里**必须释放**。
9. 用 `this.getUIContext().xxx()`，不用废弃的全局函数。
10. 界面不刷新时，**先查那 7 个原因**（2.6 节的表）。
