# 第 10 章 · 资源与主题：颜色、文字、图标、深色模式

> 本章讲清楚：为什么不能写死颜色和文字、`$r()` 到底怎么工作、深色模式怎么自动生效、
> 系统 token 有哪些、本项目的两套配色体系是怎么回事。

## 10.1 硬编码的问题

### 反面例子

```typescript
Text('首页')                      // ❌ 写死中文 → 没法做多语言
  .fontSize(16)                    // ❌ 写死字号 → 不跟随用户的系统字号设置
  .fontColor('#000000')            // ❌ 写死颜色 → 深色模式下看不见
  .padding(16)                     // ⚠️ 写死间距 → 不跟随系统间距规范
```

### 正确写法

```typescript
Text($r('app.string.tab_home'))                 // ✅ 资源引用，可翻译
  .fontSize($r('sys.float.Body_L'))             // ✅ 系统字号 token
  .fontColor($r('sys.color.font_primary'))      // ✅ 系统颜色 token，自动适配深浅色
  .padding($r('sys.float.padding_level8'))      // ✅ 系统间距 token
```

**四个好处**：

1. **多语言**：换一个语言目录就能整体翻译
2. **深色模式**：系统 token 自动切换，你不用写任何 if
3. **无障碍**：用户调大系统字号，你的 App 跟着变
4. **一致性**：和系统 App 视觉统一

### 资源查找规则（限定词匹配）

系统按**当前环境**从最匹配的目录找起，找不到就退回 `base`：

```
当前环境：中文 + 深色模式
查颜色 'brand_blue'：
  ① 找 zh_CN/dark/element/color.json   → 没有
  ② 找 dark/element/color.json         → 找到了！用这个
  ③ （如果还没有）找 base/element/color.json

查字符串 'tab_home'：
  ① 找 zh_CN/element/string.json       → 找到了！用这个
  ② （如果没有）找 base/element/string.json
```

**核心规则**：**`base` 里必须有全套**，其它目录只写「需要覆盖的部分」。


## 10.3 `$r()` 语法

### 格式

```
$r('<来源>.<类型>.<名字>')
```

| 来源 | 含义 |
|---|---|
| `app` | 你自己的模块资源（`resources/` 下的） |
| `sys` | 系统提供的资源 |

| 类型 | 对应文件 |
|---|---|
| `string` | `element/string.json` |
| `color` | `element/color.json` |
| `float` | `element/float.json` |
| `media` | `media/` 目录下的图片 |
| `plural` | `element/plural.json` |
| `symbol` | 系统符号图标（只有 `sys.symbol.*`） |
| `profile` | `profile/` 目录下的配置 |

### 例子

```typescript
$r('app.string.tab_home')            // 你的字符串
$r('app.color.brand_blue')           // 你的颜色
$r('app.media.ic_logo')              // 你的图片
$r('sys.color.font_primary')         // 系统颜色
$r('sys.float.Title_M')              // 系统字号
$r('sys.symbol.house_fill')          // 系统图标
$rawfile('images/photo.png')         // rawfile 里的文件（注意是 $rawfile，不是 $r）
```

### 在配置文件（json5）里的写法

配置文件用 `$xxx:name` 而不是 `$r()`：

```json5
// AppScope/app.json5
{
  "app": {
    "bundleName": "com.gxoc.kxbai",
    "vendor": "example",
    "versionCode": 1000000,
    "versionName": "1.0.0",
    "icon": "$media:layered_image",       // ← $media:
    "label": "$string:app_name"           // ← $string:
  }
}
```

```json5
// module.json5
{
  "module": {
    "description": "$string:module_desc",
    "pages": "$profile:main_pages",       // ← $profile:
    "abilities": [{
      "icon": "$media:layered_image",
      "label": "$string:KanxiaobanAbility_label",
      "startWindowBackground": "$color:start_window_background"   // ← $color:
    }]
  }
}
```

### 类型说明

```typescript
type Resource = { id: number; type: number; params: any[]; /* ... */ };
type ResourceStr = string | Resource;          // 「字符串或资源」
type ResourceColor = Color | number | string | Resource;   // 「颜色的任意形式」
type Length = string | number | Resource;
```

**这就是为什么很多属性能同时接受字符串和 `$r()`**：

```typescript
Text('直接写')                       // string
Text($r('app.string.tab_home'))      // Resource
// 两种都行，因为参数类型是 ResourceStr
```

### 运行时读取资源的值

有时候你需要拿到字符串的**实际内容**（而不是传给组件）：

```typescript
// 方法 1（推荐，需要 UIContext）
const text: string = this.getUIContext().getHostContext()!
  .resourceManager.getStringSync($r('app.string.tab_home').id);

// 方法 2：只读示例里的封装
// transitions-collection/entry/src/main/ets/utils/commonutils/ResourceString.ets
getResourceString(this.getUIContext(), $r('app.string.search_title'), this)
```

**尽量避免运行时读取**——直接把 `Resource` 传给组件，让框架处理。

## 10.4 字符串资源与多语言

### `string.json` 格式

```json
{
  "string": [
    {
      "name": "tab_home",
      "value": "首页"
    },
    {
      "name": "greeting",
      "value": "你好，%s！你有 %d 条消息"    // ← 支持占位符
    }
  ]
}
```

**注意**：本项目的 json 文件里中文是 **Unicode 转义**形式（`首页` = 「首页」）。
这是工具生成的，等价于直接写中文。你手写时直接写中文即可。

### 带参数的字符串

```typescript
$r('app.string.greeting', '张三', 5)     // 「你好，张三！你有 5 条消息」
```

### 复数（`plural.json`）

```json
{
  "plural": [
    {
      "name": "message_count",
      "value": [
        { "quantity": "one", "value": "%d 条消息" },
        { "quantity": "other", "value": "%d 条消息" }
      ]
    }
  ]
}
```

```typescript
$r('app.plural.message_count', 5, 5)
```

### 多语言目录命名

```
zh_CN     简体中文（中国大陆）
zh_TW     繁体中文（台湾）
zh_HK     繁体中文（香港）
en_US     英文（美国）
en_GB     英文（英国）
ja_JP     日语
ko_KR     韩语
```

也可以只写语言不写地区：`zh`、`en`。

### 本项目的实际情况

`base/element/string.json` 里 180 条字符串，其中：

- 部分是英文（`"home_title": "Adaptive Floating Navigation"`）
- 部分是中文（`"tab_home": "首页"`）

`zh_CN/element/string.json` 和 `en_US/element/string.json` 提供了对应翻译。

**⚠️ 一个历史遗留问题**：

```json
{ "name": "tab_music",   "value": "长者" }     // key 叫 music，值是「长者」
{ "name": "tab_message", "value": "消息" }     // 在别处又被当成「任务」
```

**这两个 key 名是从音乐 App 模板继承的，和实际含义不符。**

改代码时**必须看 `value`，不要相信 `name`**。

### ⚠️ 不要编辑生成的资源文件

`resources/base/media/layered_image.json`、`AppScope/resources/base/media/layered_image.json`
这类是 DevEco 生成的分层图标配置，**不要手改**。

## 10.5 颜色资源与深色模式

### 深色模式怎么自动生效

**只需要两步**：

**第一步**：在 `EntryAbility.onCreate` 里设置跟随系统

```typescript
// ets/entryability/EntryAbility.ets
onCreate(want: Want, launchParam: AbilityConstant.LaunchParam): void {
  try {
    this.context.getApplicationContext()
      .setColorMode(ConfigurationConstant.ColorMode.COLOR_MODE_NOT_SET);
    //                                              ↑ 不指定 = 跟随系统
  } catch (err) {
    Logger.error(TAG, `Failed to set colorMode. Cause: ${err.message}`);
  }
}
```

**三个可选值**：

| 值 | 含义 |
|---|---|
| `COLOR_MODE_NOT_SET` | ★跟随系统（本项目用这个） |
| `COLOR_MODE_LIGHT` | 强制浅色 |
| `COLOR_MODE_DARK` | 强制深色 |

**第二步**：在 `dark/element/color.json` 里写深色版本

```
resources/
├── base/element/color.json    ← 浅色（默认）
└── dark/element/color.json    ← 深色（覆盖）
```

**就这样。系统切换深色模式时，`$r('app.color.xxx')` 自动取深色版本，你不用写一行代码。**

### 为什么有两套配色

| | 护工端（手机 + 宽屏） | 医师端 / 管理端（宽屏专用） |
|---|---|---|
| 用什么色 | 系统 token（`sys.color.*`）+ 品牌色 | 专用 `doctor_workspace_*` |
| 视觉风格 | 系统原生感、亲和 | 「专业控制台」感，高信息密度 |
| 为什么 | 护工在移动中使用，需要和系统一致的操作直觉 | 医师坐在工位上长时间盯屏，需要低对比疲劳 |

**这是一个刻意的产品决策**，不是代码混乱。改这两块 UI 时要用对应的色板。

### `StatusLevel` 三级状态色（贯穿全项目）

```typescript
// model/DetailTypes.ets
export type StatusLevel = 'normal' | 'warning' | 'danger';
```

**配套的三个辅助函数**（在多个组件里重复出现）：

```typescript
private statusColor(level: StatusLevel): ResourceColor {
  if (level === 'danger') return $r('app.color.status_danger');
  if (level === 'warning') return $r('app.color.status_warning');
  return $r('app.color.status_normal');
}

private statusBg(level: StatusLevel): ResourceColor {
  if (level === 'danger') return $r('app.color.status_danger_bg');
  if (level === 'warning') return $r('app.color.status_warning_bg');
  return $r('app.color.status_normal_bg');
}

private statusText(level: StatusLevel): string {
  if (level === 'danger') return '风险';
  if (level === 'warning') return '关注';
  return '正常';
}
```

> ⚠️ **这三个函数目前在 `TabPageView`、`HealthExpandPage`、`ResidentDetailPage` 等多处重复定义**，
> 而且文案略有差异（有的返回「风险/关注/正常」，有的返回「危险/关注/稳定」）。
> **本项目规范：跟着你所在文件的本地写法走，不要擅自抽公共函数**（那是一次独立的重构）。

```
resources/base/media/icon.svg       → $r('app.media.icon')
resources/rawfile/images/photo.png  → $rawfile('images/photo.png')
```

### `media` vs `rawfile` 的区别

| | `media/` | `rawfile/` |
|---|---|---|
| 引用方式 | `$r('app.media.name')` | `$rawfile('path/name.ext')` |
| 是否参与编译 | ✅ 会被编入资源表 | ❌ 原样打包 |
| 能否按限定词切换 | ✅ 能（dark/、phone/ 等） | ❌ 不能 |
| 名字规则 | 不带扩展名，全小写下划线 | 带完整路径和扩展名 |
| 适合 | 图标、插图 | 大文件、字体、JSON 数据、HTML |

### 分层图标（`layered_image.json`）

鸿蒙的应用图标是**分层的**（前景 + 背景），能做桌面动效：

```json
// resources/base/media/layered_image.json
{
  "layered-image": {
    "background": "$media:background",
    "foreground": "$media:foreground"
  }
}
```

在 `app.json5` 里引用：

```json5
"icon": "$media:layered_image"
```

**⚠️ 这个文件由 DevEco 生成，不要手改。**

## 10.8 自定义主题（`WithTheme` / `CustomTheme`）

如果需要局部换一整套配色（不只是几个颜色）：

```typescript
import { CustomColors, CustomTheme } from '@kit.ArkUI';

class MyColors implements CustomColors {
  fontPrimary = '#FF0000';
  brand = '#00FF00';
  // ...
}

class MyTheme implements CustomTheme {
  colors = new MyColors();
}

// 使用
WithTheme({ theme: new MyTheme(), colorMode: ThemeColorMode.DARK }) {
  Column() {
    Text('这块区域用自定义主题')
  }
}
```

**HDS 也支持**：

```typescript
HdsNavigation(this.pathStack) { }
  .withTheme({ /* WithThemeOptions */ })
```

**本项目没用**——医师控制台的深色感是通过专用色板（`doctor_workspace_*`）实现的，
而不是切换整个主题。这样更可控。

## 10.9 本项目主题实践总结

### 规则 1：优先级顺序

```
① sys.color.* / sys.float.*         ← 首选，自动适配一切
② app.color.* / app.string.*        ← 系统没有的语义，自己定义
③ 硬编码值                            ← 只在临时/特殊情况，且要写注释
```

### 规则 2：能用系统 token 就不要自己定义

```typescript
// ❌ 不要自己定义「主要文字色」
$r('app.color.my_text_primary')

// ✅ 用系统的
$r('sys.color.font_primary')
```

**只有系统没有的语义才自己定义**：品牌色、业务状态色（危险/关注/正常）、控制台专用色。

### 规则 3：透明色用系统 token

```typescript
$r('sys.color.ohos_id_color_background_transparent')     // ✅
Color.Transparent                                         // ✅ 也行
'rgba(0,0,0,0)'                                           // ⚠️ 能用但不如上面清晰
```

**本项目三种都出现了**，主要是历史原因。新代码统一用第一种。

### 规则 4：阴影和半透明叠加可以用 rgba

```typescript
.shadow({ radius: 6, color: 'rgba(0,0,0,0.05)', offsetY: 1 })    // ✅ 合理
```

阴影这种「叠加在任何背景上都成立」的效果，用 rgba 是对的。

### 规则 5：不要为了迎合旧文档改代码

仓库里的 `KANGXIAOBANAI_ARKTS_DEEP_PROJECT_REPORT.md` 说 API 23，
实际 `build-profile.json5` 是 API 24。**以配置文件为准。**

## 10.10 常见问题

### Q1：深色模式下文字看不见？

用了硬编码颜色（`'#000000'`）。改成 `$r('sys.color.font_primary')`。

### Q2：改了 `dark/element/color.json` 但没生效？

检查三点：
1. `EntryAbility.onCreate` 里有没有设 `COLOR_MODE_NOT_SET`
2. `dark/element/color.json` 里的 `name` 和 `base` 里是否完全一致
3. 有没有重新编译（资源改动有时需要 clean）

### Q3：`$r('app.string.xxx')` 报「找不到资源」？

1. 名字拼错
2. `base/element/string.json` 里没有（其它语言目录有也不行，`base` 必须有）
3. json 格式错误（少逗号、多逗号）→ 整个文件都不会被解析

### Q4：多语言切换后有些文字没变？

那些文字在 `base` 里，但对应语言目录里缺少条目 → 退回了 `base` 的值。
补上翻译即可。

### Q5：图片不显示？

1. 文件名有大写字母或特殊字符（**必须全小写 + 下划线**）
2. 引用时带了扩展名（`$r('app.media.logo.png')` ❌，应该是 `$r('app.media.logo')`）
3. 图片放在了 `rawfile/` 但用 `$r()` 引用（应该用 `$rawfile()`）

### Q6：`sys.symbol.xxx` 不显示？

图标名不存在。用 IDE 补全确认名字。

### Q7：`$r()` 能在 `class` 里用吗？

能。但要注意 `$r()` 返回的是 `Resource` 对象，不是字符串。

```typescript
// model/TabsBarModel.ets 的真实例子
const PAGE_BAR_MAP: Map<PageKeyEnum, BarItem[]> = new Map([
  [PageKeyEnum.ADAPTIVE_TAB, [
    {
      label: '',
      normalColor: $r('sys.color.icon_primary'),          // ✅ 在普通对象里用
      normalSymbolResource: $r('sys.symbol.house_fill'),
      selectedColor: $r('app.color.brand_blue'),
      selectedSymbolResource: $r('sys.symbol.house_fill'),
    } as BarItem,
  ]],
]);
```

### Q8：怎么判断当前是深色还是浅色？

```typescript
import { ConfigurationConstant } from '@kit.AbilityKit';

const colorMode = this.getUIContext().getHostContext()!
  .config.colorMode;
const isDark = colorMode === ConfigurationConstant.ColorMode.COLOR_MODE_DARK;
```

**但通常你不需要判断**——用 token 让系统自动处理。
只有在需要动态生成颜色（比如根据图片主色调）时才需要。
