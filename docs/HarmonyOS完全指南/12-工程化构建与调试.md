## 12.1 hvigor 构建系统

### hvigor 是什么

鸿蒙的构建工具，相当于安卓的 Gradle、前端的 Webpack。

- 用 **TypeScript** 写构建脚本（`hvigorfile.ts`）
- 用 **json5** 写配置（`build-profile.json5`）
- 命令行工具叫 `hvigorw`（w = wrapper，会自动下载对应版本）

### 四个关键文件

```
KangxiaobanAI/
├── hvigorfile.ts                    ← 工程级构建脚本
├── build-profile.json5              ← 工程级构建配置（SDK/签名/产品/模块）
├── oh-package.json5                 ← 工程级依赖
├── hvigor/hvigor-config.json5       ← hvigor 自身配置（版本/性能）
└── products/entry/
    ├── hvigorfile.ts                ← 模块级构建脚本
    ├── build-profile.json5          ← 模块级构建配置
    └── oh-package.json5             ← 模块级依赖
```

### `hvigorfile.ts`（本项目全文）

**工程级**：

```typescript
import { appTasks } from '@ohos/hvigor-ohos-plugin';

export default {
  system: appTasks,   /* 内置插件，不能改 */
  plugins: []         /* 自定义插件写这里 */
}
```

**模块级**：

```typescript
import { hapTasks } from '@ohos/hvigor-ohos-plugin';

export default {
  system: hapTasks,   /* HAP 模块用 hapTasks */
  plugins: []
}
```

**三种任务集**：

| 导入 | 用在哪 |
|---|---|
| `appTasks` | 工程根 `hvigorfile.ts` |
| `hapTasks` | `type: "entry"` 或 `"feature"` 的模块 |
| `harTasks` | `type: "har"` 的模块 |
| `hspTasks` | `type: "shared"` 的模块 |

### `hvigor-config.json5`（本项目全文，注释是官方模板）

```json5
{
  "modelVersion": "6.1.0",              // ★hvigor 版本（和 SDK 对应）
  "dependencies": { },
  "execution": {
    // "analyze": "normal",             // 构建分析模式: normal | advanced | ultrafine | false
    // "daemon": true,                  // 守护进程编译（加快后续构建）
    // "incremental": true,             // 增量编译
    // "parallel": true,                // 并行编译
    // "typeCheck": false,              // ★类型检查（默认关闭！）
    // "optimizationStrategy": "memory" // memory | performance
  },
  "logging": {
    // "level": "info"                  // debug | info | warn | error
  },
  "debugging": {
    // "stacktrace": false"
  },
  "nodeOptions": {
    // "maxOldSpaceSize": 8192          // Node 堆大小（大工程可能需要调大）
    // "exposeGC": true
  }
}
```

**⚠️ 注意 `typeCheck` 默认是 `false`**。
这意味着**有些类型错误在编译时不会被发现**，运行时才炸。
如果你想更严格，可以打开它（会变慢）：

```json5
"execution": { "typeCheck": true }
```

## 12.2 构建命令（本项目实测）

### 前提：先 `cd` 到工程目录

```bash
cd C:/Users/Shenyi/Documents/Samson/Coding/KangxiaobanAI_OC/KangxiaobanAI
```

**仓库根目录没有 CI 包装脚本**，必须进到 `KangxiaobanAI/` 这一层。

### 常用命令

```bash
# Debug 构建（product=default，模块 kanxiaoban）
hvigorw assembleHap --mode module -p product=default -p buildMode=debug

# Release 构建
hvigorw assembleHap --mode module -p product=default -p buildMode=release

# 清理
hvigorw clean

# 跑测试
hvigorw test

# 只编译不打包
hvigorw build

# 打 App 包（上架用，聚合多个 hap）
hvigorw assembleApp

# 看所有可用任务
hvigorw tasks

# 详细日志（排查构建问题）
hvigorw assembleHap --mode module -p product=default --debug
hvigorw assembleHap --mode module -p product=default -i     # info 级别
```

### 参数说明

| 参数 | 含义 |
|---|---|
| `--mode module` | 按模块构建（vs `--mode project` 整工程） |
| `-p product=default` | 选哪个 product（在 `build-profile.json5` 的 `products` 里定义） |
| `-p buildMode=debug` | debug / release |
| `-p module=kanxiaoban` | 只构建某个模块 |
| `--no-daemon` | 不用守护进程（CI 环境用） |
| `--stacktrace` | 出错时打印完整堆栈 |

### 产物位置

```
KangxiaobanAI/products/entry/build/default/outputs/default/kanxiaoban-default-signed.hap
                              ↑product      ↑product      ↑模块名-product-signed.hap
```

### ⚠️ 关于构建状态的诚实表述

**一次 `product=default` 构建成功，只能证明 default 这个产品配置在当前 SDK 下能编译。**

它**不能**证明：
- 其它 product 能构建
- 其它设备形态（平板/PC）的布局是对的
- 真机上跑起来没问题

**本项目规范要求用四档表述**：

| 档位 | 含义 |
|---|---|
| **已实现** | 代码写完了，没编译验证 |
| **已构建验证** | `hvigorw assembleHap` 通过了 |
| **已真机验证** | 装到真机上，功能实际跑通了 |
| **仅规划** | 还没写 |

**不要把「已实现」说成「已验证」。**

## 12.4 模块类型与多模块工程

### 四种模块类型

| `type` | 产物 | 特点 | 什么时候用 |
|---|---|---|---|
| `entry` | HAP | 主模块，一个应用一个 | 必有 |
| `feature` | HAP | 特性模块，可按需下载 | 大型应用拆包 |
| `har` | HAR | 静态库，编译期打进使用方 | 抽公共代码（会复制多份） |
| `shared` | HSP | 动态共享包，运行期共享一份 | 抽公共代码（只有一份，省体积） |

### HAR vs HSP 怎么选

```
公共代码只被 1 个模块用            → HAR
公共代码被 3+ 个模块用，且体积大    → HSP（省体积）
需要单例（全局唯一实例）           → HSP（HAR 会每个使用方一份，单例失效）
需要热更新                        → HSP
构建速度优先                      → HAR
```

**⚠️ HAR 的单例陷阱**：

```typescript
// mylib（HAR）里的单例
export class MyManager {
  private static instance: MyManager;
  static getInstance(): MyManager { /* ... */ }
}
```

如果 `entry` 和 `feature` 都依赖这个 HAR，**会有两个独立的实例**（因为代码被复制了两份）。
需要真单例就用 HSP。

### 多模块工程示例（`MusicHome`）

```

│   ├── pc/          ← entry（PC）
```

### 配置文件（`code-linter.json5`，本项目全文）

```json5
{
  "files": ["**/*.ets"],                    // 检查所有 .ets

    "plugin:@typescript-eslint/recommended"  // ★TS 规范集
  ],
  "rules": {
    "@security/no-unsafe-aes": "error",           // ★以下全部 error，触发即构建失败
    "@security/no-unsafe-hash": "error",
    "@security/no-unsafe-mac": "warn",
    "@security/no-unsafe-dh": "error",
    "@security/no-unsafe-dsa": "error",
    "@security/no-unsafe-ecdsa": "error",
    "@security/no-unsafe-rsa-encrypt": "error",
    "@security/no-unsafe-rsa-sign": "error",
    "@security/no-unsafe-rsa-key": "error",
    "@security/no-unsafe-dsa-key": "error",
    "@security/no-unsafe-dh-key": "error",
    "@security/no-unsafe-3des": "error"
  }
}
```

### 🔒 安全规则解读（会让构建失败）

| 规则 | 禁止什么 | 应该用什么 |
|---|---|---|
| `no-unsafe-aes` | AES 的 ECB 模式、弱密钥 | AES-256-GCM |
| `no-unsafe-hash` | MD5、SHA1 | SHA-256 及以上 |
| `no-unsafe-3des` | 3DES | AES |
| `no-unsafe-rsa-key` | RSA 密钥 < 2048 位 | ≥ 2048 位 |
| `no-unsafe-dsa` / `no-unsafe-dsa-key` | DSA / 短 DSA 密钥 | ECDSA P-256+ |
| `no-unsafe-dh` / `no-unsafe-dh-key` | DH / 短 DH 密钥 | ECDH |
| `no-unsafe-ecdsa` | 不安全的 ECDSA 曲线 | P-256 / P-384 |
| `no-unsafe-rsa-encrypt` / `no-unsafe-rsa-sign` | RSA PKCS#1 v1.5 | OAEP / PSS |
| `no-unsafe-mac` (warn) | 不安全的 MAC | HMAC-SHA256 |

**结论：本项目里绝对不要引入任何弱加密。** 这些是 `error` 级别，一触发就编译不过。

### 性能规则（`@performance/recommended`）

常见检查项：

- 不要在 `build()` 里创建对象 / 调用高开销函数
- `ForEach` 要提供 key
- 长列表用 `LazyForEach`
- 不要用 `Flex` 当简单的 `Row`/`Column` 用
- 避免深层嵌套

**如果你要加真实测试，建议从这些「纯逻辑」的地方开始**（不需要 UI）：

```typescript
// 可测试的纯函数示例
BreakpointType<number>({ sm: 16, md: 24, lg: 28, xl: 32 }).getValue(WidthBreakpoint.WIDTH_MD)  // 应该 = 24
```

**实际测试示例**：

```typescript
import { describe, it, expect } from '@ohos/hypium';
import { BreakpointType, BreakpointUtil } from '../../main/ets/util/BreakpointSystem';

export default function breakpointTest() {
  describe('BreakpointSystemTest', () => {
    it('BreakpointType_returns_correct_value', 0, () => {
      const bp = new BreakpointType<number>({ sm: 16, md: 24, lg: 28, xl: 32 });
      expect(bp.getValue(WidthBreakpoint.WIDTH_SM)).assertEqual(16);
      expect(bp.getValue(WidthBreakpoint.WIDTH_MD)).assertEqual(24);
      expect(bp.getValue(WidthBreakpoint.WIDTH_LG)).assertEqual(28);
      expect(bp.getValue(WidthBreakpoint.WIDTH_XL)).assertEqual(32);
    });

    it('BreakpointType_xs_falls_back_to_sm', 0, () => {
      const bp = new BreakpointType<number>({ sm: 16, md: 24, lg: 28 });
      expect(bp.getValue(WidthBreakpoint.WIDTH_XS)).assertEqual(16);   // xs 没传 → 用 sm
      expect(bp.getValue(WidthBreakpoint.WIDTH_XL)).assertEqual(28);   // xl 没传 → 用 lg
    });

    it('BreakpointUtil_isWide', 0, () => {
      expect(BreakpointUtil.isWide(WidthBreakpoint.WIDTH_XS)).assertFalse();
      expect(BreakpointUtil.isWide(WidthBreakpoint.WIDTH_SM)).assertFalse();
      expect(BreakpointUtil.isWide(WidthBreakpoint.WIDTH_MD)).assertTrue();
      expect(BreakpointUtil.isWide(WidthBreakpoint.WIDTH_LG)).assertTrue();
      expect(BreakpointUtil.isWide(WidthBreakpoint.WIDTH_XL)).assertTrue();
    });
  });
}
```

| **Frame** | 掉帧、卡顿（红色柱子 = 超过 16.6ms） |
| **Time** | CPU 耗时、函数调用栈 |
| **Allocation** | 内存分配、对象数量 |
| **Snapshot** | 内存快照、内存泄漏 |
| **Realtime Monitor** | 实时 CPU / 内存 / GPU |

**排查掉帧的思路**：

```
Frame 面板发现红色帧
  ↓
切到 Time 面板，看那一帧在干什么
  ↓
├─ build() 耗时长      → 检查 build 里有没有重计算
├─ 布局耗时长          → 嵌套太深，或者用了 Flex
├─ 绘制耗时长          → 模糊/阴影/裁剪太多
└─ GC 频繁            → build() 里创建了大量临时对象
```

## 12.10 构建报错速查

| 报错 | 原因 | 解决 |
|---|---|---|
| `Cannot find module '@kit.XXX'` | Kit 名写错，或 SDK 版本不支持 | 检查拼写，检查 `@since` |
| `Property 'xxx' does not exist` | 类型不匹配 / API 版本太低 | 检查 SDK 的 `.d.ts` |
| `arkts-no-xxx` | 违反 ArkTS 限制 | 看第 01 章 B 部分 |
| `SDK version mismatch` | 本机 SDK 和项目配置不一致 | `File → Project Structure` 检查 |
| `Signing config not found` | 签名没配 | Project Structure → Signing Configs |
| `hvigor daemon 启动失败` | 缓存损坏 | `hvigorw clean`，删 `.hvigor/`，重启 IDE |
| `OutOfMemory` / heap 溢出 | Node 堆不够 | `hvigor-config.json5` 里调大 `maxOldSpaceSize` |
| `Resource not found: app.string.xxx` | 资源不存在 | 检查 `base/element/string.json` |
| `Duplicate resource name` | 资源重名 | 检查各个限定词目录 |
| `@security/no-unsafe-xxx` | 用了弱加密 | 换安全算法（第 12.5 节表格） |
| `Module 'xxx' not found` | 依赖没装 | `ohpm install` |
| `Page not found in main_pages.json` | 路由页面没注册 | 加进 `main_pages.json` |
| 构建成功但装不上 | 签名/包名冲突 | 卸载旧版本重装 |

### 构建环境重置流程

```bash
# 1. 清理构建产物
hvigorw clean

# 2. 删缓存（手动删这些目录）
rm -rf .hvigor build */build oh_modules
rm -f *.tsbuildinfo

# 3. 重装依赖
ohpm install

# 4. IDE: File → Invalidate Caches and Restart

# 5. 重新构建
hvigorw assembleHap --mode module -p product=default -p buildMode=debug
```
