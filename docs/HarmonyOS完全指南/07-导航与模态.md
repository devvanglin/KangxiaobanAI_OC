# 第 07 章 · 导航与模态：页面之间怎么跳

> 鸿蒙提供三套相互独立的页面切换机制，用途各不相同。
> 本章讲清楚它们分别是什么、什么时候用哪个、本项目怎么选的。

---

## 7.1 三套机制总览

| # | 机制 | 是不是真的「页面」 | 有独立生命周期吗 | 系统返回键管吗 | 本项目用在哪 |
|---|---|---|---|---|---|
| **①** | `router`（页面路由） | ✅ 是（写在 `main_pages.json`） | ✅ 有 | ✅ 管 | **只有 Login ↔ Main** |
| **②** | `Navigation` + `NavPathStack` | ⚠️ 页内路由（同一个 router 页面里） | ✅ 有（NavDestination） | ✅ 管 | 关于页、通用设置页 |
| **③** | 模态 / 浮层（`bindSheet` / `bindContentCover` / `Stack`） | ❌ 不是，就是组件 | ❌ 没有 | ❌ **要手动拦截** | AI 聊天、长者详情、健康展开、任务展开、各种底部弹窗 |

**选择依据**：

```
要不要换掉整个 App 的外壳（比如登录页 ↔ 主界面）？  → 用 ① router
要不要在当前外壳内推入一个新页面（有返回栏）？      → 用 ② NavPathStack
只是弹个东西盖在上面，关掉就回来？                 → 用 ③ 模态/浮层
```

## 7.2 机制一：`router` 页面路由

### 什么是「路由页面」

只有同时满足两个条件，才是一个路由页面：

1. 组件加了 `@Entry`
2. 路径写进了 `resources/base/profile/main_pages.json`

**本项目的 `main_pages.json`（全文）**：

```json
{
  "src": [
    "pages/LoginPage",
    "pages/MainPage"
  ]
}
```

**只有 2 个页面。**

`pages/` 目录下还有 4 个文件（`AiChatPage`、`HealthExpandPage`、`ResidentDetailPage`、`MineDetailPage`），
它们**不在这个清单里**，所以**不是路由页面**——它们只是恰好放在 `pages/` 目录的普通组件。

> ⚠️ **这是本项目最容易误解的地方。** 看到 `pages/AiChatPage.ets` 不要以为它能 `router.pushUrl` 过去。

### API

```typescript
import { router } from '@kit.ArkUI';

// 跳转（保留当前页，可以返回）
router.pushUrl({ url: 'pages/DetailPage', params: { id: 1 } });

// 替换（销毁当前页，不能返回）
router.replaceUrl({ url: 'pages/MainPage' });

// 返回
router.back();
router.back({ url: 'pages/HomePage' });      // 返回到指定页

// 清空栈
router.clear();

// 拿参数
const params = router.getParams() as Record<string, Object>;

// 栈长度
router.getLength();

// 页面状态
router.getState();
```

### 本项目的两处使用

**登录成功**（`pages/LoginPage.ets`）：

```typescript
private async handleLogin(): Promise<void> {
  if (!this.account || !this.password) return;
  this.isLoading = true;
  setTimeout(async () => {
    this.isLoading = false;
    this.globalInfoModel.role = this.selectedRole;
    try {
      await router.replaceUrl({ url: 'pages/MainPage' });     // ← replaceUrl，不能返回登录页
    } catch (err) {
      Logger.error(TAG, `login route failed: ${JSON.stringify(err)}`);
    }
  }, 800);
}
```

**退出登录**（`pages/MainPage.ets`）：

```typescript
private async handleLogout(): Promise<void> {
  try {
    await router.replaceUrl({ url: 'pages/LoginPage' });      // ← 同样 replaceUrl
  } catch (error) {
    Logger.error(TAG, `logout failed: ${JSON.stringify(error)}`);
  }
}
```

**为什么用 `replaceUrl` 而不是 `pushUrl`**：登录成功后不应该能「返回」到登录页；
退出登录后也不应该能「返回」到主界面。`replaceUrl` 会销毁当前页。

### ⚠️ `router` 已被标记为不推荐

`router` 在新版本会输出**弃用警告**（deprecation warning）。官方推荐改用 `Navigation`。

**本项目的策略**（写在项目规范里）：

> `router.replaceUrl` **仅**用于「认证外壳边界」（登录成功 / 退出登录）。
> **不要**把它扩展到 App 内部的任何流程。

**为什么保留**：登录页和主界面的外壳结构完全不同（一个没有导航栏，一个有完整的导航体系），
用 `Navigation` 做这个切换反而别扭。这是一个务实的妥协。

**给你的建议**：**新代码不要用 `router`。** 想加新页面，走机制 ②。

## 7.3 机制二：`Navigation` + `NavPathStack`（页内路由）

### 结构模型

```
一个 router 页面（比如 MainPage）
  └── Navigation 容器              ← 相当于一个「浏览器」
       ├── NavBar（首页内容）        ← 相当于浏览器的首页
       └── NavPathStack（栈）        ← 相当于浏览历史
            ├── NavDestination A    ← 推入的第 1 个页面
            └── NavDestination B    ← 推入的第 2 个页面
```

用户在 `Navigation` 内部跳来跳去，**URL 层面还是同一个 router 页面**。

### 三个组成部分

**① `NavPathStack`：导航栈对象**

```typescript
private pathStack: NavPathStack = new NavPathStack();
```

**② `Navigation` 容器：绑定栈 + 指定目的地构造器**

```typescript
Navigation(this.pathStack) {
  // 这里是「首页」内容（NavBar）
}
.navDestination(this.destinationBuilder)      // ← 告诉它「名字 → 组件」的映射
.mode(NavigationMode.Stack)
```

**③ `destinationBuilder`：把路由名映射成组件**

```typescript
@Builder
private destinationBuilder(name: string, param?: ESObject) {
  if (name === 'AboutPage') {
    MineDetailPage({ pageType: 'about' })
  } else if (name === 'GeneralSettingsPage') {
    MineDetailPage({ pageType: 'general' })
  }
}
```

### 本项目的完整实现

**MainPage 拥有栈，并通过 `@Provider` 共享给整棵子树**：

```typescript
// pages/MainPage.ets
@Entry
@ComponentV2
struct MainPage {
  @Provider('mainPageStack') pathStack: NavPathStack = new NavPathStack();

  @Builder
  private destinationBuilder(name: string, param?: ESObject) {
    if (name === 'AboutPage') {
      MineDetailPage({ pageType: 'about' })
    } else if (name === 'GeneralSettingsPage') {
      MineDetailPage({ pageType: 'general' })
    }
  }

  build() {
    Stack() {
      if (this.isRoleAdapted()) {
        HdsNavigation(this.pathStack) {                  // ← HDS 版的 Navigation
          if (this.isWideLayout()) { this.wideShell() }
          else { this.phoneTabs() }
        }
        .mode(NavigationMode.Stack)
        .navDestination(this.destinationBuilder)          // ← 绑定构造器
        .titleBar({ /* ... */ })
        .bindToScrollable(PAGE_SCROLLER_MAP.get(PageKeyEnum.ADAPTIVE_TAB) ?? [])
        .hideBackButton(true)
        .hideTitleBar(this.isWideLayout(), true)          // 宽屏隐藏标题栏
        .titleMode(HdsNavigationTitleMode.MINI)
        .ignoreLayoutSafeArea([LayoutSafeAreaType.SYSTEM], [LayoutSafeAreaEdge.TOP, LayoutSafeAreaEdge.BOTTOM])
        .width('100%').height('100%')
      } else {
        this.roleWipPanel()
      }

      if (this.isAiChatShow) { this.aiChatCover() }
    }
    .width('100%').height('100%')
    .expandSafeArea([SafeAreaType.SYSTEM], [SafeAreaEdge.TOP, SafeAreaEdge.BOTTOM])
  }
}
```

**子组件通过 `@Consumer` 拿到栈**：

```typescript
// component/TabPageView.ets
@Consumer('mainPageStack') pathStack: NavPathStack = new NavPathStack();
```

**推入页面**：

```typescript
this.pathStack.pushPath({ name: 'AboutPage' });
this.pathStack.pushPath({ name: 'GeneralSettingsPage' });
```

**宽屏工作台通过 `@Event` 请求跳转**（子组件不直接碰栈）：

```typescript
// pages/MainPage.ets
WideDoctorWorkspace({
  /* ... */
  onOpenAbout: () => { this.pathStack.pushPath({ name: 'AboutPage' }); },
  onOpenGeneral: () => { this.pathStack.pushPath({ name: 'GeneralSettingsPage' }); },
  onLogout: () => { this.handleLogout(); }
})
```

### 🔑 一个巧妙的设计：两个路由名映射到同一个组件

```typescript
if (name === 'AboutPage') {
  MineDetailPage({ pageType: 'about' })        // ← 同一个组件
} else if (name === 'GeneralSettingsPage') {
  MineDetailPage({ pageType: 'general' })      // ← 不同的 pageType 参数
}
```

`MineDetailPage` 内部按 `pageType` 分叉：

```typescript
@Param @Require pageType: MineDetailType;      // 'about' | 'general'

build() {
  HdsNavDestination() {
    Scroll(this.scroller) {
      Row() {
        Column({ space: 18 }) {
          if (this.pageType === 'about') {
            this.aboutContent()
          } else {
            this.generalContent()
          }
        }
        .width('100%')
        .constraintSize({ maxWidth: 720 })
      }
    }
  }
}
```

**好处**：两个设置类页面共享标题栏样式、滚动行为、布局骨架，只有内容不同。
**代价**：一个文件 494 行，承载两个页面的内容。数量再多就该拆了。

### 新增页面的完整步骤

```
1. 写一个组件（用 @ComponentV2 + HdsNavDestination 作为根）
2. 在 MainPage.destinationBuilder 里加一个 if 分支
3. 在需要跳转的地方调 this.pathStack.pushPath({ name: '你的路由名' })
```

**注意**：加 `NavPathStack` 路由**不需要**改 `main_pages.json`。
`main_pages.json` 只管 `router` 那一套。

（本项目规范里写着「加真实路由要同时改 `main_pages.json` 和 `destinationBuilder`」——
这句话的准确含义是：如果你要加的是 **router 级页面**才需要改 `main_pages.json`；
如果只是 NavPathStack 目的地，只改 `destinationBuilder` 即可。）

## 7.4 机制三：模态与浮层

### 三种做法

| 做法 | 从哪出来 | 适合 |
|---|---|---|
| `bindSheet` | 底部升起，半屏/全屏可拖 | 详情预览、表单、操作面板 |
| `bindContentCover` | 全屏覆盖 | 需要占满屏幕的展开页 |
| `Stack` + 条件渲染 | 手动控制层级 | 需要盖住一切（包括 TabBar）的场景 |

### 7.4.1 `bindSheet`：半模态面板

```typescript
Column() { /* 触发区域 */ }
  .onClick(() => { this.isOpen = true; })
  .bindSheet(this.isOpen, this.sheetBuilder, {
    detents: [SheetSize.LARGE, SheetSize.MEDIUM],   // 可拖拽的高度档位
    height: SheetSize.FIT_CONTENT,                  // 或固定高度
    showClose: true,
    dragBar: true,
    title: { title: '标题', subtitle: '副标题' },
    backgroundColor: $r('sys.color.background_secondary'),
    preferType: SheetType.BOTTOM,                   // BOTTOM / CENTER / POPUP
    blurStyle: BlurStyle.Thick,
    maskColor: 'rgba(0,0,0,0.2)',
    enableOutsideInteractive: false,                // 背后能不能点
    onWillAppear: () => { },
    onAppear: () => { },
    onWillDisappear: () => { },
    onDisappear: () => { this.isOpen = false; },    // 必须在这里同步状态
    shouldDismiss: (sheetDismiss: SheetDismiss) => { sheetDismiss.dismiss(); },
    onWillDismiss: (action: DismissSheetAction) => { }
  })
```

### 关键约束：`onDisappear` 必须同步状态

```typescript
onDisappear: () => { this.isQuickRowSheetOpen = false; }
```

**为什么**：用户可以下滑手势关闭面板，这时候你的 `@Local` 变量还是 `true`。
下次点击时，`true → true` 没有变化，面板不会重新打开。

遗漏该行会导致面板只能打开一次，是常见缺陷。

### 本项目的真实例子（条件绑定 + 动态配置）

`component/TabPageView.ets`：

```typescript
@Builder
private quickListRow(item: QuickListRow, isLast: boolean) {
  Row() { /* 行内容 */ }
    .onClick(() => {
      this.selectedQuickRowId = item.id;      // ① 记住是哪一项
      this.isQuickRowSheetOpen = true;        // ② 打开
    })
    .bindSheet(
      this.isQuickRowSheetOpen && this.selectedQuickRowId === item.id,   // 条件
      this.quickRowSheetBuilder,
      this.quickRowSheetOptions(item)                                    // 动态配置
    )
}
```

**注意 `bindSheet` 的第一个参数**：

```typescript
this.isQuickRowSheetOpen && this.selectedQuickRowId === item.id
```

因为 `bindSheet` 挂在**每一行**上（列表有 N 行就有 N 个 bindSheet），
必须加 `selectedQuickRowId === item.id` 判断，否则 N 个面板会同时弹出来。

**动态配置**（按内容多少选不同高度）：

```typescript
private quickRowSheetOptions(item: QuickListRow): SheetOptions {
  if (this.allTasks().some((task: CareTask) => task.id === item.id)) {
    // 任务详情内容多 → 大档位，可拖拽
    return {
      detents: [SheetSize.LARGE, SheetSize.MEDIUM],
      showClose: true, dragBar: true,
      title: { title: item.title },
      backgroundColor: $r('sys.color.background_secondary'),
      onDisappear: () => { this.isQuickRowSheetOpen = false; }
    };
  }
  // 其它内容少 → 贴合内容高度
  return {
    height: SheetSize.FIT_CONTENT,
    showClose: true, dragBar: true,
    title: { title: item.title },
    backgroundColor: $r('sys.color.background_secondary'),
    onDisappear: () => { this.isQuickRowSheetOpen = false; }
  };
}
```

### 7.4.2 `bindContentCover`：全屏覆盖

```typescript
.bindContentCover(this.isShow, this.coverBuilder, {
  modalTransition: ModalTransition.NONE,       // NONE / DEFAULT / ALPHA
  backgroundColor: 'rgba(0,0,0,0)',
  onWillDismiss: (action: DismissContentCoverAction) => {
    if (action.reason === DismissReason.PRESS_BACK) {
      this.close();
    }
  },
  onAppear: () => { },
  onDisappear: () => { }
})
```

**三种 `modalTransition`**：

| 值 | 效果 | 什么时候用 |
|---|---|---|
| `DEFAULT` | 从下往上滑入 | 普通全屏页 |
| `ALPHA` | 淡入淡出 | 简单覆盖 |
| `NONE` | **无转场** | **一镜到底必用**（把动画交给 `geometryTransition`） |

**本项目全部用 `NONE`**（因为都配了一镜到底）：

```typescript
// component/TabPageView.ets，三个 cover 用了同一套配置
.bindContentCover(this.isResidentDetailShow, this.residentDetailCover, {
  modalTransition: ModalTransition.NONE,
  backgroundColor: 'rgba(0,0,0,0)',
  onWillDismiss: (action: DismissContentCoverAction) => {
    if (action.reason === DismissReason.PRESS_BACK) { this.closeResidentDetail(); }
  }
})
.bindContentCover(this.isHealthExpandShow, this.healthExpandCover, { /* 同上 */ })
.bindContentCover(this.isTaskExpandShow, this.taskExpandCover, { /* 同上 */ })
```

### `DismissReason` 枚举

```typescript
DismissReason.PRESS_BACK      // 按了返回键/手势
DismissReason.TOUCH_OUTSIDE   // 点了外部
DismissReason.CLOSE_BUTTON    // 点了关闭按钮
DismissReason.SLIDE_DOWN      // 下滑关闭
```

**只处理你关心的**：

```typescript
onWillDismiss: (action: DismissContentCoverAction) => {
  if (action.reason === DismissReason.PRESS_BACK) {
    this.close();      // 走自己的关闭逻辑（带动画）
  }
  // 不调 action.dismiss() 就是「我自己处理」
}
```

### 7.4.3 `Stack` + 条件渲染（最灵活）

```typescript
// pages/MainPage.ets
build() {
  Stack() {
    if (this.isRoleAdapted()) {
      HdsNavigation(this.pathStack) { /* 整个 App 主体 */ }
    } else {
      this.roleWipPanel()
    }

    if (this.isAiChatShow) {        // ← AI 聊天浮层
      this.aiChatCover()
    }
  }
  .width('100%').height('100%')
}
```

**为什么 AI 聊天不用 `bindContentCover`**：

`bindContentCover` 挂在某个具体组件上，它的覆盖范围和层级受宿主限制。
而 AI 聊天页需要**盖住包括底部 TabBar 在内的整个 App**，
放在 `MainPage` 最外层的 `Stack` 里最可靠。

**代价**：必须手动处理返回键（见下一节）。

### 7.4.4 浮层必须手动拦截返回键

**问题**：浮层不是页面，系统按返回键时会**直接退出整个 App**，而不是关闭浮层。

**解法**：在 `@Entry` 页面的 `onBackPress` 里拦截。

```typescript
// pages/MainPage.ets
onBackPress(): boolean {
  if (this.isAiChatShow) {           // ① AI 浮层开着 → 关掉它
    this.closeAiChat();
    return true;                     //    true = 我处理了，别退出 App
  }
  if (this.isWideLayout() && this.pathStack.size() === 0 && this.currentTabIndex !== 0) {
    this.switchTab(0);               // ② 宽屏、栈是空的、不在首页 → 回首页
    return true;
  }
  return false;                      // ③ 其它情况走默认（退出 App）
}
```

**注意判断顺序**：从「最上层的浮层」往下判断。有多个浮层时要一层层写。

**`bindSheet` / `bindContentCover` 不用这么麻烦**，它们有 `onWillDismiss` 能接管返回键。
只有 `Stack` 方案需要手动拦截。

## 7.6 机制选择决策树

```
我要做一个新的界面…
│
├─ 它会替换掉整个 App 的外壳吗（比如另一个「App 模式」）？
│   └─ YES → router.replaceUrl + 写进 main_pages.json
│            （本项目只有登录/退出属于这种，新功能几乎不会）
│
├─ 它是一个「二级页面」，用户点进去、看完点返回？
│   ├─ 需要标准的标题栏 + 返回按钮 + 系统返回键自动生效？
│   │   └─ YES → NavPathStack：加 destinationBuilder 分支 + pushPath
│   │
│   └─ 需要从某个卡片「长出来」（一镜到底）？
│       └─ YES → bindContentCover + geometryTransition
│
├─ 它是从底部升起的面板（表单/详情预览/操作列表）？
│   └─ YES → bindSheet
│
├─ 它需要盖住包括底部 TabBar 在内的一切？
│   └─ YES → Stack + 条件渲染 + onBackPress 手动拦截
│
└─ 它只是一个确认框 / 提示？
    └─ YES → AlertDialog / promptAction.showToast
```

## 7.7 常见问题

### Q1：为什么我的浮层按返回键直接退出 App 了？

浮层不是页面。在 `@Entry` 页面的 `onBackPress()` 里拦截，返回 `true`。

### Q2：`bindSheet` 只能打开一次，第二次点没反应？

`onDisappear` 里忘了 `this.isOpen = false;`

### Q3：列表里每一行都 `bindSheet`，点一行弹出好几个？

第一个参数要加身份判断：

```typescript
.bindSheet(this.isOpen && this.selectedId === item.id, builder, options)
```

### Q4：`@Consumer('xxx')` 拿到的栈 `pushPath` 没反应？

别名字符串和 `@Provider('xxx')` 不一致（拼写错误）。这个错误**不报错**，只是静默失效。

### Q5：`pushPath` 后页面白屏？

`destinationBuilder` 里没有对应的 `name` 分支，或者名字拼错了。

### Q6：一镜到底和 `bindContentCover` 的默认动画打架？

`modalTransition` 必须设成 `ModalTransition.NONE`。

### Q7：`Navigation` 里 `pushPath` 有默认转场，怎么关？

```typescript
this.pathStack.pushPath({ name: 'X' }, false);    // 第二个参数 animated = false
this.pathStack.pop(false);
```

### Q8：`router` 报弃用警告怎么办？

本项目只在登录边界用它，忽略警告即可。新功能一律走 `NavPathStack`。

### Q9：怎么在浮层里再开一个浮层？

可以，但 `onBackPress` 的判断要按层级从上到下写：

```typescript
onBackPress(): boolean {
  if (this.isLevel2Show) { this.closeLevel2(); return true; }
  if (this.isLevel1Show) { this.closeLevel1(); return true; }
  return false;
}
```

### Q10：怎么做「返回时刷新上一页」？

用 `pushPathByName` 的 `onPop` 回调：

```typescript
this.pathStack.pushPathByName('EditPage', param, (popInfo: PopInfo) => {
  this.refreshData(popInfo.result);
}, true);
```

```typescript
// ① router（只在认证边界用）
import { router } from '@kit.ArkUI';
await router.replaceUrl({ url: 'pages/MainPage' });

// ② NavPathStack
@Provider('mainPageStack') pathStack: NavPathStack = new NavPathStack();   // 祖先
@Consumer('mainPageStack') pathStack: NavPathStack = new NavPathStack();   // 后代

@Builder
private destinationBuilder(name: string, param?: ESObject) {
  if (name === 'AboutPage') { MineDetailPage({ pageType: 'about' }) }
}

HdsNavigation(this.pathStack) { }.navDestination(this.destinationBuilder).mode(NavigationMode.Stack)

this.pathStack.pushPath({ name: 'AboutPage' });
this.pathStack.pushPath({ name: 'X' }, false);      // 关掉转场（一镜到底时）
this.pathStack.pop();
this.pathStack.size();

// ③ bindSheet
.bindSheet(this.isOpen && this.selectedId === item.id, this.builder, {
  detents: [SheetSize.LARGE, SheetSize.MEDIUM],
  showClose: true, dragBar: true,
  title: { title: '标题' },
  onDisappear: () => { this.isOpen = false; }        // 必须
})

// ④ bindContentCover（一镜到底）
.bindContentCover(this.isShow, this.builder, {
  modalTransition: ModalTransition.NONE,             // 必须
  backgroundColor: 'rgba(0,0,0,0)',
  onWillDismiss: (a: DismissContentCoverAction) => {
    if (a.reason === DismissReason.PRESS_BACK) { this.close(); }
  }
})

// ⑤ Stack 浮层 + 返回拦截
Stack() { MainContent(); if (this.isShow) { this.overlay() } }

onBackPress(): boolean {
  if (this.isShow) { this.close(); return true; }
  return false;
}
```
