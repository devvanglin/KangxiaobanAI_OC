## 13.1 性能红线（违反了一定卡）

### 🔴 红线 1：`build()` 和 `@Builder` 里不能有重活

```typescript
// ❌ 每次渲染都排序 500 条数据
build() {
  Column() {
    ForEach(this.items.sort((a, b) => a.time - b.time), (item) => { })
  }
}

// ❌ 每次渲染都 JSON.parse
build() {
  Text(JSON.parse(this.rawData).title)
}

// ❌ 每次渲染都创建对象
build() {
  Row().backgroundColor(new ColorMetrics(...))
}

// ✅ 用 @Computed 缓存
@Computed
get sortedItems(): Item[] {
  return this.items.slice().sort((a, b) => a.time - b.time);
}

// ✅ 或者在数据变化时算一次，存成状态
@Monitor('rawData')
onRawDataChange(): void {
  this.parsedData = JSON.parse(this.rawData);
}
```

**为什么严重**：`build()` 每次状态变化都可能执行。一秒 60 帧 = 一秒可能执行 60 次。

**本项目的正面例子**（`model/TabsBarModel.ets` 用 Map 缓存 TabBar 样式）：

```typescript
private static pageTabBarStyleMap: Map<PageKeyEnum, BottomTabBarStyle[]> = new Map();

public static getTabBarByPage(pageKey: PageKeyEnum): BottomTabBarStyle[] {
  if (!TabsBarModel.pageTabBarStyleMap.has(pageKey)) {
    // 只在第一次构造
    /* ... 构造 4 个 BottomTabBarStyle + 8 个 SymbolGlyphModifier ... */
    TabsBarModel.pageTabBarStyleMap.set(pageKey, tabBarStyleList);
  }
  return TabsBarModel.pageTabBarStyleMap.get(pageKey) ?? [];
}
```

**本项目的反面例子**（`component/TabPageView.ets`）：

```typescript
private allResidents(): ResidentData[] {
  return [ /* 12 个长者对象字面量 */ ];      // ← 每次调用都新建 12 个对象
}

private filteredResidents(): ResidentData[] {
  return this.allResidents().filter(/* ... */);   // ← 又调一次
}
```

这些方法在 `build()` 里被调用，**每次渲染都重建整个数组**。
数据量小（12 条）所以感觉不到，但**这是错误示范**。数据一多就会卡。

**正确做法**：把 mock 数据提到模块级常量，或者用 `@Computed`。

### 🔴 红线 2：长列表必须用 `LazyForEach` 或 `Repeat`

```typescript
// ❌ 1000 条数据用 ForEach → 一次性创建 1000 个节点 → 卡死
ForEach(this.thousandItems, (item) => { ListItem() { } })

// ✅ LazyForEach → 只创建可见的
LazyForEach(this.dataSource, (item) => { ListItem() { } }, (item) => item.id)

// ✅ 或 Repeat + virtualScroll
Repeat(this.items).virtualScroll().each((r) => { }).key((i) => i.id)
```

**分界线**：

| 数据量 | 用什么 |
|---|---|
| < 100 | `ForEach` 够用 |
| 100 ~ 1000 | `Repeat`（V2 项目首选） |
| > 1000 | `LazyForEach` + `cachedCount` |

### 🔴 红线 3：`ForEach`/`Repeat` 必须给稳定唯一 key

```typescript
// ❌ 用 index 当 key
ForEach(this.items, (item) => { }, (item, index) => `${index}`)
// 删除第一项 → 所有 index 变化 → 框架认为全部变了 → 全部重建

// ✅ 用数据 id
ForEach(this.items, (item) => { }, (item) => item.id)
```

**例外**：静态列表（永不增删改）用 index 是可以的。
本项目 `MainPage.wideNavGroups()` 就是静态的，用 index 没问题。

### 🔴 红线 4：定时器和监听器必须清理

```typescript
// ✅ 本项目的正确做法（component/TabPageView.ets）
private timerId: number = -1;

aboutToAppear(): void {
  this.timerId = setInterval(() => { this.currentTime = new Date(); }, 1000);
}

aboutToDisappear(): void {
  if (this.timerId !== -1) {
    clearInterval(this.timerId);
    this.timerId = -1;
  }
}
```

**不清理的后果**：组件销毁后定时器还在跑，持有组件引用 → **内存泄漏 + 无效渲染**。

**要清理的东西清单**：

```
□ setTimeout / setInterval        → clearTimeout / clearInterval
□ window.on(...)                  → window.off(...)
□ mediaquery listener.on(...)     → listener.off(...)
□ emitter.on(...)                 → emitter.off(...)
□ AVPlayer / 相机 / 传感器          → release()
□ 数据库连接                        → close()
```

### 🔴 红线 5：动画优先用 transform 类属性

```typescript
// ❌ 慢：每帧重新测量+布局
.width(this.isOpen ? 300 : 100)
.animation({ duration: 300 })

// ✅ 快：只在合成阶段处理
.scale({ x: this.isOpen ? 1 : 0.33 })
.animation({ duration: 300 })
```

| 属性 | 触发什么 | 开销 |
|---|---|---|
| `translate` / `scale` / `rotate` / `opacity` | 只合成 | 🟢 低 |
| `backgroundColor` / `borderRadius` | 重绘 | 🟡 中 |
| `width` / `height` / `padding` / `margin` | 重新测量 + 布局 + 绘制 | 🔴 高 |

**但要权衡**：`scale` 会把内容一起缩放（文字变形）。
本项目侧边栏折叠就接受了宽度动画的开销（`72 ↔ 288`），因为文字不能变形。

### 🔴 红线 6：模糊效果要克制

```typescript
.backgroundBlurStyle(BlurStyle.Thick)     // GPU 开销大
.blur(20)
.shadow({ radius: 20 })                    // 大半径阴影也很贵
```

**规则**：

- ❌ 不要在**滚动列表的每一项**上加模糊
- ❌ 不要**大面积**（全屏）持续模糊
- ❌ 不要让模糊**参与动画**
- ✅ 用 HDS 的 `materialLevel: ADAPTIVE`（系统会按设备降级）

### 🔴 红线 7：嵌套层级不要太深

```
> 5 层嵌套 → 考虑用 RelativeContainer 压平
> 10 层 → 一定有问题
```

**查看层级**：ArkUI Inspector。

### 🔴 红线 8：能用 Row/Column 就不用 Flex

`Flex` 需要**二次测量**（先算每个子元素想要多大，再按剩余空间分配）。
`Row`/`Column` 只测一次。

**只有需要 `wrap`（自动换行）时才用 `Flex`。**

## 13.2 内存优化

### 图片

```typescript
// ❌ 加载 4000×3000 的原图当缩略图
Image($r('app.media.huge_photo')).width(100).height(100)

// ✅ 限制解码尺寸
Image($r('app.media.huge_photo'))
```

```typescript
struct ListItemComponent {
  @Param data: Item;
  build() { }

```

配合 `LazyForEach` 使用，滚动时复用节点而不是新建。

```typescript
aboutToDisappear(): void {
```

## 13.3 启动优化

```
□ onCreate / onWindowStageCreate 里不做耗时操作
□ 首页只加载首屏必需的数据
□ 大数据延迟到 aboutToAppear 里异步加载
□ 图片资源压缩（webp 比 png 小很多）
□ 不必要的模块用 feature（按需下载）
□ 谨慎使用 preloadItems（本项目预加载了 4 个 Tab，因为数据是 mock 的所以没问题）
```

**本项目的 `preloadItems` 权衡**：

```typescript
.onAttach(() => {
  this.controller.preloadItems([0, 1, 2, 3]);     // 预加载全部 4 个 Tab
})
```

好处：切 Tab 零延迟。
代价：启动时构造 4 个 `TabPageView`（每个都有 20+ 个 `@Local` 和大量 mock 数据）。

**如果 Tab 内容有网络请求，这么做会拖慢启动，应该只预加载相邻的。**

## 13.5 「界面不刷新」排查流程

按顺序检查，90% 的问题在前 5 步：

### 1️⃣ 变量有装饰器吗

```typescript
count: number = 0;           // ❌
@Local count: number = 0;    // ✅
```

### 2️⃣ 是不是在改 `@Param`

```typescript
@Param value: string = '';
this.value = 'x';            // ❌ 编译报错
```
→ 让父改（`@Event`），或加 `@Once`。

### 3️⃣ 类字段有 `@Trace` 吗

```typescript
@ObservedV2
class M {
  name: string = '';          // ❌
  @Trace name2: string = '';  // ✅
}
```

### 4️⃣ 嵌套的每一层都是 `@ObservedV2` 吗

```typescript
@ObservedV2 class A { @Trace b: B = new B(); }
class B { @Trace c: string = ''; }      // ❌ B 缺 @ObservedV2，链断了
```

### 5️⃣ 数组元素是 `@ObservedV2` 吗

```typescript
this.list[0].name = 'x';       // ❌ 元素不是 @ObservedV2
this.list = [...this.list];    // ✅ 整体替换强制触发
```

### 6️⃣ `ForEach` 的 key 变了吗

用了 index 当 key，数据换了但 index 没变 → 框架认为没变。

### 7️⃣ `this` 丢了吗

```typescript
setTimeout(function() { this.count++; }, 100);   // ❌
setTimeout(() => { this.count++; }, 100);        // ✅
```

### 8️⃣ `@Consumer` 找到 `@Provider` 了吗

别名字符串拼错 → 静默失效。

### 9️⃣ `@Monitor` 的路径写对了吗

```typescript
@Monitor('globalInfoModel.keyboardHeigt')   // ← 少个 h，静默失效
```

### 🔟 改的是 `AppStorageV2` 里的那个实例吗

```typescript
const m = new GlobalInfoModel();      // ❌ 新建的，不是 storage 里那个
m.role = '医师';

const m = AppStorageV2.connect(GlobalInfoModel, StorageKey.GLOBAL_INFO, () => new GlobalInfoModel());
m!.role = '医师';                      // ✅
```

## 13.6 本项目已知缺陷清单

> 这些是**已记录、待修复**的问题。
> **不要依赖它们的现有行为，也不要照抄这些写法。**

### 缺陷 1：`PreferenceManager.hasValue()` 无限递归 🔴

**位置**：`util/PreferenceManager.ets:91-103`

```typescript
public hasValue(key: string): boolean {
  if (this.preferences) {
    try {
      return this.preferences.hasSync(key);
    } catch (err) {
      Logger.error(TAG, `Preferences hasValue ${key} failed. ...`);
      return false;
    }
  } else {
    this.initPreference(PREFERENCES_NAME);
    return this.hasValue(key);            // ★★ 无限递归，栈溢出
  }
}
```

**问题**：如果 `initPreference` 失败（`UIContext` 未就绪），`this.preferences` 仍是 undefined，
然后又递归调自己 → 无限循环 → 崩溃。

**对比**：`setValue` / `getValue` / `deleteValue` 都有 `retry: boolean` 参数控制只重试一次，
只有 `hasValue` 漏了。

**修法**：

```typescript
public hasValue(key: string, retry: boolean = true): boolean {
  if (this.preferences) {
    try {
      return this.preferences.hasSync(key);
    } catch (err) {
      Logger.error(TAG, `Preferences hasValue ${key} failed. err code:${err.code},msg:${err.message}`);
      return false;
    }
  }
  if (retry) {
    this.initPreference(PREFERENCES_NAME);
    return this.hasValue(key, false);
  }
  return false;
}
```

**当前影响**：`hasValue` 目前**没有被任何代码调用**，所以还没炸。但一旦有人用就会踩雷。

### 缺陷 2：`HealthExpandPage` 的 ListScroller 没绑定 🟡

**位置**：`pages/HealthExpandPage.ets:33, 100-167, 200-203`

```typescript
private listScroller: ListScroller = new ListScroller();   // ← 创建了

build() {
  Stack({ alignContent: Alignment.End }) {
    Scroll() {                    // ★ 用的是 Scroll，不是 List
      Row() { Column() { Repeat<ElderGroup>(...) } }
    }
    .scrollBar(BarState.Off)      // ★ 没有把 listScroller 传进去

    AlphabetIndexer({ arrayValue: this.alphabets(), selected: this.selectedIndex })
      .onSelect((index: number) => { this.onIndexerSelected(index); })
  }
}

private onIndexerSelected(index: number): void {
  this.selectedIndex = index;
  this.listScroller.scrollToIndex(index);    // ★ 对一个未绑定的 scroller 调用 → 无效果
}
```

**症状**：点右侧的楼层索引条，高亮会变，但**列表不会滚动**。

**修法**（二选一）：

```typescript
// 方案 A：把 Scroll 换成 List，绑定 scroller
List({ scroller: this.listScroller }) {

    ListItemGroup({ header: this.itemGroupHeader(g.item.letter) }) {
      Repeat<HealthRowData>(g.item.elders).each((e) => { ListItem() { } })
    }
  })
}

// 方案 B：改用 Scroller + scrollTo（自己算偏移量）
private scroller: Scroller = new Scroller();
Scroll(this.scroller) { }
```

**另外**：`onListScrolled(firstIndex)` 这个方法也定义了但**从未被调用**（滚动时索引条不会跟着高亮）。

### 缺陷 3：`WindowUtil` 监听器没有反注册 🟡

**位置**：`util/WindowUtil.ets:95-107`

```typescript
windowClass.on('windowSizeChange', (windowSize: window.Size) => WindowUtil.setWindowSize(windowSize));
windowClass.on('avoidAreaChange', (avoidAreaOption) => { /* ... */ });
```

**问题**：没有对应的 `off()`。

**当前影响**：App 生命周期内只注册一次，理论上没有实际泄漏。
但如果以后加了 `onWindowStageDestroy` 重新初始化的逻辑，就会重复注册。

**建议**：加一个对称的清理方法，并在 `onWindowStageDestroy` 里调用：

```typescript
public static release(): void {
  try {
    WindowUtil.windowClass?.off('windowSizeChange');
    WindowUtil.windowClass?.off('avoidAreaChange');
  } catch (err) {
    Logger.error(TAG, `release failed: ${err.message}`);
  }
}
```

**规范**：**以后加任何监听器，都要先写好清理再写注册。**

### 缺陷 6：「减少动效」设置不生效 🟡

**位置**：`pages/MineDetailPage.ets`

```typescript
const PREF_REDUCE_MOTION: string = 'general_reduce_motion';
@Local reduceMotion: boolean = false;

aboutToAppear(): void {
  this.reduceMotion = this.readBoolean(PREF_REDUCE_MOTION, false);
}
```

这个值被读写和持久化了，但**没有任何动画代码消费它**。
用户打开「减少动效」，所有动画照常播放。

**这是无障碍问题**（前庭功能障碍用户需要这个设置真的生效）。

**修法思路**：把这个状态提到 `GlobalInfoModel`，然后在所有 `animateTo` 前判断：

```typescript
private animate(action: () => void): void {
  if (this.globalInfoModel.reduceMotion) {
    action();                                  // 直接改，不动画
  } else {
    this.getUIContext().animateTo({ curve: curves.interpolatingSpring(0, 1, 328, 36) }, action);
  }
}
```

### 缺陷 11：手机横屏会进宽屏布局 🟢

```typescript
private isWideLayout(): boolean {
  return BreakpointUtil.isWide(this.globalInfoModel.widthBreakpoint);
  //  ↑ 只看宽度断点
}
```

手机横屏时宽度可能达到 `WIDTH_MD`（≥600vp），触发宽屏工作台布局。
但手机横屏的高度很小，宽屏布局会很挤。

**可能的改法**（加高度判断）：

```typescript
private isWideLayout(): boolean {
  return BreakpointUtil.isWide(this.globalInfoModel.widthBreakpoint) &&
    this.globalInfoModel.heightBreakpoint !== HeightBreakpoint.HEIGHT_SM;
}
```

**注意**：这是一个**产品决策**，不是纯技术问题。改之前要确认设计意图。

### 缺陷 12：`WaterFlowView` 的 `@Computed` 有副作用 🟡

**位置**：`component/WaterFlowView.ets:57-66`

```typescript
@Computed
get getBannerItemsCount(): number {
  this.handleTabBarAnimation?.(-1);      // ★ 在 @Computed 里调用回调 = 副作用
  const bannerItemsCount: number = new BreakpointType({ /* ... */ }).getValue(/* ... */);
  return bannerItemsCount;
}
```

**问题**：`@Computed` 应该是**纯函数**（只算值，不做别的）。
这里调用了 `handleTabBarAnimation` 回调，属于副作用。

**风险**：`@Computed` 的重算时机由框架决定，副作用的触发时机就变得不可预测。

**不要照抄这个写法。**

## 13.7 安全清单

### 🔒 绝对禁止

```
❌ 引入弱加密（MD5/SHA1/DES/3DES/ECB-AES/短密钥 RSA-DSA-DH）
   → linter 是 error 级别，构建直接失败

❌ 打印/复制/提交 build-profile.json5 里的证书路径和密码

❌ 日志里输出敏感信息用 %{public}s
   → token/密码/手机号/证件号必须用 %{private}s

❌ 基于 GlobalInfoModel.role 做权限判断
   → 那只是登录页的一个下拉选择，用户随便改

❌ 把本地数组增删说成「已保存到服务器」
   → 本项目没有网络层
```

### ✅ 本项目的安全定位

**这是一个纯本地交互原型**：

- 无网络层
- 无真实鉴权（登录接受任何非空账号密码，延迟 800ms 后放行）
- AI 回复是本地确定性文本，不是真模型
- 所有数据是 mock

**在任何文档、演示、汇报里都要如实说明这一点。**
