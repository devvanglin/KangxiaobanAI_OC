## 6.1 ArkUI 的四种动画

| 类型 | 触发方式 | 写法 | 适用 |
|---|---|---|---|
| **① 属性动画** | 属性值变了自动播 | `.animation({...})` | 简单的颜色/尺寸/位移变化 |
| **② 显式动画** | 你主动调用 | `animateTo({...}, () => {改状态})` | 需要精确控制的复杂动画 |
| **③ 转场动画** | 组件出现/消失 | `.transition(TransitionEffect...)` | 元素进出场 |
| **④ 共享元素转场** | 两个页面共享一个 ID | `.geometryTransition('id')` | **一镜到底** |

**一镜到底 = ② + ③ + ④ 三者配合。**

## 6.2 属性动画 `.animation()`

### 最简单的形式

```typescript
@ComponentV2
struct Demo {
  @Local isBig: boolean = false;

  build() {
    Column() {
      Row()
        .width(this.isBig ? 200 : 100)          // ← 这个属性会动画
        .height(this.isBig ? 200 : 100)         // ← 这个也会
        .backgroundColor(Color.Blue)
        .animation({ duration: 300, curve: Curve.EaseInOut })   // 放最后

      Button('切换').onClick(() => { this.isBig = !this.isBig; })
    }
  }
}
```

### `AnimateParam` 全部参数

```typescript
.animation({
  duration: 300,                    // 时长（ms），默认 1000
  tempo: 1.0,                       // 播放速度倍率
  curve: Curve.EaseInOut,           // 曲线
  delay: 0,                         // 延迟（ms）
  iterations: 1,                    // 重复次数，-1 = 无限
  playMode: PlayMode.Normal,        // Normal / Reverse / Alternate / AlternateReverse
  onFinish: () => { },              // 动画结束回调
  finishCallbackType: FinishCallbackType.REMOVED,
  expectedFrameRateRange: { min: 30, max: 120, expected: 60 }   // 期望帧率
})
```

### ⚠️ 最重要的规则：`.animation()` 只影响写在它**前面**的属性

```typescript
// ✅ 正确
Row()
  .width(this.w)          // ← 有动画
  .opacity(this.o)        // ← 有动画
  .animation({ duration: 300 })

// ❌ 错误
Row()
  .animation({ duration: 300 })
  .width(this.w)          // ← 没动画
```

### 分段控制（进阶）

```typescript
Row()
  .width(this.w)
  .animation({ duration: 300 })      // width 用 300ms
  .opacity(this.o)
  .animation({ duration: 100 })      // opacity 用 100ms
```

### 本项目的真实用法

`component/wide/WideSlidingCapsule.ets`（滑动胶囊）：

## 6.3 显式动画 `animateTo()`

### 基本形式

```typescript
this.getUIContext().animateTo(
  { duration: 300, curve: Curve.EaseOut },     // ① 动画参数
  () => {                                       // ② 在这个闭包里改状态
    this.isOpen = true;
  }
);
```

**理解方式**：

> 「把闭包里造成的**所有** UI 变化，用这套参数做成动画。」

### 和 `.animation()` 的区别

| | `.animation()` | `animateTo()` |
|---|---|---|
| 作用范围 | 单个组件的部分属性 | **闭包里改的状态影响的所有组件** |
| 触发 | 属性变化时自动 | 你主动调用 |
| 适合 | 局部小动效 | 页面级、跨组件的联动动画 |
| 能否做转场 | ❌ | ✅（配合 `transition`/`geometryTransition`） |

### 关键：`animateTo` 能让「组件的插入/删除」变成动画

```typescript
// ❌ 直接改，浮层瞬间出现，很生硬
this.isShow = true;

// ✅ 包在 animateTo 里，配合 transition 就有进场动画
this.getUIContext().animateTo({ curve: curves.interpolatingSpring(0, 1, 328, 36) }, () => {
  this.isShow = true;
});
```

### 本项目的标准开关模式

`component/TabPageView.ets`：

```typescript
private openHealthExpand(): void {
  this.getUIContext().animateTo({
    curve: curves.interpolatingSpring(0, 1, 328, 36)     // ← 打开用这组参数
  }, () => {
    this.isHealthExpandShow = true;
  })
}

private closeHealthExpand(): void {
  this.getUIContext().animateTo({
    curve: curves.interpolatingSpring(0, 1, 342, 38)     // ← 关闭用这组（略硬一点，更快收回）
  }, () => {
    this.isHealthExpandShow = false;
  })
}
```

**注意开关用了不同参数**：`(0,1,328,36)` 打开、`(0,1,342,38)` 关闭。
关闭的刚度（328→342）和阻尼（36→38）都更大 → 关闭更快更利落。
以上为华为官方示例中的标准取值，建议直接沿用。

`pages/MainPage.ets` 也是同一套：

```typescript
private openAiChat(): void {
  this.getUIContext().animateTo({ curve: curves.interpolatingSpring(0, 1, 328, 36) }, () => {
    this.isAiChatShow = true;
  })
}

private closeAiChat(): void {
  this.getUIContext().animateTo({ curve: curves.interpolatingSpring(0, 1, 342, 38) }, () => {
    this.isAiChatShow = false;
  })
}
```

### `keyframeAnimateTo`：关键帧动画

```typescript
this.getUIContext().keyframeAnimateTo({ iterations: 1 }, [
  { duration: 500, curve: Curve.Ease, event: () => { this.x = 100; } },
  { duration: 300, curve: Curve.Ease, event: () => { this.x = 50; } },
  { duration: 200, curve: Curve.Ease, event: () => { this.x = 80; } },
]);
```

## 6.4 动画曲线（Curve）

### 内置曲线枚举 `Curve`

| 曲线 | 效果 | 用在哪 |
|---|---|---|
| `Linear` | 匀速 | 进度条、旋转 |
| `Ease` | 慢-快-慢 | 通用 |
| `EaseIn` | 慢起 | 元素退场 |
| `EaseOut` | 快起慢停 | **元素入场（最常用）** |
| `EaseInOut` | 两头慢中间快 | 状态切换 |
| `FastOutSlowIn` | 材质设计标准曲线 | 通用 |
| `Friction` | 摩擦减速 | **滑动、拖拽后的收尾** |
| `Sharp` | 锐利 | 快速的透明度变化 |
| `Rhythm` | 节奏感 | 特殊场景 |
| `Smooth` | 平滑 | 通用 |
| `ExtremeDeceleration` | 极度减速 | 大幅度位移 |

### `curves` 模块（更强大）

```typescript
import { curves } from '@kit.ArkUI';

curves.initCurve(Curve.EaseOut)                        // 把枚举转成 ICurve
curves.cubicBezierCurve(0.33, 0, 0.67, 1)              // 三次贝塞尔（和 CSS 一样）
curves.stepsCurve(4, true)                             // 阶跃
curves.springCurve(velocity, mass, stiffness, damping) // 弹簧（时长由物理决定）
curves.springMotion(response?, dampingFraction?, overlapDuration?)
curves.responsiveSpringMotion(response?, dampingFraction?, overlapDuration?)
curves.interpolatingSpring(velocity, mass, stiffness, damping)   // 一镜到底专用
curves.customCurve((fraction: number) => number)       // 完全自定义
```

### `interpolatingSpring` 详解

```typescript
curves.interpolatingSpring(velocity, mass, stiffness, damping)
//                          初速度   质量   刚度      阻尼
```

| 参数 | 含义 | 调大了会怎样 |
|---|---|---|
| `velocity` | 初速度 | 一开始冲得更猛 |
| `mass` | 质量 | 更「重」，动得更慢，惯性更大 |
| `stiffness` | 刚度（弹簧硬度） | 更快到达目标 |
| `damping` | 阻尼 | 更少回弹/震荡（太小会来回抖） |

**华为官方标准值（直接抄）**：

```typescript
curves.interpolatingSpring(0, 1, 328, 36)    // 打开：稍软，有轻微回弹感
curves.interpolatingSpring(0, 1, 342, 38)    // 关闭：稍硬，干脆
curves.interpolatingSpring(0, 1, 350, 35)    // 按压反馈
curves.interpolatingSpring(0, 1, 195, 23)    // 大幅度位移（慢一些）
```

这些取值来自华为设计系统的调校结果，不建议自行设定，沿用上述四组即可。

**重要特性**：`interpolatingSpring` 的动画时长**由物理参数决定**，
所以**不需要也不能设置 `duration`**（设了会被忽略）。

### `springMotion` vs `interpolatingSpring`

```typescript
curves.springMotion(0.55, 0.825)    // response(响应时间), dampingFraction(阻尼比)
```

`springMotion` 更直观（响应时间 = 大概多久到位），
`interpolatingSpring` 更精确（物理参数）。

**本项目侧边栏折叠用的是 `springMotion()`**（不传参用默认值）：

```typescript
private toggleSidebar(): void {
  this.getUIContext().animateTo({ curve: curves.springMotion() }, () => {
    this.isSidebarCollapsed = !this.isSidebarCollapsed;
  });
}
```

## 6.5 转场动画 `TransitionEffect`

### 干什么

控制组件**出现**和**消失**时的动画。

```typescript
if (this.show) {
  Column() { }
    .transition(TransitionEffect.OPACITY)     // 出现时淡入，消失时淡出
}
```

### 内置效果

```typescript
TransitionEffect.IDENTITY                     // 无效果（立即出现/消失）
TransitionEffect.OPACITY                      // 透明度 0↔1
TransitionEffect.SLIDE                        // 滑入滑出
TransitionEffect.SLIDE_SWITCH                 // 滑动切换

TransitionEffect.opacity(0.5)                 // 自定义起始透明度
TransitionEffect.translate({ x: 100, y: 0 })  // 平移
TransitionEffect.scale({ x: 0.9, y: 0.9 })    // 缩放
TransitionEffect.rotate({ angle: 90 })        // 旋转
TransitionEffect.move(TransitionEdge.BOTTOM)  // 从某个边进出
```

### 组合：`.combine()`

```typescript
TransitionEffect.OPACITY
  .combine(TransitionEffect.scale({ x: 0.9, y: 0.9 }))
  .animation({ curve: curves.interpolatingSpring(0, 1, 195, 23) })
```

（这是 `transitions-collection/ListLongTakeTransitionPageOne.ets` 的真实代码。）

### 非对称：`.asymmetric()`

进场和出场用不同效果：

```typescript
TransitionEffect.asymmetric(
  TransitionEffect.OPACITY.animation({ duration: 200, delay: 150, curve: curves.cubicBezierCurve(0.33, 0, 0.67, 1) }),  // 进场：延迟 150ms 再淡入
  TransitionEffect.OPACITY.animation({ duration: 200, curve: curves.cubicBezierCurve(0.33, 0, 0.67, 1) })                // 出场：立即淡出
)
```

（`transitions-collection/SearchLongTakeTransitionPageTwo.ets` 的返回箭头就是这么做的：
进场时**晚一点**出现，让搜索框的形变先完成，视觉更干净。）

### ⚠️ 关键：`transition` 必须配合 `animateTo` 才有动画

```typescript
// ❌ 没有动画（瞬间出现）
this.show = true;

// ✅ 有动画
this.getUIContext().animateTo({ curve: ... }, () => { this.show = true; });
```

**`transition` 只是「描述用什么效果」，`animateTo` 才是「播放」。**

## 6.6 一镜到底 `geometryTransition`

### 6.6.1 一镜到底的定义

「一镜到底」（Shared Element Transition / Long Take Transition）指：

> 用户点击列表里的一张卡片，这张卡片**平滑地放大、变形**成为详情页，
> 中间没有跳转闪烁，视觉上像一个连续的镜头运动。

对比：

```
❌ 传统跳转：       ✅ 一镜到底：
┌────┐             ┌────┐
│卡片│  → 闪一下 →  │卡片│ → 卡片放大变形 → ┌────────┐
└────┘   全新页面   └────┘                 │ 详情页  │
                                          └────────┘
```

### 6.6.2 API 定义（SDK 实测）

```typescript
// sdk/default/openharmony/ets/component/common.d.ts:28958
geometryTransition(id: string, options?: GeometryTransitionOptions): T;
// @since 11（基础），@since 12（atomicservice）

declare interface GeometryTransitionOptions {
  follow?: boolean;    // 默认 false
}
```

**只有两个参数**，但用对不容易。

### 6.6.2.5 三种转场机制怎么选（官方推荐）

| 场景 | 用什么 |
|---|---|
| 两个页面有**相同/相似元素** | ★ `geometryTransition`（共享元素转场） |
| `router` 页面之间的整页切换 | `pageTransition` |
| `Navigation` 页面之间的自定义转场 | `customNavContentTransition` |

**本项目 4 处一镜到底全部走 `geometryTransition`。**

**时长建议**：转场动画控制在 **300~600ms**。
- 太短（<200ms）→ 用户看不清发生了什么，显得生硬
- 太长（>800ms）→ 拖沓，操作效率下降

用弹簧曲线时不需要手动设时长（物理参数决定），
本项目用的 `interpolatingSpring(0,1,328,36)` 实际时长就落在这个区间内。

### 6.6.3 工作原理

```
① 你给「起点组件」和「终点组件」绑同一个 id
       起点：.geometryTransition('myId', { follow: true })
       终点：.geometryTransition('myId')

② 在 animateTo 闭包里，让起点消失、终点出现

③ 框架检测到：「有两个组件共享 id 'myId'，一个正在消失、一个正在出现」

④ 框架自动计算两者的位置、尺寸差异，
   生成一个从「起点几何形状」到「终点几何形状」的插值动画

⑤ 播放这个动画（用 animateTo 指定的曲线）
```

**关键点**：框架只负责「几何形变」（位置+尺寸+圆角），
**内容的淡入淡出要你自己用 `.transition(TransitionEffect.OPACITY)` 补上**。

### 6.6.4 `follow` 参数的含义

SDK 原文注释：

> `whether follow target for the component still in the hierarchy, default: false, stay current.`

翻译：**「仍然留在 UI 树上的那个组件，是否要跟随目标一起形变」**

| 场景 | `follow` 的值 |
|---|---|
| 起点组件（点击后仍留在树上，只是被盖住了） | `{ follow: true }` |
| 终点组件（新出现的） | 不传（默认 `false`） |

**记忆法**：

> **起点带 `follow: true`，终点不带。**

**为什么起点要 `follow: true`**：
一镜到底打开时，列表还在下面没被销毁。如果不设 `follow: true`，
起点卡片会**留在原位不动**，你会看到「原卡片还在，又飞出来一个新卡片」的双影 bug。

### 6.6.5 六个必检项

| # | 检查项 | 常见错误 |
|---|---|---|
| 1 | **两边 id 完全一致** | 拼写错、大小写不同、动态 id 生成规则不一致 |
| 2 | **起点有 `{ follow: true }`，终点没有** | 两边都写 follow、或都不写 |
| 3 | **两边都有 `.transition(TransitionEffect.OPACITY)`** | 只写了 geometryTransition，内容会硬切 |
| 4 | **插入/删除包在 `animateTo` 里** | 直接 `this.show = true` 没动画 |
| 5 | **`bindContentCover` 用了 `modalTransition: ModalTransition.NONE`** | 用默认转场会和 geometry 打架 |
| 6 | **起点在打开后渲染成空占位** | 不然会看到重影 |

### 6.6.6 最小完整示例

```typescript
@Entry
@ComponentV2
struct MinimalLongTake {
  @Local isDetailShow: boolean = false;

  // ① 打开（用打开曲线）
  private open(): void {
    this.getUIContext().animateTo({
      curve: curves.interpolatingSpring(0, 1, 328, 36)
    }, () => { this.isDetailShow = true; });
  }

  // ② 关闭（用关闭曲线）
  private close(): void {
    this.getUIContext().animateTo({
      curve: curves.interpolatingSpring(0, 1, 342, 38)
    }, () => { this.isDetailShow = false; });
  }

  // ③ 终点（详情页）
  @Builder
  private detailCover() {
    Column() {
      Text('详情内容').fontSize(24)
      Button('关闭').onClick(() => { this.close(); })
    }
    .width('100%')
    .height('100%')
    .backgroundColor(Color.White)
    .geometryTransition('myCard')              // 终点：不带 follow
    .transition(TransitionEffect.OPACITY)      // 必须
  }

  build() {
    Column() {
      // ④ 起点（卡片）
      if (this.isDetailShow) {
        // 打开后渲染空占位，承载形变，避免重影
        Column()
          .width('100%').height(100)
          .backgroundColor(Color.Gray)
          .borderRadius(16)
      } else {
        Column() {
          Text('点我展开').fontSize(18)
        }
        .width('100%').height(100)
        .backgroundColor(Color.Gray)
        .borderRadius(16)
        .geometryTransition('myCard', { follow: true })   // 起点：带 follow
        .transition(TransitionEffect.OPACITY)              // 必须
        .onClick(() => { this.open(); })
      }
    }
    .width('100%').height('100%').padding(16)
    .bindContentCover(this.isDetailShow, this.detailCover, {
      modalTransition: ModalTransition.NONE,               // 必须 NONE
      backgroundColor: 'rgba(0,0,0,0)',
      onWillDismiss: (action: DismissContentCoverAction) => {
        if (action.reason === DismissReason.PRESS_BACK) { this.close(); }
      }
    })
  }
}
```

以上即为一镜到底的完整最小实现。 把它跑通，后面所有变体都是在这个骨架上加东西。

### ① 搜索一镜到底（`SearchLongTakeTransition`）

**场景**：点搜索框 → 搜索框飞到顶部 → 展开搜索页

**关键代码（起点，PageOne）**：

```typescript
Search({ placeholder: 'Search' })
  .height(40).width('100%')
  .geometryTransition('SEARCH_ONE_SHOT_DEMO_TRANSITION_ID', { follow: true })
  .backgroundColor('#0D000000')
  .defaultFocus(false)         // 起点不要抢焦点
  .focusOnTouch(false)
  .focusable(false)
  .onTouch((event: TouchEvent) => {
    if (event.type === TouchType.Up) { this.showSearchPage(); }
  })

private showSearchPage(): void {
  this.transitionEffect = TransitionEffect.OPACITY;
  this.getUIContext().animateTo({
    curve: curves.interpolatingSpring(0, 1, 342, 38)
  }, () => {
    this.pageInfos.pushPath({ name: 'SearchLongTakeTransitionPageTwo' }, false);
    //                                                                   ↑ animated=false！
  })
}
```

**🔑 重点 1**：`pushPath(..., false)` —— **关掉 Navigation 自带的转场动画**，
否则会和 `geometryTransition` 打架（相当于 `bindContentCover` 的 `ModalTransition.NONE`）。

**关键代码（终点，PageTwo）**：

```typescript
Row({ space: 8 }) {
  Image($r('app.media.img'))        // 返回箭头
    .width(40).height(40)
    .onClick(() => { this.onArrowClicked(); })
    .transition(TransitionEffect.asymmetric(
      TransitionEffect.OPACITY.animation({ duration: 200, delay: 150, curve: curves.cubicBezierCurve(0.33, 0, 0.67, 1) }),
      TransitionEffect.OPACITY.animation({ duration: 200, curve: curves.cubicBezierCurve(0.33, 0, 0.67, 1) })
    ))
    //  ↑ 进场延迟 150ms，等搜索框形变完成再出现

  Search({ placeholder: 'DevEco Studio' })
    .height(40).width('85%')
    .geometryTransition('SEARCH_ONE_SHOT_DEMO_TRANSITION_ID')    // 终点
    .transition(TransitionEffect.opacity(0.99))                   // 注意是 0.99 不是 1
    .defaultFocus(true)          // 终点自动聚焦，弹出键盘
    .focusOnTouch(true)
}
```

**🔑 重点 2**：`TransitionEffect.opacity(0.99)` 而不是 `TransitionEffect.OPACITY`。
`0.99` 是一个技巧：让组件**几乎不透明但仍标记为「有转场」**，
避免完全不透明时框架跳过转场处理。这是官方示例里的实战技巧。

**🔑 重点 3**：焦点管理。起点 `focusable(false)`（点了不弹键盘），终点 `defaultFocus(true)`（自动弹）。
这样用户点搜索框 → 形变 → 到位后键盘弹出，节奏很自然。

**返回**：


### ② 列表一镜到底（`ListLongTakeTransition`）

**场景**：备忘录列表 → 点某条 → 展开为详情

**关键点 1：用 index 做动态 ID**

**关键点 2：按压反馈（细节控必看）**

```typescript
private onTouchProcess(event?: TouchEvent): void {
  if (!event) return;
  if (event.type === TouchType.Down) {
    this.getUIContext().animateTo({ curve: curves.interpolatingSpring(0, 1, 350, 35) },
      () => { this.scaleValue = 0.95; });        // 按下缩小
  } else if (event.type === TouchType.Up || event.type === TouchType.Cancel) {
    this.getUIContext().animateTo({ curve: curves.interpolatingSpring(0, 1, 350, 35) },
      () => { this.scaleValue = 1; });           // 松开恢复
  }
}
```

**注意 `TouchType.Cancel` 也要处理**，否则用户按下后手指滑走，卡片会一直保持缩小状态。

**关键点 3：页面级转场（列表页整体后退）**


然后详情页用 `customNavContentTransition` 手动做动画（`LongTakeAnimationProperties.ets`）：

```typescript
public doEnterAnimation(transitionProxy: NavigationTransitionProxy): void {
  // 起始状态 = 卡片的位置和尺寸
  this.scaleValue = this.initScale;
  this.translateX = this.initTranslateX;
  this.clipWidth = this.initClipWidth;
  this.clipHeight = this.initClipHeight;
  this.translateY = this.initTranslateY;

  // 动画到全屏状态
  uiContext?.animateTo({
    duration: 350, curve: Curve.EaseInOut,
    onFinish: () => { transitionProxy.finishTransition(); }    // 必须调，否则转场卡住
  }, () => {
    this.scaleValue = 1.0;
    this.translateX = 0; this.translateY = 0;
    this.clipWidth = '100%'; this.clipHeight = '100%';
    this.radius = 34;
  });

  // 截图淡出
  uiContext?.animateTo({ delay: 50, duration: 100, curve: Curve.Sharp },
    () => { this.snapShotOpacity = 0; });

  // 真实内容淡入
  uiContext?.animateTo({ duration: 100, curve: Curve.Sharp },
    () => { this.postPageOpacity = 1.0; });
}
```

**什么时候需要这种复杂做法**：

- 起点和终点**结构差异太大**，`geometryTransition` 的自动形变效果不好
- 需要精确控制**裁剪区域**（`clipWidth`/`clipHeight`）
- 起点在 `LazyForEach` 里可能已被回收

**结论**：**优先用 `geometryTransition`**，只有它做不出效果时才考虑截图法。
本项目 4 处一镜到底全部用的 `geometryTransition`。

## 6.9 一镜到底的完整检查清单

```
□ 1. 起点和终点的 geometryTransition ID 完全一致（拼写、大小写、动态生成规则）
□ 2. 起点写 { follow: true }，终点不写
□ 3. 起点和终点都加了 .transition(TransitionEffect.OPACITY)
□ 4. 打开/关闭都包在 this.getUIContext().animateTo(...) 里
□ 5. 打开曲线 interpolatingSpring(0, 1, 328, 36)，关闭 (0, 1, 342, 38)
□ 6. bindContentCover 用了 modalTransition: ModalTransition.NONE
      或 pushPath(..., false) 关掉 Navigation 转场
□ 7. bindContentCover 的 backgroundColor 是 'rgba(0,0,0,0)'（透明）
□ 8. 起点在展开状态下渲染成【空占位】，尺寸/圆角和真卡片一致
□ 9. onWillDismiss 里处理了 PRESS_BACK，调用关闭方法
□ 10. 动态 ID 场景：@Local 保存了 activeGeometryId，并传给了终点组件
□ 11. 终点组件用 @Param 接收 geometryId，而不是硬编码
□ 12. 焦点：起点 focusable(false)，终点 defaultFocus(true)（如果涉及输入框）
```

### 常见故障 → 原因对照

| 现象 | 原因 |
|---|---|
| 完全没动画，直接闪现 | 没包在 `animateTo` 里，或 `modalTransition` 不是 `NONE` |
| 有两个卡片（重影） | 起点没渲染空占位，或没加 `{ follow: true }` |
| 卡片飞到错误的位置 | ID 不匹配（框架找不到配对，退化成普通转场） |
| 形变正常但内容硬切 | 缺 `.transition(TransitionEffect.OPACITY)` |
| 动画很生硬 | 用了 `duration` 而不是弹簧曲线 |
| 返回时没动画 | 关闭没包 `animateTo`，或 `onWillDismiss` 没处理 |
| 打开瞬间闪黑边 | `bindContentCover` 的 `backgroundColor` 没设成透明 |
| 列表滚动后打开位置错乱 | 起点组件被 `LazyForEach` 回收了 → 改用 `Repeat` 或截图法 |

## 6.11 `customNavContentTransition`：自定义 Navigation 转场

给 `Navigation` / `HdsNavigation` 用的高级能力：

```typescript
declare type CustomTransitionDelegate = (
  from: NavContentInfo,
  to: NavContentInfo,
  operation: NavigationOperation

```

```typescript
HdsNavigation(this.pathStack) { }
  .customNavContentTransition((from, to, operation) => {
    if (/* 需要自定义 */) {
      return {
        timeout: 1000,
        transition: (transitionProxy: NavigationTransitionProxy) => {

  })
```

## 6.12 动画性能规则

| # | 规则 | 原因 |
|---|---|---|
| 1 | **优先动画 `transform` 类属性**（`translate`/`scale`/`rotate`/`opacity`） | 这些只在合成阶段处理，不触发重新布局 |
| 2 | **避免动画 `width`/`height`/`padding`/`margin`** | 会触发重新测量+布局，每帧都算，很贵 |
| 3 | **避免在动画中改变列表数据** | 会触发列表重建 |
| 4 | **模糊（blur/backgroundBlurStyle）不要参与动画** | GPU 开销极大 |
| 5 | **同时动画的元素不要超过 10 个** | — |
| 6 | **弹簧曲线不要设 `duration`** | 会被忽略，还会误导后来人 |
| 7 | **动画期间不要做 I/O 或重计算** | 会掉帧 |
| 8 | `expectedFrameRateRange` 按需设置 | 简单动画 30fps 就够，省电 |

### 举例：宽度动画的替代方案

```typescript
// ❌ 慢：每帧重新布局
.width(this.isOpen ? 300 : 100)
.animation({ duration: 300 })

// ✅ 快：只在合成阶段缩放
.width(300)
.scale({ x: this.isOpen ? 1 : 0.33 })
.animation({ duration: 300 })
```

**但要注意**：`scale` 会同时缩放内容（文字也变小），不一定符合设计意图。
本项目的侧边栏折叠就是**接受了宽度动画的开销**（`this.isSidebarCollapsed ? 72 : 288`），
因为文字不能变形。**性能和效果要权衡，不是死规则。**
