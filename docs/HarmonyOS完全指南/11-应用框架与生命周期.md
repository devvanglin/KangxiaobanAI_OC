# 第 11 章 · 应用框架与生命周期（Stage 模型）

> 本章说明应用的启动、运行与销毁流程，以及各配置文件字段的含义。

---

## 11.1 Stage 模型全景

### 层级关系

```
应用（Application）  = 一个 bundleName，比如 com.gxoc.kxbai
 │
 ├── AbilityStage    （模块级运行时容器，可选实现）
 │
 └── HAP 包（模块）
      │
      └── UIAbility  （一个「有界面的能力」≈ 安卓的 Activity）
           │
           └── WindowStage  （窗口舞台，管理这个 Ability 的所有窗口）
                │
                └── Window   （主窗口 / 子窗口）
                     │
                     └── Page（你的 @Entry 页面）
                          │
                          └── 组件树（Column / Row / Text ...）
```

### 类比

| 鸿蒙 | 安卓 | iOS | Web |
|---|---|---|---|
| Application | Application | UIApplication | 整个站点 |
| UIAbility | Activity | UIViewController（根） | 一个 tab 页 |
| WindowStage | — | UIWindowScene | — |
| Window | Window | UIWindow | 浏览器窗口 |
| Page (@Entry) | Fragment / 布局 | View | 一个 HTML 页面 |

### 还有哪些 Ability 类型

| 类型 | 有界面吗 | 干什么 |
|---|---|---|
| **UIAbility** | ✅ | ★普通的、有界面的能力（本项目用这个） |
| ExtensionAbility | 视子类而定 | 扩展能力的基类 |
| ├─ FormExtensionAbility | ✅ 卡片 | 桌面服务卡片 |
| ├─ ServiceExtensionAbility | ❌ | 后台服务（系统应用才能用） |
| ├─ WorkSchedulerExtensionAbility | ❌ | 延迟任务 |
| ├─ InputMethodExtensionAbility | ✅ | 输入法 |
| ├─ UIExtensionAbility | ✅ | 嵌入到别的应用里的界面 |
| └─ ... | | |

**本项目只有一个 `UIAbility`。**

## 11.2 `UIAbility` 生命周期

### 完整回调（本项目 `ets/entryability/EntryAbility.ets` 全文）

```typescript
import { AbilityConstant, ConfigurationConstant, UIAbility, Want } from '@kit.AbilityKit';
import { window } from '@kit.ArkUI';
import Logger from '../util/Logger';
import { WindowUtil } from '../util/WindowUtil';

const TAG: string = '[KanxiaobanAbility]';

export default class KanxiaobanAbility extends UIAbility {

  // ① Ability 被创建（整个生命周期只调一次）
  onCreate(want: Want, launchParam: AbilityConstant.LaunchParam): void {
    try {
      // ★设置深色模式跟随系统
      this.context.getApplicationContext()
        .setColorMode(ConfigurationConstant.ColorMode.COLOR_MODE_NOT_SET);
    } catch (err) {
      Logger.error(TAG, `Failed to set colorMode. Cause: ${err.message}`);
    }
    Logger.info(TAG, 'Ability onCreate');
  }

  // ② 窗口舞台创建（最重要的回调）
  onWindowStageCreate(windowStage: window.WindowStage): void {
    Logger.info(TAG, 'Ability onWindowStageCreate');

    windowStage.loadContent('pages/LoginPage', (err) => {   // ★加载首页
      if (err.code) {
        Logger.error(TAG, `Failed to load the content. Cause: ${err.message}`);
        return;
      }
      WindowUtil.initialize(windowStage);                   // ★初始化窗口工具
      Logger.info(TAG, 'Succeeded in loading the content.');
    });
  }

  // ③ 进入前台
  onForeground(): void {
    Logger.info(TAG, 'Ability onForeground');
  }

  // ④ 进入后台
  onBackground(): void {
    Logger.info(TAG, 'Ability onBackground');
  }

  // ⑤ 窗口舞台销毁
  onWindowStageDestroy(): void {
    Logger.info(TAG, 'Ability onWindowStageDestroy');
  }

  // ⑥ Ability 销毁
  onDestroy(): void {
    Logger.info(TAG, 'Ability onDestroy');
  }
}
```

### 调用顺序

**冷启动**：

```
onCreate → onWindowStageCreate → onForeground → (页面 aboutToAppear → build)
```

**按 Home 键回桌面**：

```
onBackground
```

**再次点开 App（热启动）**：

```
onForeground
```

**退出（上滑清理）**：

```
onBackground → onWindowStageDestroy → onDestroy
```

### 其它可选回调

```typescript
onNewWant(want: Want, launchParam: AbilityConstant.LaunchParam): void {
  // 已经在运行时，又被启动了一次（singleton 模式下）
}

onConfigurationUpdate(newConfig: Configuration): void {
  // 系统配置变了（语言、深浅色、字号）
}

onMemoryLevel(level: AbilityConstant.MemoryLevel): void {
  // 系统内存紧张，可以在这里释放缓存
}

onSaveState(reason: AbilityConstant.StateType, wantParam: Record<string, Object>): AbilityConstant.OnSaveResult {
  // 保存状态（应用被系统回收前）
  return AbilityConstant.OnSaveResult.ALL_AGREE;
}
```

### 各阶段该做什么

| 回调 | 该做的事 | 不该做的事 |
|---|---|---|
| `onCreate` | 全局配置（深浅色模式）、初始化不依赖 UI 的服务 | 操作窗口（还没有窗口） |
| `onWindowStageCreate` | ★`loadContent` 加载页面、初始化窗口监听 | 耗时操作（会拖慢启动） |
| `onForeground` | 恢复动画、刷新数据、重新订阅 | — |
| `onBackground` | 暂停动画、保存草稿、释放摄像头等独占资源 | 长耗时操作（可能被杀） |
| `onWindowStageDestroy` | 注销窗口监听 | — |
| `onDestroy` | 释放所有资源 | 假设它一定会被调用（可能被强杀） |

## 11.3 `windowStage.loadContent()`

### 三种重载

```typescript
// ① 只指定页面路径
windowStage.loadContent('pages/LoginPage', (err) => { });

// ② 带 LocalStorage（V1 用法）
windowStage.loadContent('pages/Index', storage, (err) => { });

// ③ 命名路由（配合 @Entry({ routeName: 'xxx' })）
windowStage.loadContentByName('MyRouteName', (err) => { });
```

### ⚠️ 关键点：这个路径必须在 `main_pages.json` 里

```json
// resources/base/profile/main_pages.json
{ "src": ["pages/LoginPage", "pages/MainPage"] }
```

**本项目加载的是 `pages/LoginPage`**，所以 App 一启动就是登录页。

### ⚠️ 回调里才能拿到窗口

```typescript
windowStage.loadContent('pages/LoginPage', (err) => {
  if (err.code) { return; }
  WindowUtil.initialize(windowStage);      // ← 必须在回调里
});
```

**为什么**：`loadContent` 是异步的，回调触发时页面才真正加载完，
这时候 `getMainWindowSync()` 和 `getUIContext()` 才可靠。

**如果放在回调外面**，可能拿到 undefined 或者旧的 UIContext。

## 11.4 Window 窗口 API

### 拿到窗口

```typescript
import { window } from '@kit.ArkUI';

const win: window.Window = windowStage.getMainWindowSync();
// 或异步
const win = await windowStage.getMainWindow();
```

### 沉浸式全屏

```typescript
// ① 布局全屏（内容延伸到状态栏/导航条下面）
win.setWindowLayoutFullScreen(true);

// ② 系统栏透明
win.setWindowSystemBarProperties({
  statusBarColor: '#00000000',
  navigationBarColor: '#00000000',
  statusBarContentColor: '#FFFFFF',        // 状态栏文字/图标颜色
  navigationBarContentColor: '#FFFFFF'
});

// ③ 隐藏/显示某个系统栏
win.setSpecificSystemBarEnabled('status', false, false);
win.setSpecificSystemBarEnabled('navigation', true, false);

// ④ 隐藏所有系统栏（全屏游戏/视频）
win.setWindowSystemBarEnable([]);          // 空数组 = 全隐藏
win.setWindowSystemBarEnable(['status', 'navigation']);   // 都显示
```

**本项目的实现**（`util/WindowUtil.ets`）：

```typescript
public static setImmersiveMode(enable: boolean): void {
  if (!WindowUtil.windowClass) return;

  WindowUtil.windowClass.setWindowLayoutFullScreen(enable)
    .catch((err: BusinessError) => {
      Logger.error(TAG, `setWindowLayoutFullScreen failed. code: ${err.code}, message: ${err.message}`);
    });

  WindowUtil.windowClass.setWindowSystemBarProperties({
    statusBarColor: '#00000000',
    navigationBarColor: '#00000000'
  }).catch((err: BusinessError) => {
    Logger.error(TAG, `setWindowSystemBarProperties failed. code: ${err.code}, message: ${err.message}`);
  });
}

public static setSystemBarForDarkBackground(isDarkBackground: boolean): void {
  if (!WindowUtil.windowClass) return;

  // 深色背景时隐藏状态栏
  WindowUtil.windowClass.setSpecificSystemBarEnabled('status', !isDarkBackground, false)
    .catch((err: BusinessError) => { /* ... */ });

  // 深色背景 → 白字；浅色背景 → 黑字
  WindowUtil.windowClass.setWindowSystemBarProperties({
    statusBarContentColor: isDarkBackground ? '#ffffff' : '#000000',
    navigationBarContentColor: isDarkBackground ? '#ffffff' : '#000000'
  }).catch((err: BusinessError) => { /* ... */ });
}
```

**`setImmersiveMode` 在本项目被调用两次**（`pages/AiChatPage.ets`）：

```typescript
aboutToAppear(): void {
  WindowUtil.setImmersiveMode(true);      // AI 聊天页进入更深的沉浸
  // ...
}

aboutToDisappear(): void {
  // ...
  WindowUtil.setImmersiveMode(false);     // 离开时还原
}
```

```typescript
properties.windowRect.height;     // px！
properties.isFullScreen;
```

**注意**：返回的是 **px**，要 `px2vp` 转换。

### 获取避让区

```typescript
area.topRect.height;       // px

```

**四种类型**：


```typescript
win.on('windowSizeChange', (size: window.Size) => { });
win.on('avoidAreaChange', (opt: { type: window.AvoidAreaType, area: window.AvoidArea }) => { });
```

## 11.5 Context 上下文

### 三种 Context

```typescript
// ① Ability 级（在 UIAbility 里）
const ctx: common.UIAbilityContext = this.context;

// ② Application 级
const appCtx: common.ApplicationContext = this.context.getApplicationContext();

// ③ 在组件里拿 Context
const ctx = this.getUIContext().getHostContext();   // 返回 Context | undefined
```

### Context 能干什么

```typescript
// 文件路径
ctx.filesDir;          // 应用私有文件目录
ctx.cacheDir;          // 缓存目录（系统可能清理）
ctx.tempDir;           // 临时目录
ctx.databaseDir;       // 数据库目录
ctx.preferencesDir;    // 偏好设置目录
ctx.bundleCodeDir;     // 安装包目录（只读）
ctx.distributedFilesDir;   // 分布式文件目录

// 资源管理
ctx.resourceManager.getStringSync($r('app.string.xxx').id);
ctx.resourceManager.getMediaContentSync($r('app.media.xxx').id);

// 应用信息
ctx.applicationInfo;
ctx.abilityInfo;
ctx.config;            // 当前配置（语言、深浅色、字号）

// 启动其它 Ability
ctx.startAbility({ bundleName: 'com.other.app', abilityName: 'MainAbility' });
ctx.terminateSelf();   // 结束自己
```

### 本项目怎么在非 UI 代码里拿 Context

**问题**：`util/PreferenceManager.ets` 是一个普通 class，没有 `this.getUIContext()`。

**解法**：把 `UIContext` 存进 `AppStorageV2`。

```typescript
// util/WindowUtil.ets（存）
const uiContext: UIContext = WindowUtil.windowClass.getUIContext();
WindowUtil.uiContext = uiContext;
AppStorageV2.connect(UIContext, StorageKey.UI_CONTEXT, () => uiContext);

// util/PreferenceManager.ets（取）
private initPreference(storeName: string): void {
  const uiContext: UIContext | undefined = AppStorageV2.connect(UIContext, StorageKey.UI_CONTEXT);
  try {
    if (!uiContext) {
      Logger.error(TAG, `initPreference failed, cause uiContext is undefined.`);
      return;
    }
    this.preferences = preferences.getPreferencesSync(
      uiContext.getHostContext() as Context,      // ★通过 UIContext 拿 Context
      { name: storeName }
    );
  } catch (err) {
    Logger.error(TAG, `initPreference failed, err code:${err.code},msg:${err.message}`);
  }
}
```

这是一种通用做法，建议沿用。

## 11.7 数据持久化

### 三种方案

| 方案 | Kit | 适合 | 本项目 |
|---|---|---|---|
| **Preferences（键值对）** | `@kit.ArkData` | 少量配置、开关 | ✅ 已封装（`PreferenceManager`） |
| **关系型数据库（RDB）** | `@kit.ArkData` | 结构化数据、需要查询 | ❌ 没用 |
| **文件读写** | `@kit.CoreFileKit` | 大文件、二进制 | ❌ 没用 |
| **PersistenceV2** | `@kit.ArkUI` | 状态对象持久化 | ❌ 没用 |

### Preferences 完整用法（本项目的 `PreferenceManager`）

```typescript
import { preferences, ValueType } from '@kit.ArkData';
import { AppStorageV2, UIContext } from '@kit.ArkUI';

const PREFERENCES_NAME: string = 'KanxiaobanStore';

export class PreferenceManager {
  private preferences?: preferences.Preferences;
  private static instance: PreferenceManager;

  private constructor() {
    this.initPreference(PREFERENCES_NAME);
  }

  public static getInstance(): PreferenceManager {
    if (!PreferenceManager.instance) {
      PreferenceManager.instance = new PreferenceManager();
    }
    return PreferenceManager.instance;
  }

  private initPreference(storeName: string): void {
    const uiContext: UIContext | undefined = AppStorageV2.connect(UIContext, StorageKey.UI_CONTEXT);
    try {
      if (!uiContext) {
        Logger.error(TAG, `initPreference failed, cause uiContext is undefined.`);
        return;
      }
      this.preferences = preferences.getPreferencesSync(
        uiContext.getHostContext() as Context, { name: storeName });
    } catch (err) {
      Logger.error(TAG, `initPreference failed, err code:${err.code},msg:${err.message}`);
    }
  }

  public setValue<T>(key: string, value: T, retry: boolean = true): void {
    if (this.preferences) {
      try {
        this.preferences.putSync(key, JSON.stringify(value));   // ★存 JSON 字符串
        this.saveValue();
      } catch (e) {
        Logger.error(TAG, `Preferences put ${key} failed, err code:${e?.code},msg:${e?.message}`);
      }
    } else {
      if (retry) {                                   // ★失败重试一次
        this.initPreference(PREFERENCES_NAME);
        this.setValue<T>(key, value, false);
      }
    }
  }

  public getValue<T>(key: string, defaultValue?: ValueType, retry: boolean = true): T | null {
    if (this.preferences) {
      try {
        const res = this.preferences.getSync(key, defaultValue);
        let value: T | null = null;
        if (res) {
          value = JSON.parse(res as string) as T;
        }
        return value;
      } catch (err) {
        Logger.error(TAG, `Preferences get ${key} failed. err code:${err.code},msg:${err.message}`);
        return null;
      }
    } else {
      if (retry) {
        this.initPreference(PREFERENCES_NAME);
        return this.getValue<T>(key, defaultValue, false);
      }
      return null;
    }
  }

  public deleteValue(key: string, retry: boolean = true): void { /* 同样的重试模式 */ }

  saveValue() {
    try {
      this.preferences?.flush()                       // ★flush 才真正写盘
        .catch((err: BusinessError) => {
          Logger.error(TAG, `Preferences flush failed.err code:${err.code},msg:${err.message}`);
        });
    } catch (err) {
      Logger.error(TAG, `Preferences flush failed.err code:${err.code},msg:${err.message}`);
    }
  }
}
```

### 本项目的一处缺陷（不建议沿用此写法）

```typescript
public hasValue(key: string): boolean {
  if (this.preferences) {
    try {
      return this.preferences.hasSync(key);
    } catch (err) {
      return false;
    }
  } else {
    this.initPreference(PREFERENCES_NAME);
    return this.hasValue(key);              // ** 无限递归！**
  }
}
```

**问题**：如果 `initPreference` 失败（比如 `UIContext` 还没准备好），
`this.preferences` 仍然是 undefined，然后又递归调用自己 → **栈溢出崩溃**。

**对比其它方法都有 `retry: boolean` 参数**（只重试一次），`hasValue` 漏了。

**正确写法**：

```typescript
public hasValue(key: string, retry: boolean = true): boolean {
  if (this.preferences) {
    try {
      return this.preferences.hasSync(key);
    } catch (err) {
      Logger.error(TAG, `Preferences hasValue ${key} failed. err code:${err.code},msg:${err.message}`);
      return false;
    }
  }
  if (retry) {
    this.initPreference(PREFERENCES_NAME);
    return this.hasValue(key, false);       // ← 只重试一次
  }
  return false;
}
```

## 11.10 常见问题

### Q1：`this.context` 在组件里是 undefined？

组件（`struct`）里没有 `this.context`，那是 `UIAbility` 的。
组件里用 `this.getUIContext().getHostContext()`。

### Q2：`WindowUtil` 里的 `uiContext` 是 undefined？

`WindowUtil.initialize()` 还没被调用。
检查 `onWindowStageCreate` 的 `loadContent` 回调里有没有调。

### Q3：状态栏高度首帧是 0？

正常。`loadContent` 是异步的，首帧渲染时 `initialize` 可能还没跑完。
`@Trace` 会在拿到真值后触发重绘。

如果闪烁明显，可以在 `EntryAbility` 里同步先算一次，或者给个合理的默认值。

### Q4：App 启动很慢？

检查 `onCreate` / `onWindowStageCreate` 里有没有耗时操作。
这两个回调**必须快**，重活放到页面的 `aboutToAppear` 里异步做。

### Q5：改了 `module.json5` 不生效？

需要重新编译（有时要 `hvigorw clean`）。配置文件不是热更新的。

### Q6：怎么知道当前是 debug 还是 release？

```typescript
import BuildProfile from 'BuildProfile';      // 自动生成的
const isDebug: boolean = BuildProfile.DEBUG;
```

（本仓库的 `MusicHome` 等项目里能看到生成的 `BuildProfile.ets`。）

### Q7：应用被系统杀了，状态怎么恢复？

实现 `onSaveState` / `onCreate` 里检查 `launchParam.launchReason`：

```typescript
onCreate(want: Want, launchParam: AbilityConstant.LaunchParam): void {
  if (launchParam.launchReason === AbilityConstant.LaunchReason.APP_RECOVERY) {
    // 从恢复中启动
  }
}
```

**本项目没做**（原型不需要）。
