## 0.2 核心名词释义

### HarmonyOS（鸿蒙）

华为的操作系统。你要区分两个东西：

- **HarmonyOS（早期版本）**：底层还兼容安卓，能装 apk。
- **HarmonyOS NEXT（纯血鸿蒙 / 星河版）**：**完全不兼容安卓**，只能跑鸿蒙原生应用。

本项目是 **HarmonyOS NEXT 原生应用**。你在 `build-profile.json5` 里能看到 `"runtimeOS": "HarmonyOS"`。

### OpenHarmony

鸿蒙的**开源版本**（由开放原子基金会维护）。HarmonyOS 是华为在 OpenHarmony 上做的商业发行版。

关系类比：`OpenHarmony : HarmonyOS ≈ AOSP : 小米澎湃OS`。

你在 SDK 目录里会看到 `sdk/default/openharmony/`（开源基础能力）和 `sdk/default/hms/`（华为增值能力，比如 HDS、地图、推送）。

### API 版本号

鸿蒙的 API 版本是个整数，越大越新。本机 SDK 装的是 **API 26**，本项目用的是 **API 24**。

你会在 SDK 的 `.d.ts` 文件里看到这种注释：

```typescript
/**
 * Defining Local PropertyDecorator.
 * @since 12          ← 自 API 12 起提供，API 24 项目可用
 */
declare const Local: PropertyDecorator;
```

```typescript
/**
 * @since 23          ← 从 API 23 才有，API 24 项目可以用
 */
```

**规则**：`@since` 的数字 ≤ 你项目的 `compatibleSdkVersion`（这里是 24），才能用。

### ArkTS

华为自研的应用开发语言。**它是 TypeScript 的严格子集 + 一堆 UI 装饰器**。

- 会 TypeScript → 90% 的语法你已经会了
- 不会 TypeScript → 第 01 章从零教你

**关键认知：ArkTS 砍掉了 TypeScript 的一堆动态特性**（`any`、`unknown`、索引签名、`delete`、结构化类型……）。
砍掉不是为了折磨你，是为了让编译器能提前把类型全部确定，从而生成更快的机器码。

文件后缀：`.ets`（ArkTS 源文件），`.d.ets`（ArkTS 声明文件）。

### ArkUI

鸿蒙的 UI 框架。它是**声明式**的（第 02 章细讲）。

你写：

```typescript
Text('你好').fontSize(20).fontColor(Color.Red)
```

它就在屏幕上画一个 20 号红色的「你好」。你不需要 `findViewById`，不需要 `element.style.color = 'red'`。

ArkUI 有两套状态管理：

- **V1**（老的）：`@State` `@Prop` `@Link` `@Observed` `@Watch` `@Provide` `@Consume`
- **V2**（新的，API 12+）：`@Local` `@Param` `@Once` `@Event` `@Monitor` `@Computed` `@Provider` `@Consumer` `@ObservedV2` `@Trace`

**本项目只用 V2。** 仓库里的只读示例大多是 V1 写的，看看就好，别抄。

### ArkCompiler / 方舟编译器

把 ArkTS 编译成字节码的编译器。你基本不用直接接触它，知道它存在就行。

### HDS（HarmonyOS Design System）

华为官方的设计系统 + 组件库，通过 `@kit.UIDesignKit` 导入。

它提供了一整套「和系统 App 长得一模一样」的组件：

```typescript
import { HdsNavigation, HdsListItemCard, HdsTabs, hdsMaterial } from '@kit.UIDesignKit';
```

**本项目的 UI 几乎全部基于 HDS。** 第 08 章专门讲。

### Kit（套件）

鸿蒙把 API 按功能打包成「Kit」，用一个 import 就能拿到一整类能力：

| Kit | 干什么 | 本项目用到 |
|---|---|---|
| `@kit.ArkUI` | UI 相关工具：`AppStorageV2` `router` `curves` `window` `UIContext` | ✅ 大量 |
| `@kit.UIDesignKit` | HDS 组件库 | ✅ 大量 |
| `@kit.AbilityKit` | UIAbility、Want、Context | ✅ |
| `@kit.BasicServicesKit` | 错误类型 `BusinessError`、剪贴板 `pasteboard` | ✅ |
| `@kit.ArkData` | 数据存储：`preferences`（键值对）、关系型数据库 | ✅ |
| `@kit.PerformanceAnalysisKit` | 日志 `hilog` | ✅ |
| `@kit.InputKit` | 键盘按键码 `KeyCode` | ✅ |
| `@kit.ImageKit` | 图片处理 `PixelMap` | 示例用到 |
| `@kit.MediaKit` | 音视频播放 | 示例用到 |

**写法**：永远用 Kit 导入，不要用底层的 `@ohos.xxx`：

```typescript
// ✅ 推荐
import { AppStorageV2, router, curves } from '@kit.ArkUI';

// ❌ 不推荐（老写法，虽然也能跑）
import router from '@ohos.router';
```

### Stage 模型

App 的运行骨架。核心概念：

```
应用（App）
 └── HAP（一个可安装的包，比如 entry）
      └── UIAbility（一个「有界面的能力」，相当于安卓的 Activity）
           └── WindowStage（窗口舞台）
                └── Window（窗口）
                     └── Page（页面，你写的 @Entry 组件）
```

第 11 章细讲。

### HAP / HAR / HSP

三种模块产物：

| 类型 | 全称 | 是什么 | 什么时候用 |
|---|---|---|---|
| **HAP** | HarmonyOS Ability Package | 可以直接安装运行的包 | `entry`（主模块）、`feature`（动态特性模块） |
| **HAR** | HarmonyOS Archive | 静态库，**编译期**被打进使用方 | 抽公共代码，会被复制多份 |
| **HSP** | HarmonyOS Shared Package | 动态共享包，**运行期**共享一份 | 抽公共代码，只有一份，省体积 |

在 `module.json5` 里用 `"type"` 字段区分：

```json5
{
  "module": {
    "name": "kanxiaoban",
    "type": "entry",        // ← 这里！entry / feature / har / shared
    ...
  }
}
```

**重要**：判断一个模块是什么类型，**看 `module.json5` 的 `type`，不要看目录名字**。
本仓库里 `MusicHome/products/tv/` 目录名叫 tv，但真正的类型要看它的 `module.json5`。

### hvigor

鸿蒙的构建工具，相当于安卓的 Gradle。

命令行工具叫 `hvigorw`（w = wrapper，包装器）：

```bash
hvigorw assembleHap --mode module -p product=default -p buildMode=debug
```

### DevEco Studio

IDE，基于 IntelliJ 改的。装在 `C:\Program Files\Huawei\DevEco Studio`。

它自带 SDK、预览器（Previewer）、模拟器、调试器。

### .hap / .app

- `.hap`：单个模块的安装包
- `.app`：上架应用市场用的聚合包（包含多个 hap）

本项目构建产物：
`KangxiaobanAI/products/entry/build/default/outputs/default/kanxiaoban-default-signed.hap`

## 0.5 第一个鸿蒙页面

新建一个文件 `ets/pages/HelloPage.ets`：

```typescript
@Entry                    // ① 我是一个路由页面（能被 router 跳转到）
@ComponentV2              // ② 我是 V2 版自定义组件
struct HelloPage {        // ③ 组件必须用 struct，不是 class！

  @Local count: number = 0;   // ④ 我的私有状态，改了会自动重绘

  build() {               // ⑤ 每个组件必须有且只有一个 build()
    Column({ space: 20 }) {          // ⑥ 竖着排，子元素间距 20
      Text(`你点了 ${this.count} 次`) // ⑦ 一个文本
        .fontSize(24)                //    链式设置属性
        .fontColor(Color.Black)

      Button('点我')                  // ⑧ 一个按钮
        .width(120)
        .height(44)
        .onClick(() => {             // ⑨ 点击事件
          this.count++;              //    改状态 → UI 自动更新
        })
    }
    .width('100%')                   // ⑩ 容器占满宽
    .height('100%')
    .justifyContent(FlexAlign.Center) //   主轴（竖直方向）居中
    .alignItems(HorizontalAlign.Center) // 交叉轴（水平方向）居中
  }
}
```

然后在 `resources/base/profile/main_pages.json` 里加上它：

```json
{ "src": ["pages/LoginPage", "pages/MainPage", "pages/HelloPage"] }
```

### 逐行说明

**① `@Entry`**
这个装饰器的意思是「我是一个可以被路由系统直接打开的页面」。
只有加了 `@Entry` 并且写进 `main_pages.json` 的组件，才能用 `router.pushUrl({url: 'pages/HelloPage'})` 打开。
一个 `.ets` 文件里最多只能有一个 `@Entry`。

**② `@ComponentV2`**
声明这是一个 V2 版自定义组件。V2 是新的状态管理体系。
（老代码里你会看到 `@Component`，那是 V1，本项目禁用。）

**③ `struct HelloPage`**
鸿蒙的自定义组件必须用 `struct` 关键字，**不能用 `class`**。
`struct` 是 ArkTS 专门为 UI 组件设计的，它不能被 `new`，只能在 `build()` 里被「调用」。

**④ `@Local count: number = 0;`**
`@Local` 表示这是组件的**私有可变状态**。
关键点：**当你修改一个 `@Local` 变量时，ArkUI 会自动找出所有用到它的 UI，重新渲染它们。**
如果你去掉 `@Local`，写成 `count: number = 0`，那么 `this.count++` 之后界面**不会变**（数据变了，UI 不知道）。

**⑤ `build()`**
每个组件必须有一个 `build()` 方法，里面**只能**写 UI 描述。
`build()` 里不能写 `if...else` 之外的复杂逻辑，不能写 `for` 循环（要用 `ForEach`），不能改状态。
详见第 02 章。

**⑥ `Column({ space: 20 }) { ... }`**
`Column` = 竖直排列容器。`{ space: 20 }` 是构造参数，表示子元素之间留 20vp 间距。
后面的 `{ ... }` 是「尾随闭包」，里面写子组件。

**⑦ `Text(...)` + 链式属性**
`Text('内容')` 创建一个文本组件，然后 `.fontSize(24)` 这种链式调用设置属性。
**注意：属性方法之间没有分号，最后一个属性后面也不加分号。**

**⑧⑨ `Button` 和 `onClick`**
`onClick` 接收一个箭头函数。在箭头函数里可以安全地用 `this`（箭头函数不会重新绑定 this）。

**⑩ `.width('100%')`**
尺寸可以是数字（表示 vp，虚拟像素）或字符串百分比。

## 0.6 三种尺寸单位

| 单位 | 全称 | 含义 | 什么时候用 |
|---|---|---|---|
| **vp** | virtual pixel | 虚拟像素，**会随屏幕密度自动缩放** | 默认单位。写 `.width(100)` 就是 100vp |
| **px** | physical pixel | 物理像素，屏幕上真实的点 | 几乎不用。系统 API 返回的常常是 px，需要转换 |
| **fp** | font pixel | 字体像素，**会随用户的系统字号设置缩放** | 字号。写 `.fontSize(16)` 默认是 fp |

### 关键换算

```typescript
// 系统返回的是 px，你要转成 vp 才能用于布局
const uiContext = this.getUIContext();
const vpValue: number = uiContext.px2vp(pxValue);
const pxValue: number = uiContext.vp2px(vpValue);
```

**本项目的真实例子**（`util/WindowUtil.ets`）：

```typescript
const systemAvoidArea: window.AvoidArea = windowClass.getWindowAvoidArea(window.AvoidAreaType.TYPE_SYSTEM);
// getWindowAvoidArea 返回的 height 是 px！必须转换
globalInfoModel.statusBarHeight = WindowUtil.uiContext.px2vp(systemAvoidArea?.topRect?.height ?? 0);
```

**如果你忘了转换**，状态栏高度就会变成 3 倍大（因为典型屏幕 1vp ≈ 3px），页面顶部会空出巨大一块。
这是新手最常见的 bug 之一。

## 0.7 常见误解澄清

### 误解 1：「ArkTS 就是 TypeScript，我随便写」

**错。** ArkTS 砍了很多东西。这样写会直接编译失败：

```typescript
let x: any = 1;                        // ❌ 不支持 any
let obj = {};  obj['name'] = 'a';      // ❌ 不支持索引访问添加属性
delete obj.name;                       // ❌ 不支持 delete
function f(a: number): void;           // ❌ 不支持函数重载
const g = new Function('return 1');    // ❌ 不支持运行时生成代码
```

第 01 章有完整清单。

### 误解 2：「组件用 class 写」

**错。** 必须用 `struct`。`class` 用来写数据模型（比如 `GlobalInfoModel`）。

### 误解 3：「改了数据界面就会变」

**不一定。** 只有被 `@Local` / `@Param` / `@Trace` 等装饰器标记的数据，改了才会触发重绘。

```typescript
@ComponentV2
struct Demo {
  @Local a: number = 0;   // 改 a → 界面更新 ✅
  b: number = 0;          // 改 b → 界面不动 ❌
}
```

### 误解 4：「pages 目录下的都是页面」

**错。** 只有写进 `main_pages.json` 的才是路由页面。
本项目 `pages/` 下 6 个文件，只有 2 个是真页面。

### 误解 5：「@Entry 的组件可以被别的组件当子组件用」

技术上可以，但不应该。`@Entry` 是给路由用的，一个页面只写一个。

### 误解 6：「vp 和 px 差不多」

**差 2~3 倍。** 忘了 `px2vp` 是最常见的布局 bug 来源。

## 0.8 本章自测

1. `ArkTS`、`ArkUI`、`HDS` 三者是什么关系？
2. 自定义组件用什么关键字声明？
3. `@Local` 和普通成员变量的区别是什么？
4. `HAP`、`HAR`、`HSP` 分别是什么？怎么判断一个模块是哪种？
5. `module.json5` 和 `build-profile.json5` 分别管什么？
6. `vp` 和 `px` 怎么换算？为什么必须换算？
7. 本项目真正的路由页面有几个？分别是什么？
8. 本项目允许用 `@State` 吗？

<details>
<summary>点开看答案</summary>

1. ArkTS 是语言，ArkUI 是用这门语言写界面的框架，HDS 是基于 ArkUI 的官方现成组件库。
2. `struct`。
3. `@Local` 修饰的变量变化时会触发 UI 重新渲染；普通成员变量不会。
4. HAP 是可安装运行的包，HAR 是编译期静态库，HSP 是运行期动态共享包。看 `module.json5` 的 `type` 字段。
5. `module.json5` 管「这个模块是什么」（类型/设备/页面/权限）；`build-profile.json5` 管「怎么编译」（SDK 版本/签名/产品）。
6. `uiContext.px2vp(px)` / `uiContext.vp2px(vp)`。因为系统 API（如 avoidArea）返回 px，而布局属性用 vp，不转换会差 2~3 倍。
7. 2 个：`pages/LoginPage` 和 `pages/MainPage`。
8. **不允许。** 本项目只用状态管理 V2，`@State` 是 V1 的。

</details>
