# 第 04 章 · 布局系统：把东西摆到正确的位置

> 布局是实践中问题最集中的部分：「为什么这个东西不居中」「为什么高度是 0」「为什么被挤出去了」。
> 本章说明布局的计算规则，以便在编写阶段即可确定结果。

---

## 4.1 布局的计算过程：测量与布局

ArkUI 摆放组件分两步：

```
第一趟：测量（Measure）
  父组件对每个子组件说：「你最多能占 W×H，你想要多大？」
  子组件回答：「我要 w×h」

第二趟：布局（Layout）
  父组件根据所有子组件的回答，决定每个子组件放在哪个坐标
```

### 关键推论 1：父约束子，子决定自己

```typescript
Column() {
  Text('很长很长很长很长很长很长很长的文字')
}
.width(100)      // ← 父给的约束是 100
```

`Text` 想要更宽，但父只给 100，所以它会**换行**（因为 Text 默认允许换行）。

### 关键推论 2：`'100%'` 是相对**父容器**的

```typescript
Column() {          // 假设父是 300 宽
  Row().width('100%')   // → 300
}
.width(300)
```

### 关键推论 3：没有明确尺寸的容器 = 内容多大它多大

```typescript
Column() {
  Text('a')       // 高 20
  Text('b')       // 高 20
}
// 这个 Column 的高度自动是 40（不加 padding 的话）
```

**这就是「高度塌陷」的原因**：如果里面的内容高度是 0（比如条件渲染没渲染出来），容器就是 0。

## 4.2 尺寸单位详解

| 单位 | 会随什么变 | 用在哪 |
|---|---|---|
| **vp** | 屏幕密度 | 所有布局尺寸（宽高、间距、圆角） |
| **fp** | 屏幕密度 + **用户系统字号设置** | 字号 |
| **px** | 不变（物理点） | 只在和系统 API 交互时出现 |
| **%** | 父容器尺寸 | 相对布局 |
| **lpx** | 设计稿等比缩放 | 极少用 |

### 写法

```typescript
.width(100)        // 100vp（数字默认 vp）
.width('100vp')    // 显式 vp
.width('100px')    // 物理像素
.width('100%')     // 百分比
.width('auto')     // 自适应内容

.fontSize(16)      // 16fp（字号数字默认 fp）
.fontSize('16fp')
.fontSize('16vp')  // 强制 vp，不随用户字号变（慎用，影响无障碍）
```

### `Length` 类型

很多属性接受 `Length = string | number | Resource`：

```typescript
.width(100)                                  // number
.width('100%')                               // string
.padding($r('sys.float.padding_level8'))     // Resource ← 推荐，跟随系统间距规范
```

### 常用系统间距 token

```
sys.float.padding_level0   → 0
sys.float.padding_level1   → 2
sys.float.padding_level2   → 4
sys.float.padding_level3   → 6
sys.float.padding_level4   → 8
sys.float.padding_level6   → 12
sys.float.padding_level8   → 16     ← 最常用
sys.float.padding_level10  → 20
sys.float.padding_level12  → 24
sys.float.padding_level16  → 32
```

（具体数值以 SDK 为准，规律是 level 数字 × 2 = vp 值。）

## 4.3 Column 与 Row

### 主轴与交叉轴

```
Column（竖着排）              Row（横着排）
┌─────────────┐              ┌─────────────────┐
│      A      │ ↑            │  A    B    C    │ → 主轴（水平）
│      B      │ │主轴（竖直）   │                 │
│      C      │ ↓            └─────────────────┘
└─────────────┘                      ↕ 交叉轴（竖直）
   ←──────→
   交叉轴（水平）
```

### 对齐属性对照表

| | `Column` | `Row` |
|---|---|---|
| **主轴方向** | 竖直 ↕ | 水平 ↔ |
| **主轴对齐属性** | `.justifyContent(FlexAlign.X)` | `.justifyContent(FlexAlign.X)` |
| **交叉轴方向** | 水平 ↔ | 竖直 ↕ |
| **交叉轴对齐属性** | `.alignItems(HorizontalAlign.X)` | `.alignItems(VerticalAlign.X)` |

**`FlexAlign` 的 6 个值**：

```
Start        │A B C          │  贴主轴起点
Center       │   A B C       │  居中
End          │          A B C│  贴主轴终点
SpaceBetween │A     B      C │  两端贴边，中间均分
SpaceAround  │ A    B    C   │  每个元素两侧等距（首尾是中间的一半）
SpaceEvenly  │  A   B   C    │  所有间隔完全相等
```

**`HorizontalAlign`**：`Start` / `Center` / `End`
**`VerticalAlign`**：`Top` / `Center` / `Bottom`

### 完整居中的写法

```typescript
// Column 里让内容水平垂直都居中
Column() {
  Text('居中')
}
.width('100%')
.height('100%')
.justifyContent(FlexAlign.Center)      // 竖直居中
.alignItems(HorizontalAlign.Center)    // 水平居中
```

**本项目的真实例子**（`pages/MainPage.ets` 的「适配中」占位页）：

```typescript
@Builder
private roleWipPanel() {
  Column({ space: 16 }) {
    SymbolGlyph($r('sys.symbol.hammer_fill')).fontSize(56).fontColor([$r('sys.color.icon_tertiary')])
    Text(`${this.globalInfoModel.role}端`).fontSize($r('sys.float.Title_M')).fontWeight(FontWeight.Medium)
    Text('适配中').fontSize($r('sys.float.Body_L')).fontColor($r('sys.color.font_secondary'))
    Text('该角色页面正在开发中，敬请期待').fontSize($r('sys.float.Body_M'))
  }
  .width('100%')
  .height('100%')
  .justifyContent(FlexAlign.Center)         // 竖直居中
  .alignItems(HorizontalAlign.Center)       // 水平居中
  .padding({ top: this.globalInfoModel.statusBarHeight })
  .expandSafeArea([SafeAreaType.SYSTEM], [SafeAreaEdge.TOP, SafeAreaEdge.BOTTOM])
  .backgroundColor($r('sys.color.background_secondary'))
}
```

### `space` 参数：子元素间距

```typescript
Column({ space: 12 }) {     // 每两个子元素之间 12vp
  Text('a')
  Text('b')
  Text('c')
}
```

比给每个元素加 `margin` 更干净（`margin` 会在首尾也留白，`space` 不会）。

### `layoutWeight`：按权重分配剩余空间

```typescript
Row() {
  Text('固定').width(100)
  Text('弹性').layoutWeight(1)       // 吃掉剩下的全部
}
.width('100%')
```

```typescript
Row() {
  Text('A').layoutWeight(1)     // 占 1/3
  Text('B').layoutWeight(2)     // 占 2/3
}
```

**`layoutWeight` vs `Blank()`**：

- `layoutWeight(1)` 加在**有内容的组件**上 → 那个组件被拉伸
- `Blank()` 是**空白占位** → 把兄弟推开

**本项目的两种用法**：

```typescript
// ① layoutWeight 让文字区域自适应（TabPageView.ets）
Row({ space: 12 }) {
  Column({ space: 4 }) {
    Text(elderItem.item.name)
    Text(`${age}岁 · ${room} · ${bed}`)
  }
  .alignItems(HorizontalAlign.Start)
  .layoutWeight(1)                      // ← 左边文字吃掉剩余宽度

  Text(this.statusText(level))           // ← 右边标签保持自身宽度
}
```

```typescript
// ② Blank 做上下弹性留白（LoginPage.ets）
Column() {
  Blank().layoutWeight(1)     // 上弹簧
  Column() { this.brandHeader() }
  Column({ space: 14 }) { /* 表单 */ }
  Blank().layoutWeight(1)     // 下弹簧
}
```

### 一个高级技巧：`layoutWeight` 的动态切换

`pages/MainPage.ets` 的侧边栏折叠：

```typescript
Row({ space: 10 }) {
  SymbolGlyph($r('sys.symbol.house_fill')).fontSize(28)
  if (!this.isSidebarCollapsed) {
    Column({ space: 2 }) { Text('康小伴'); Text('移动智慧养老') }
  }
}
.layoutWeight(this.isSidebarCollapsed ? 0 : 1)     // ← 折叠时不占权重
.justifyContent(this.isSidebarCollapsed ? FlexAlign.Center : FlexAlign.Start)
.width(this.isSidebarCollapsed ? '100%' : undefined)
```

折叠时：不吃权重 + 内容居中 + 宽度 100% → 图标居中
展开时：吃满剩余空间 + 内容左对齐 → 图标+文字靠左

## 4.4 Stack：层叠布局

```typescript
Stack({ alignContent: Alignment.Center }) {
  // 后写的盖在先写的上面
  Image($r('app.media.bg'))       // 最底
  Text('中间层')
  Button('最上层')
}
```

**`Alignment` 的 9 个值**：

```
TopStart      Top        TopEnd
Start         Center     End
BottomStart   Bottom     BottomEnd
```

### 三大用途

**① 浮层 / 蒙层**（本项目 `MainPage.ets`）：

```typescript
Stack() {
  HdsNavigation(this.pathStack) { /* 主内容 */ }     // 底层
  if (this.isAiChatShow) { this.aiChatCover() }      // 浮层
}
```

**② 角标定位**（本项目 `MainPage.ets`）：

```typescript
Stack({ alignContent: Alignment.TopEnd }) {
  Row() { SymbolGlyph(symbol) }.width(40).height(40)
  if (hasBadge) {
    Column().width(8).height(8).borderRadius(4)
      .backgroundColor($r('app.color.status_danger'))
      .margin({ top: 6, right: 6 })
  }
}
.width(40).height(40)
```

**③ 滑动指示器（胶囊背景）**（本项目 `WideSlidingCapsule.ets`）：

```typescript
Stack({ alignContent: Alignment.Start }) {
  // 底层：会滑动的白色胶囊
  Row()
    .width(this.effectiveItemWidth())
    .height(38).borderRadius(19)
    .backgroundColor($r('sys.color.comp_background_primary'))
    .translate({ x: this.selectionOffset() })     // ← 用 translate 滑动
    .animation({ duration: 260, curve: Curve.Friction })

  // 上层：文字按钮们
  Row({ space: 4 }) {
    ForEach(this.items, (item) => { this.capsuleItem(item) })
  }
}
```

该模式的要点是：不移动选中项本身，而是让背景块滑动到目标位置。

### `zIndex`：手动控制层级

```typescript
Text('A').zIndex(2)     // 数字越大越靠上
Text('B').zIndex(1)
```

### `position` vs `offset`

```typescript
.position({ x: 10, y: 20 })   // 绝对定位：相对父容器左上角，脱离文档流
.offset({ x: 10, y: 20 })     // 相对偏移：相对自己原本的位置，不脱离文档流（仍占原位）
```

## 4.5 Flex 的适用场景

**先说结论：能用 `Row`/`Column` 就别用 `Flex`。**

原因：`Flex` 会**额外测量一次**子组件（因为要计算伸缩），性能开销更大。
`@performance/recommended` linter 规则会警告这一点。

### 唯一必须用 Flex 的场景：自动换行

```typescript
Flex({ wrap: FlexWrap.Wrap, justifyContent: FlexAlign.Start }) {
  ForEach(this.tags, (tag: string) => {
    Text(tag)
      .padding({ left: 12, right: 12, top: 6, bottom: 6 })
      .backgroundColor($r('sys.color.comp_background_secondary'))
      .borderRadius(14)
      .margin({ right: 8, bottom: 8 })
  }, (tag: string) => tag)
}
.width('100%')
```

标签云、筛选条件这种「一行放不下自动换行」的场景，只能用 `Flex`（或 `GridRow`）。

### Flex 参数

```typescript
Flex({
  direction: FlexDirection.Row,     // Row / RowReverse / Column / ColumnReverse
  wrap: FlexWrap.Wrap,              // NoWrap(默认) / Wrap / WrapReverse
  justifyContent: FlexAlign.Start,  // 主轴
  alignItems: ItemAlign.Center,     // 交叉轴（注意类型是 ItemAlign！）
  alignContent: FlexAlign.Start     // 多行时，行与行之间的对齐
})
```

**`ItemAlign`**：`Auto` / `Start` / `Center` / `End` / `Baseline` / `Stretch`

### 子组件的 Flex 属性

```typescript
Text('a')
  .flexGrow(1)       // 有剩余空间时，按比例增长
  .flexShrink(1)     // 空间不够时，按比例缩小
  .flexBasis(100)    // 基础尺寸
  .alignSelf(ItemAlign.End)   // 单独覆盖交叉轴对齐
```

## 4.6 Grid：数据网格

```typescript
Grid() {
  ForEach(this.items, (item: Item) => {
    GridItem() {
      Column() { Text(item.name) }
    }
  }, (item: Item) => item.id)
}
.columnsTemplate('1fr 1fr 1fr')     // 三等分
.rowsTemplate('1fr 1fr')            // 可省略（省略则行高自适应且可滚动）
.columnsGap(12)
.rowsGap(12)
.width('100%')
```

### `columnsTemplate` 语法详解

```
'1fr 1fr'                 → 两等分
'1fr 2fr'                 → 1:2 比例
'100 1fr 100'             → 左右固定 100vp，中间弹性
'repeat(3, 1fr)'          → 重复三次 1fr（等价于 '1fr 1fr 1fr'）
'repeat(auto-fit, 100)'   → 自动放尽可能多的 100vp 列
```

### `GridItem` 跨行跨列

```typescript
GridItem() { Text('大格子') }
  .columnStart(0).columnEnd(1)     // 横跨第 0~1 列
  .rowStart(0).rowEnd(1)           // 纵跨第 0~1 行
```

### 本项目的替代做法：手写 Row + layoutWeight

本项目的 `overviewGrid()` 没用 `Grid`，而是用 `Row` + `layoutWeight` 手拼 2 列：

```typescript
Row({ space: 12 }) {
  this.overviewCard(...).layoutWeight(1)
  this.overviewCard(...).layoutWeight(1)
}
```

**为什么**：固定 2 列时手拼更简单、性能更好，`Grid` 适合数量不定的数据。

## 4.7 GridRow / GridCol：栅格系统（响应式核心）

这是**一多适配**的标准武器（第 09 章详讲）。

```typescript
GridRow({
  columns: { xs: 4, sm: 4, md: 8, lg: 12 },     // 不同断点下总共分几列
  gutter: { x: 12, y: 12 },                      // 列间距 / 行间距
  breakpoints: {                                  // 自定义断点（可选）
    value: ['320vp', '600vp', '840vp'],
    reference: BreakpointsReference.WindowSize
  }
}) {
  ForEach(this.cards, (card: Card) => {
    GridCol({
      span: { xs: 4, sm: 2, md: 2, lg: 3 },      // 这个格子占几列
      offset: { xs: 0, sm: 0 }                    // 左边空几列
    }) {
      // 卡片内容
    }
  }, (card: Card) => card.id)
}
.onBreakpointChange((bp: string) => {
  console.log(bp);   // 'xs' | 'sm' | 'md' | 'lg' | 'xl'
})
```

**理解方式**：

- 屏幕被分成 `columns` 份
- 每个 `GridCol` 说自己要占几份（`span`）
- 一行占满 `columns` 份后自动换行

**例子**：`columns: 12`，三个 `GridCol` 的 `span` 都是 4 → 一行放 3 个（4+4+4=12）

**默认断点**：

| 断点 | 窗口宽度 | 典型设备 |
|---|---|---|
| `xs` | [0, 320vp) | 超小（手表） |
| `sm` | [320vp, 600vp) | 手机 |
| `md` | [600vp, 840vp) | 折叠屏展开 / 小平板 |
| `lg` | [840vp, +∞) | 平板 / PC |

## 4.8 RelativeContainer：相对定位

用来避免多层嵌套。

```typescript
RelativeContainer() {
  Text('标题')
    .id('title')                              // ★ 必须设置 id，供其它组件锚定
    .alignRules({
      top: { anchor: '__container__', align: VerticalAlign.Top },
      left: { anchor: '__container__', align: HorizontalAlign.Start }
    })

  Text('副标题')
    .alignRules({
      top: { anchor: 'title', align: VerticalAlign.Bottom },      // 在 title 下面
      left: { anchor: 'title', align: HorizontalAlign.Start }     // 和 title 左对齐
    })

  Button('右下角')
    .alignRules({
      bottom: { anchor: '__container__', align: VerticalAlign.Bottom },
      right: { anchor: '__container__', align: HorizontalAlign.End }
    })
}
.width('100%').height(200)
```

- `'__container__'` 是特殊锚点，表示容器本身
- 锚定别的组件时用它的 `id`

**什么时候用**：布局关系复杂、层级会嵌套 4 层以上时，用它能压平层级、提升性能。

## 4.9 安全区（SafeArea）：沉浸式的核心

### 什么是安全区

手机屏幕不是所有区域都能放内容：

```
┌─────────────────────┐
│ ⬛ 状态栏（时间/电量） │ ← 不安全区（内容会被遮）
├─────────────────────┤
│                     │
│    安全区            │ ← 可以放内容
│    你的内容放这里     │
│                     │
├─────────────────────┤
│ ▬▬▬ 导航条           │ ← 不安全区
└─────────────────────┘
```

### 两种处理策略

**策略 A（默认）：系统自动避让**

系统自动给你的页面加上下 padding，你的内容永远在安全区内。简单，但顶部会有一条空白，不好看。

**策略 B（沉浸式）：内容延伸到全屏，自己控制留白**

内容铺满全屏（背景色/图片顶到状态栏后面），但文字/按钮自己加 padding 避开。视觉更好，但要手动算。

**本项目用的是策略 B（全沉浸式）。**

### 怎么开启沉浸式

`util/WindowUtil.ets`：

```typescript
public static setImmersiveMode(enable: boolean): void {
  // ① 让窗口布局全屏（内容延伸到状态栏和导航条下面）
  WindowUtil.windowClass.setWindowLayoutFullScreen(enable);

  // ② 让系统栏透明（这样能看到你的背景）
  WindowUtil.windowClass.setWindowSystemBarProperties({
    statusBarColor: '#00000000',        // 全透明
    navigationBarColor: '#00000000'
  });
}
```

### 怎么拿到安全区高度

```typescript
// util/WindowUtil.ets
const systemAvoidArea: window.AvoidArea = windowClass.getWindowAvoidArea(window.AvoidAreaType.TYPE_SYSTEM);
globalInfoModel.statusBarHeight = uiContext.px2vp(systemAvoidArea?.topRect?.height ?? 0);
//                                        ↑ 必须 px2vp！

const bottomArea: window.AvoidArea = windowClass.getWindowAvoidArea(window.AvoidAreaType.TYPE_NAVIGATION_INDICATOR);
globalInfoModel.naviIndicatorHeight = uiContext.px2vp(bottomArea?.bottomRect?.height ?? 0);
```

**四种 AvoidAreaType**：

| 类型 | 是什么 |
|---|---|
| `TYPE_SYSTEM` | 状态栏区域 |
| `TYPE_NAVIGATION_INDICATOR` | 底部导航条 |
| `TYPE_KEYBOARD` | 软键盘 |
| `TYPE_CUTOUT` | 刘海/挖孔 |

### 监听安全区变化

```typescript
windowClass.on('avoidAreaChange', (avoidAreaOption) => {
  if (avoidAreaOption.type === window.AvoidAreaType.TYPE_SYSTEM ||
      avoidAreaOption.type === window.AvoidAreaType.TYPE_NAVIGATION_INDICATOR) {
    WindowUtil.setAvoidArea(avoidAreaOption.type, avoidAreaOption.area);
  } else if (avoidAreaOption.type === window.AvoidAreaType.TYPE_KEYBOARD) {
    globalInfoModel.keyboardHeight = uiContext.px2vp(avoidAreaOption.area?.bottomRect?.height ?? 0);
  }
});
```

### 页面里怎么用

```typescript
build() {
  Column() {
    // 内容
  }
  .width('100%')
  .height('100%')
  .padding({
    top: this.globalInfoModel.statusBarHeight,          // ← 顶部避开状态栏
    bottom: this.globalInfoModel.naviIndicatorHeight    // ← 底部避开导航条
  })
  .expandSafeArea([SafeAreaType.SYSTEM], [SafeAreaEdge.TOP, SafeAreaEdge.BOTTOM])
}
```

### `expandSafeArea` vs `ignoreLayoutSafeArea`

| 属性 | 作用 | 用在哪 |
|---|---|---|
| `.expandSafeArea(types, edges)` | 让**这个组件的绘制**扩展到安全区外（背景延伸过去） | 普通组件 |
| `.ignoreLayoutSafeArea(types, edges)` | 让**布局计算**忽略安全区 | `Navigation` / `NavDestination` |

```typescript
// 普通组件
.expandSafeArea([SafeAreaType.SYSTEM], [SafeAreaEdge.TOP, SafeAreaEdge.BOTTOM])

// Navigation 类组件
.ignoreLayoutSafeArea([LayoutSafeAreaType.SYSTEM], [LayoutSafeAreaEdge.TOP, LayoutSafeAreaEdge.BOTTOM])
```

**`SafeAreaType`**：`SYSTEM`（状态栏+导航条）/ `CUTOUT`（刘海）/ `KEYBOARD`（键盘）
**`SafeAreaEdge`**：`TOP` / `BOTTOM` / `START` / `END`

### ⚠️ 关键警告：不要用 `expandSafeArea(KEYBOARD)`

本项目的规范明确写了这一条：

> **不要使用 `expandSafeArea(KEYBOARD)`（会和手动键盘避让产生双重避让冲突）**

如果你既用了 `expandSafeArea([SafeAreaType.KEYBOARD])`，又用 `@Monitor` 手动监听 `keyboardHeight` 加 padding，
两套机制会叠加，页面会被顶起两倍高度。**只能选一种。**

本项目选的是手动方案（见下一节）。

## 4.10 键盘适配

### 完整模式

```typescript
@ComponentV2
struct MyPage {
  @Local globalInfoModel: GlobalInfoModel =
    AppStorageV2.connect(GlobalInfoModel, StorageKey.GLOBAL_INFO) ?? new GlobalInfoModel();

  @Local keyboardOffset: number = 0;         // ① 本地保存一份偏移量

  @Monitor('globalInfoModel.keyboardHeight') // ② 监听全局键盘高度
  onKeyboardHeightChange(): void {
    this.getUIContext().animateTo({          // ③ 用动画平滑过渡
      duration: 400,
      curve: Curve.EaseOut
    }, () => {
      this.keyboardOffset = this.globalInfoModel.keyboardHeight;
    })
  }

  build() {
    Column() {
      // 内容
    }
    .padding({ bottom: this.keyboardOffset })   // ④ 底部加 padding 把内容顶上去
  }
}
```

（这段就是 `pages/LoginPage.ets` 的真实代码。）

### 为什么要用本地变量 + 动画

如果直接 `.padding({ bottom: this.globalInfoModel.keyboardHeight })`：
键盘弹出是瞬间的，页面会「跳」一下，很生硬。

用 `@Monitor` + `animateTo` 让它平滑过渡，体验好很多。

### 更精细的控制：`KeyboardAvoidMode`

```typescript
this.getUIContext().setKeyboardAvoidMode(KeyboardAvoidMode.RESIZE);
// OFFSET（默认）：整个页面上移
// RESIZE：页面高度缩小（适合聊天页，让列表滚动区变小而不是整体上移）
// NONE：不避让
```

**本项目 AI 聊天页的做法**（`pages/AiChatPage.ets`）：

```typescript
private previousKeyboardAvoidMode: KeyboardAvoidMode = KeyboardAvoidMode.OFFSET;

aboutToAppear(): void {
  this.previousKeyboardAvoidMode = this.getUIContext().getKeyboardAvoidMode();  // 记住原来的
  // ...
}

private restoreSession(session: ChatSession): void {
  // ...
  this.getUIContext().setKeyboardAvoidMode(KeyboardAvoidMode.RESIZE);   // 聊天页用 RESIZE
}

aboutToDisappear(): void {
  this.getUIContext().setKeyboardAvoidMode(this.previousKeyboardAvoidMode);  // 走的时候还原
}
```

**注意这个「记住-修改-还原」模式**，改全局设置时都应该这么做。

## 4.11 大屏内容限宽

在平板/PC 上，如果内容宽度也跟着 100%，一行文字会横跨 1920px，非常难读。

**标准解法：外层撑满 + 内层限宽 + 居中**

```typescript
Scroll() {
  Row() {                                       // ① 外层 Row 负责水平居中
    Column({ space: 16 }) {                     // ② 内层 Column 是真正的内容
      // 内容
    }
    .width('100%')
    .constraintSize({ maxWidth: 960 })          // ③ 最大宽度限制
    .padding({ left: this.pagePadding(), right: this.pagePadding() })
  }
  .width('100%')
  .justifyContent(FlexAlign.Center)             // ④ 居中
}
```

**本项目多处使用**：`pages/HealthExpandPage.ets`（maxWidth 960）、`component/TabPageView.ets`（`expandMaxWidth()`）。

`constraintSize` 的四个参数：

```typescript
.constraintSize({
  minWidth: 0,
  maxWidth: 960,
  minHeight: 0,
  maxHeight: 500
})
```

## 4.12 布局问题排查

### 症状 1：组件高度是 0 / 看不见

**可能原因**：

| 原因 | 检查 |
|---|---|
| 容器没内容 | 条件渲染是不是没进去？`ForEach` 数据是不是空数组？ |
| 父容器高度是 0 | 一层层往上查 `.height()` |
| `Scroll` 的子组件没高度 | `Scroll` 里的内容需要能确定高度 |
| 用了 `layoutWeight` 但父容器没高度 | `layoutWeight` 需要父有确定尺寸 |
| `visibility` 设成了 `None` | `Hidden` 占位，`None` 不占位 |

**调试技巧**：给可疑组件加个显眼的背景色

```typescript
.backgroundColor(Color.Red)     // 看它到底在哪、有多大
.border({ width: 1, color: Color.Blue })
```

### 症状 2：内容被挤出去 / 显示不全

**原因**：`Row` 里的元素总宽度超过了容器。

**解法**：

```typescript
Row() {
  Text('很长的标题')
    .layoutWeight(1)                                   // ① 让它可压缩
    .maxLines(1)                                       // ② 限制行数
    .textOverflow({ overflow: TextOverflow.Ellipsis }) // ③ 超出显示省略号

  Text('固定标签')                                      // ④ 这个保持原宽
}
```

### 症状 3：居中不生效

**检查清单**：

1. 容器有没有明确的 `width`/`height`？（没尺寸就没法居中）
2. 用对枚举了吗？`Column` 的交叉轴是 `HorizontalAlign`，不是 `VerticalAlign`
3. 是不是想居中的是 `Stack` 的子元素？那要用 `alignContent` 或子元素的 `.align()`

### 症状 4：padding 和 margin 分不清

```
┌─────────────────────────┐
│        margin           │  ← 外边距（组件和兄弟/父的距离）
│  ┌───────────────────┐  │
│  │      border       │  │  ← 边框
│  │  ┌─────────────┐  │  │
│  │  │   padding   │  │  │  ← 内边距（边框和内容的距离）
│  │  │  ┌───────┐  │  │  │
│  │  │  │ 内容  │  │  │  │
│  │  │  └───────┘  │  │  │
│  │  └─────────────┘  │  │
│  └───────────────────┘  │
└─────────────────────────┘
```

**背景色会覆盖 padding 区域，但不覆盖 margin 区域。**

### 症状 5：滚动不了 / 滚动冲突

| 症状 | 原因 | 解法 |
|---|---|---|
| 完全不能滚 | 内容高度 < 容器高度 | 正常现象，内容够多才能滚 |
| 内层能滚外层不能 | 嵌套滚动策略 | 设 `.nestedScroll({ scrollForward: NestedScrollMode.PARENT_FIRST })` |
| 滚动很卡 | 数据量大用了 `ForEach` | 换 `LazyForEach` 或 `Repeat` + `virtualScroll` |
| 两个滚动条 | `Scroll` 里放了 `List` 且两个都能滚 | 内层 `List` 给固定高度 + `EdgeEffect.None` |

**本项目的解法**（`component/HealthListCard.ets`）：

```typescript
List({ space: 0 }) { /* ... */ }
  .nestedScroll({
    scrollForward: NestedScrollMode.PARENT_FIRST,
    scrollBackward: NestedScrollMode.PARENT_FIRST
  })
  .scrollBar(BarState.Off)
  .edgeEffect(EdgeEffect.None)                     // ← 内层不回弹
  .height(this.cardData.rows.length * 68)          // ← 固定高度，交给外层滚
```

### 症状 6：状态栏遮住了内容

**原因**：开了沉浸式但没加 padding。

**解法**：

```typescript
.padding({ top: this.globalInfoModel.statusBarHeight })
```

### 症状 7：底部内容被 TabBar 遮住

**解法**：给内容底部留出 TabBar 高度 + 导航条高度：

```typescript
private bottomPadding(): number {
  return this.isWideLayout() ? 36 : 124;    // 手机端 124 = TabBar 高度 + 安全距离
}
```

（这是本项目 `TabPageView.ets` 的真实做法。）

### 症状 8：`.animation()` 不生效

**原因**：`.animation()` 只对**写在它前面**的属性生效。

```typescript
// ❌
.animation({ duration: 300 })
.opacity(this.o)

// ✅
.opacity(this.o)
.animation({ duration: 300 })
```

## 4.13 布局性能规则

1. **减少嵌套层级**。超过 5 层考虑用 `RelativeContainer` 压平。
2. **能用 `Row`/`Column` 不用 `Flex`**（Flex 多测量一次）。
3. **不要在 `build()` 里做重计算**。
4. **长列表用 `LazyForEach`**，配 `cachedCount`。
5. **`ForEach`/`Repeat` 必须给稳定的唯一 key**。
6. **固定尺寸优于百分比**（百分比需要父先算完）。
7. **`.clip(true)` 有开销**，不需要裁剪就别开。
8. **模糊效果（`backgroundBlurStyle`、`blur`）很贵**，不要大面积用、不要在滚动列表里逐项用。
