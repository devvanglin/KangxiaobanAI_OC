## 5.1 一分钟总览

```
┌──────────────────────────────────────────────────────────────┐
│  组件自己的状态                                                 │
│    @Local          我的私有状态，改了就重绘                       │
│    @Computed       派生值，依赖变了才重算（有缓存）                 │
│    @Monitor('x')   x 变了就跑一次回调                            │
├──────────────────────────────────────────────────────────────┤
│  父子之间                                                      │
│    @Param          父传子（子只读）                              │
│    @Param @Require 父必须传                                     │
│    @Param @Once    只接收初值，之后父改了不同步（子可改）            │
│    @Event          子回调父                                     │
├──────────────────────────────────────────────────────────────┤
│  跨层级（爷爷传孙子，中间不用手动接力）                             │
│    @Provider()     我提供                                       │
│    @Consumer()     我消费（找最近的祖先 Provider）                 │
├──────────────────────────────────────────────────────────────┤
│  类对象的深度观察                                                │
│    @ObservedV2     标记这个 class 可被观察                       │
│    @Trace          标记类里的哪个字段变了要通知 UI                 │
├──────────────────────────────────────────────────────────────┤
│  全局 / 持久化                                                  │
│    AppStorageV2    全应用共享（内存，重启丢失）                     │
│    PersistenceV2   全应用共享 + 落盘（重启还在）                    │
└──────────────────────────────────────────────────────────────┘
```

## 5.2 V2 的设计动因

### V1 的三个致命问题

**问题 1：只能观察「第一层」**

```typescript
// V1 写法
@Observed
class Person {
  name: string = '';
  address: Address = new Address();
}

@Component
struct Demo {
  @State person: Person = new Person();

  build() {
    Column() {
      Text(this.person.name)                  // ✅ 改 name 会刷新
      Text(this.person.address.city)          // ❌ 改 address.city 不会刷新！
    }
  }
}
```

V1 只能观察到 `person.xxx` 这一层。再深一层（`person.address.city`）就失灵了。
要解决只能给每一层都套 `@Observed` + `@ObjectLink`，代码爆炸。

**问题 2：`@State` 有隐式深拷贝，性能差且行为诡异**

**问题 3：`@Prop` 是单向拷贝、`@Link` 是双向引用，两者行为差别大，容易用错**

### V2 怎么解决

**V2 把「观察能力」从组件转移到了类本身**：

```typescript
@ObservedV2                        // ← 这个 class 支持观察
class Person {
  @Trace name: string = '';        // ← 这个字段变了要通知
  @Trace address: Address = new Address();
}

@ObservedV2
class Address {
  @Trace city: string = '';        // ← 深层字段也能被观察 ✅
}
```

**只要每一层都是 `@ObservedV2` + `@Trace`，无论多深都能观察到。**

## 5.3 `@ComponentV2`

```typescript
@ComponentV2                       // ← 没有这个，下面所有 V2 装饰器都不能用
struct MyComponent {
  build() { }
}
```

**SDK 定义**（`common.d.ts:398`）：

```typescript
declare const ComponentV2: ClassDecorator & ((options: ComponentOptions) => ClassDecorator);
// @since 12（基础），@since 23（支持 @form 卡片）
```

**规则**：

| 规则 | 说明 |
|---|---|
| 一个 struct 只能用 `@Component` 或 `@ComponentV2` 之一 | 不能同时写 |
| `@ComponentV2` 组件里**不能**用 V1 装饰器 | `@State` 等会直接报错 |
| `@Component`（V1）组件里**不能**用 V2 装饰器 | 反之亦然 |
| V1 和 V2 组件**可以互相嵌套使用** | 但状态不能直接互通 |
| `@Entry` 可以配合任一版本 | `@Entry @ComponentV2 struct MyPage` |

### V1 与 V2 的混用禁令

V2 的实现机制和 V1 完全不同，**以下三种混用是禁止的**：

1. **把 V2 装饰器修饰的变量传给 V1 装饰器修饰的变量**（反之亦然）
2. **把 `@Observed`/`@Track` 和 `@ObservedV2`/`@Trace` 混用**（同一个类里不能既有 V1 又有 V2）
3. **在 `@ComponentV2` 里使用任何 V1 装饰器**：
   `@State` `@Prop` `@Link` `@ObjectLink` `@Provide` `@Consume`
   `@StorageLink` `@StorageProp` `@LocalStorageLink` `@LocalStorageProp` `@Watch`

**这也是为什么本项目全面禁用 V1**：一旦局部混用，很快就会遇到「数据传不过去」的死结。
统一用 V2 反而最省事。

**本项目的全部组件都是 `@ComponentV2`**，包括 `@Entry` 页面：

```typescript
// pages/MainPage.ets
@Entry
@ComponentV2
struct MainPage { }

// component/TabPageView.ets
@ComponentV2
export struct TabPageView { }
```

## 5.4 `@Local`：组件的私有状态

### 定义

```typescript
declare const Local: PropertyDecorator;   // @since 12
```

### 基本用法

```typescript
@ComponentV2
struct Counter {
  @Local count: number = 0;         // ← 必须有初值

  build() {
    Column() {
      Text(`${this.count}`)
      Button('+').onClick(() => { this.count++; })     // 改了 → Text 自动更新
    }
  }
}
```

### 五条规则

| # | 规则 | 说明 |
|---|---|---|
| 1 | **必须在声明时给初值** | `@Local count: number;` ❌ 会报错 |
| 2 | **不能从外部初始化** | 父组件不能 `Counter({ count: 5 })` |
| 3 | **可以是任何类型** | number/string/boolean/对象/数组/class 实例 |
| 4 | **观察深度只有一层** | `this.obj.a = 1` 不会刷新（除非 obj 是 `@ObservedV2`） |
| 5 | 组件销毁后状态丢失 | 需要保留就用 `AppStorageV2` |

### 关键理解：`@Local` 的观察深度

```typescript
@ComponentV2
struct Demo {
  @Local num: number = 0;
  @Local arr: string[] = [];
  @Local obj: MyObj = new MyObj();       // MyObj 是普通 class（没有 @ObservedV2）

  test(): void {
    this.num = 1;                  // ✅ 会刷新（整体赋值）
    this.arr = ['a'];              // ✅ 会刷新（整体赋值）
    this.arr.push('b');            // ✅ 会刷新（V2 对数组方法做了代理）
    this.obj = new MyObj();        // ✅ 会刷新（整体赋值）
    this.obj.name = 'x';           // ❌ 不会刷新！（改的是对象内部）
  }
}
```

**记忆口诀**：

> **`@Local` 只盯着「这个变量本身指向谁」，不盯「它指向的东西内部变了没」。**
> （数组的 push/pop/splice 等方法是特例，V2 做了代理，会触发更新。）

### 三种解法（对象内部字段要刷新时）

```typescript
// 解法 A：整体替换（最简单，小对象推荐）
this.obj = { name: 'x', age: this.obj.age };

// 解法 B：类加 @ObservedV2 + @Trace（推荐，本项目做法）
@ObservedV2
class MyObj {
  @Trace name: string = '';
}
// 之后 this.obj.name = 'x' 就能刷新了

// 解法 C：数组整体替换
this.list = [...this.list];           // 强制触发
```

### 本项目的真实例子

`component/TabPageView.ets` 里有 **20 多个 `@Local`**：

```typescript
@Local isProfileSheetOpen: boolean = false;
@Local selectedTaskId: string = '';
@Local isTaskSheetOpen: boolean = false;
@Local residentSearch: string = '';
@Local residentFilter: 'all' | 'warning' | 'danger' = 'all';
@Local taskFilter: 'all' | 'ai' | 'elder' | 'plan' = 'all';
@Local currentTime: Date = new Date();
@Local isClockedIn: boolean = false;
@Local clockInTime: Date | null = null;
@Local isHealthExpandShow: boolean = false;
@Local isResidentDetailShow: boolean = false;
@Local selectedResidentId: string = '';
@Local activeResidentGeometryId: string = '';
// ...
```

**注意 `private timerId: number = -1;` 没有 `@Local`** —— 因为定时器 ID 不影响 UI，不需要触发重绘。

> **原则：只给「会影响界面显示」的变量加 `@Local`。** 不影响 UI 的用普通字段，省性能。

## 5.5 `@Param`：父传子（只读）

### 定义

```typescript
declare const Param: PropertyDecorator;      // @since 12
declare const Require: PropertyDecorator;    // @since 11
declare const Once: PropertyDecorator;       // @since 12
```

### 基本用法

```typescript
// 子组件
@ComponentV2
export struct HealthListCard {
  @Param @Require cardData: HealthListCardData;      // 必填
  @Param @Require widthBreakpoint: WidthBreakpoint;  // 必填
  @Param isExpanded: boolean = false;                 // 可选，有默认值

  build() {
    Text(this.cardData.title)
  }
}

// 父组件使用
HealthListCard({
  cardData: this.healthCardData(),
  widthBreakpoint: this.globalInfoModel.widthBreakpoint,
  isExpanded: this.isHealthExpandShow
})
```

### 四条规则

| # | 规则 |
|---|---|
| 1 | **子组件不能修改 `@Param`**（`this.myParam = x` 编译报错） |
| 2 | **父组件的值变了，子组件自动同步** |
| 3 | 加 `@Require` = 父组件**必须**传，不传编译报错 |
| 4 | 不加 `@Require` 就**必须有默认值** |

### `@Param @Once`：只接收一次

```typescript
@ComponentV2
struct Child {
  @Param @Once initialValue: string = '';    // 只在创建时接收父的值

  private change(): void {
    this.initialValue = 'changed';           // ✅ 加了 @Once 就可以改了
  }
}
```

**用途**：父组件传一个「初始值」，之后子组件自己管理。
比如一个编辑表单，初始内容来自父，编辑过程中子组件自己维护。

**对照表**：

| 写法 | 父改了会同步给子吗 | 子能改吗 |
|---|---|---|
| `@Param x` | ✅ 会 | ❌ 不能 |
| `@Param @Once x` | ❌ 不会 | ✅ 能 |
| `@Local x` | 父根本传不进来 | ✅ 能 |

**`@Once` 的 5 条硬规则**：

1. **必须和 `@Param` 一起用**，不能单独使用
2. **不能和 `@Local` 一起用**（语义冲突）
3. **只能在 `@ComponentV2` 组件里用**
4. **书写顺序不影响功能**：`@Param @Once x` 和 `@Once @Param x` 等价
5. **不影响 `@Param` 的观测能力**，只拦截「数据源变化时的同步」这一件事

**直接修改没有 `@Once` 的 `@Param` 会运行时报错**，不只是编译警告。

### 本项目的真实例子

`component/TabPageView.ets`：

```typescript

@Param @Require pageKey: PageKeyEnum;
@Param @Require config: TabPageConfig;
```

`component/wide/WideSlidingCapsule.ets`：

```typescript

@Param @Require itemWidth: number;
@Param fillWidth: boolean = false;              // 可选
```

`pages/AiChatPage.ets`：


## 5.6 `@Event`：子回调父

### 定义

```typescript
declare const Event: PropertyDecorator;   // @since 12
```

### 基本用法

```typescript
// 子组件
@ComponentV2
export struct WideSlidingCapsule {
  @Param @Require items: WideSlidingCapsuleItem[];
  @Event onSelect: (index: number) => void = (_index: number) => {};
  //                                          ↑ 必须有默认值（通常是空函数）

  build() {
    Row().onClick(() => {
      this.onSelect(item.index);         // ← 调用它，通知父组件
    })
  }
}

// 父组件
WideSlidingCapsule({
  items: this.items,
  selectedIndex: this.selected,
  itemWidth: 100,
  onSelect: (index: number) => {          // ← 父组件提供实现
    this.selected = index;
  }
})
```

### 必须提供默认空函数的原因

```typescript
@Event onSelect: (index: number) => void = (_index: number) => {};
```

如果父组件没传 `onSelect`，子组件调用 `this.onSelect(...)` 会崩溃。
给一个空函数做默认值，父组件不传也不会出错。

**这是 V2 的强制约定，`@Event` 必须有默认值。**

### 命名约定

统一用 `on` 开头：`onSelect` / `onClose` / `onItemClick` / `onSwitchTab` / `onOpenAiChat`。

### 本项目的真实例子

`component/HealthListCard.ets`：

```typescript
@Event onItemClick: (id: string) => void = () => {};
@Event onCardExpand: () => void = () => {};
```

`component/TabPageView.ets`：

```typescript
@Event onSwitchTab: (index: number) => void = () => {};
@Event onOpenAiChat: () => void = () => {};
```

`pages/MainPage.ets` 提供实现：

```typescript
TabPageView({
  currentTabIndex: 0,
  pageKey: PageKeyEnum.ADAPTIVE_TAB,
  config: this.pageConfigs[0],
  onSwitchTab: (index: number) => { this.switchTab(index); },
  onOpenAiChat: () => { this.openAiChat(); }
})
```

### 一个更大的例子：`WideDoctorWorkspace` 的 5 个回调

```typescript
WideDoctorWorkspace({
  statusBarHeight: this.globalInfoModel.statusBarHeight,
  naviIndicatorHeight: this.globalInfoModel.naviIndicatorHeight,
  compactWidth: BreakpointUtil.isTablet(this.globalInfoModel.widthBreakpoint),
  admissionCompactWidth: this.globalInfoModel.widthBreakpoint !== WidthBreakpoint.WIDTH_XL,
  onOpenAbout: () => { this.pathStack.pushPath({ name: 'AboutPage' }); },
  onOpenGeneral: () => { this.pathStack.pushPath({ name: 'GeneralSettingsPage' }); },
  onLogout: () => { this.handleLogout(); }
})
```

**注意这个设计**：子组件（`WideDoctorWorkspace`）**不直接操作路由栈**，
而是通过 `@Event` 告诉父组件「用户想打开关于页」，由父组件决定怎么做。
这样子组件可以被复用到不同的导航环境里。

## 5.7 `@Monitor`：监听变化

### 定义（SDK 实测）

```typescript
declare const Monitor: MonitorDecorator;
declare type MonitorDecorator = (value: string | MonitorDecoratorOptions, ...args: string[]) => MethodDecorator;

declare interface IMonitor {
  dirty: Array<string>;                                    // 这次变了哪些路径
  value<T>(path?: string): IMonitorValue<T> | undefined;   // 拿某个路径的新旧值
}

declare interface IMonitorValue<T> {
  before: T;      // 变化前
  now: T;         // 变化后
  path: string;   // 路径
}
```

还有一个同步版本：`declare const SyncMonitor: MonitorDecorator;`

### 基本用法

```typescript
@ComponentV2
struct Demo {
  @Local count: number = 0;

  @Monitor('count')
  onCountChange(monitor: IMonitor): void {
    const v = monitor.value<number>('count');
    console.log(`从 ${v?.before} 变成 ${v?.now}`);
  }
}
```

### 监听多个路径

```typescript
@Monitor('a', 'b', 'c')
onAnyChange(monitor: IMonitor): void {
  monitor.dirty.forEach((path: string) => {
    console.log(`${path} 变了`);
  });
}
```

### 监听嵌套路径

```typescript
@Monitor('globalInfoModel.keyboardHeight')
onKeyboardHeightChange(): void {
  // globalInfoModel 是一个 @ObservedV2 类的实例
  // keyboardHeight 是它的 @Trace 字段
  // 这个字段一变，这个方法就跑
}
```

**这是本项目最常用的模式**，出现在 `LoginPage`、`AiChatPage` 等多处。

### 本项目的真实例子

**例 1：键盘高度变化 → 平滑动画**（`pages/LoginPage.ets`）：

```typescript
@Local globalInfoModel: GlobalInfoModel =
  AppStorageV2.connect(GlobalInfoModel, StorageKey.GLOBAL_INFO, () => new GlobalInfoModel()) ?? new GlobalInfoModel();

@Local keyboardOffset: number = 0;

@Monitor('globalInfoModel.keyboardHeight')
onKeyboardHeightChange(): void {
  this.getUIContext().animateTo({
    duration: 400,
    curve: Curve.EaseOut
  }, () => {
    this.keyboardOffset = this.globalInfoModel.keyboardHeight;
  })
}
```

**为什么不直接用 `this.globalInfoModel.keyboardHeight`**：
因为直接用的话，键盘弹出时页面会瞬间跳变。
通过 `@Monitor` 转成本地变量 + `animateTo`，可以加动画。

**例 2：键盘变化 + 滚动到底部**（`pages/AiChatPage.ets`）：

```typescript
@Monitor('globalInfoModel.keyboardHeight')
onKeyboardHeightChange(): void {
  this.keyboardOffset = this.globalInfoModel.keyboardHeight;
  if (this.messages.length > 0) {
    this.scheduleScrollToBottom(300);      // 键盘弹出后，把最新消息滚到可见区
  }
}
```

### `@Monitor` vs V1 的 `@Watch`

| | V1 `@Watch` | V2 `@Monitor` |
|---|---|---|
| 写法 | `@State @Watch('cb') x: number = 0` | `@Monitor('x') cb() {}` |
| 位置 | 装饰在**属性**上 | 装饰在**方法**上 |
| 监听多个 | 每个属性单独写 | `@Monitor('a','b','c')` 一次搞定 |
| 拿旧值 | ❌ 不行 | ✅ `monitor.value().before` |
| 监听嵌套路径 | ❌ 不行 | ✅ `@Monitor('obj.deep.field')` |

**本项目禁用 `@Watch`，只用 `@Monitor`。**

### 注意事项

1. `@Monitor` 回调**不要修改被监听的变量**，会死循环。
2. 回调是**异步**的（在状态变更后的统一时机调用）。需要同步用 `@SyncMonitor`。
3. 监听路径写错**不会报错**，只是不触发。写路径时要仔细。

## 5.8 `@Computed`：派生值（带缓存）

### 定义

```typescript
declare const Computed: MethodDecorator;   // @since 12
```

### 基本用法

```typescript
@ComponentV2
struct Demo {
  @Local price: number = 100;
  @Local count: number = 2;

  @Computed
  get total(): number {          // ← 必须是 getter（get 关键字）
    return this.price * this.count;
  }

  build() {
    Text(`总价：${this.total}`)   // ← 像普通属性一样用，不加括号
  }
}
```

### 和普通方法的区别

```typescript
// ① 普通方法：每次渲染都重新计算
private getTotal(): number {
  return this.price * this.count;
}
// 用：Text(`${this.getTotal()}`)

// ② @Computed：只有依赖（price/count）变了才重算，否则用缓存
@Computed
get total(): number {
  return this.price * this.count;
}
// 用：Text(`${this.total}`)
```

**什么时候必须用 `@Computed`**：

- 计算成本高（排序、过滤大数组、复杂对象构造）
- 同一个值在 `build()` 里被用到多次

**什么时候用普通方法就行**：

- 计算很轻（几个三元表达式、简单加减）
- 本项目的 `pagePadding()`、`isWideLayout()` 这类都是普通方法

### 本项目的真实例子

`component/WaterFlowView.ets`：

```typescript
@Computed
get getBannerItemsCount(): number {
  this.handleTabBarAnimation?.(-1);
  const bannerItemsCount: number = new BreakpointType({
    sm: 1,
    md: this.globalInfoModel.heightBreakpoint === HeightBreakpoint.HEIGHT_LG ? 1 : 2,
    lg: 2,
  }).getValue(this.globalInfoModel.widthBreakpoint);
  return bannerItemsCount;
}

@Computed
get getSections(): WaterFlowSections {
  const horizontalMargin = new BreakpointType({
    sm: $r('sys.float.padding_level8'),
    md: $r('sys.float.padding_level12'),
    lg: $r('sys.float.padding_level16'),
  }).getValue(this.globalInfoModel.widthBreakpoint)

  const bannerSection: SectionOptions = {
    itemsCount: this.getBannerItemsCount,       // ← @Computed 之间可以互相依赖
    crossCount: this.getBannerItemsCount,
    margin: { left: horizontalMargin, right: horizontalMargin,
              top: this.globalInfoModel.statusBarHeight + 56 },
  };
  // ...
  this.sectionOptions.splice(0, this.sectionOptions.length(), [bannerSection, waterFlowSection]);
  return this.sectionOptions;
}
```

**这里为什么必须用 `@Computed`**：`WaterFlowSections` 构造涉及断点判断和对象拼装，
而且 `WaterFlow` 每帧滚动都会读它。不缓存的话滚动会很卡。

### 规则

| # | 规则 |
|---|---|
| 1 | 必须是 `get` 访问器 |
| 2 | **不能有副作用**（不能改状态、不能做 I/O） |
| 3 | 依赖必须是可观察的（`@Local` / `@Param` / `@Trace`） |
| 4 | 使用时不加括号：`this.total` 而不是 `this.total()` |

> ⚠️ 上面 `getBannerItemsCount` 里调用了 `this.handleTabBarAnimation?.(-1)`，这**是一个副作用**，
> 严格说违反了规则 2。这是本项目里一个可以改进的地方，不要照抄这个做法。

## 5.9 `@Provider` / `@Consumer`：跨层级传递

### 定义

```typescript
declare const Provider: (aliasName?: string) => PropertyDecorator;   // @since 12
declare const Consumer: (aliasName?: string) => PropertyDecorator;   // @since 12
```

### 解决什么问题

```
MainPage           ← 这里有 pathStack
  └── HdsNavigation
       └── TabPageView    ← 这里要用 pathStack
```

如果用 `@Param` 一层层传，中间每一层都要写一遍，很烦（这叫 "prop drilling"）。

`@Provider`/`@Consumer` 让**后代直接拿祖先的数据**，中间层什么都不用写。

### 用法

```typescript
// 祖先组件：提供
@Entry
@ComponentV2
struct MainPage {
  @Provider('mainPageStack') pathStack: NavPathStack = new NavPathStack();
  //         ↑ 别名（可选，不写就用变量名）
}

// 后代组件（任意深度）：消费
@ComponentV2
export struct TabPageView {
  @Consumer('mainPageStack') pathStack: NavPathStack = new NavPathStack();
  //                                                    ↑ 必须有默认值（找不到 Provider 时用）
}
```

### 规则

| # | 规则 |
|---|---|
| 1 | `@Consumer` 会找**最近的**祖先 `@Provider`（同名的） |
| 2 | 找不到就用自己的默认值（**不报错**，容易埋坑） |
| 3 | `@Consumer` **可以修改**，会同步回 `@Provider` |
| 4 | 别名建议显式写，避免变量重名冲突 |
| 5 | 只在 V2 组件之间生效 |

### 本项目的真实用法

**这是本项目唯一使用 `@Provider`/`@Consumer` 的地方**（`pages/MainPage.ets` ↔ `component/TabPageView.ets`）：

```typescript
// MainPage.ets（提供）
@Provider('mainPageStack') pathStack: NavPathStack = new NavPathStack();

// TabPageView.ets（消费）
@Consumer('mainPageStack') pathStack: NavPathStack = new NavPathStack();
```

**为什么不用 `AppStorageV2`**：`NavPathStack` 是和特定页面绑定的导航栈，不是全局状态。
用 `@Provider` 语义更准确（「这个子树共享一个导航栈」）。

### ⚠️ 陷阱：找不到 Provider 时静默失败

```typescript
@Consumer('mainPageStackTypo') pathStack: NavPathStack = new NavPathStack();
//                    ↑ 名字打错了
```

不会报错，但 `this.pathStack` 是一个**孤立的空栈**，`pushPath` 之后什么都不会发生。
排查这类 bug 很痛苦，所以**别名字符串要小心**。

## 5.10 `@ObservedV2` + `@Trace`：类的深度观察

### 定义

```typescript
declare const ObservedV2: ClassDecorator;   // @since 12
declare const Trace: PropertyDecorator;     // @since 12
```

### 核心规则

```typescript
@ObservedV2                       // ① 类上加这个
class MyModel {
  @Trace name: string = '';       // ② 需要触发 UI 更新的字段加这个
  age: number = 0;                // ③ 不加 @Trace 的字段，改了 UI 不会动
}
```

**一句话**：`@ObservedV2` 开启观察能力，`@Trace` 标记具体哪个字段要被观察。

### 本项目的核心：`GlobalInfoModel`

`model/GlobalInfoModel.ets`（全文，只有 14 行有效代码）：

```typescript
@ObservedV2
export class GlobalInfoModel {
  @Trace public foldExpanded: boolean = false;                                  // 折叠屏是否展开
  @Trace public widthBreakpoint: WidthBreakpoint = WidthBreakpoint.WIDTH_SM;    // 宽度断点
  @Trace public heightBreakpoint: HeightBreakpoint = HeightBreakpoint.HEIGHT_SM;// 高度断点
  @Trace public naviIndicatorHeight: number = 0;                                // 底部导航条高度
  @Trace public statusBarHeight: number = 0;                                    // 状态栏高度
  @Trace public keyboardHeight: number = 0;                                     // 键盘高度
  @Trace public deviceHeight: number = 0;                                       // 设备高度(vp)
  @Trace public deviceWidth: number = 0;                                        // 设备宽度(vp)
  @Trace public role: string = '护工';                                          // 当前角色

  public needDynamicHideBar: boolean = false;   // ← 没有 @Trace
  public aspectRatio: number = 0;                // ← 没有 @Trace
}
```

**为什么最后两个不加 `@Trace`**：

它们是**中间计算结果**，不直接驱动 UI。
`aspectRatio` 用来算 `needDynamicHideBar`，`needDynamicHideBar` 目前只在内部逻辑用。
改它们不需要重绘，所以不加 `@Trace` 能省性能。

> 此处体现了一条设计原则：并非所有字段都需要 `@Trace`，仅对真正驱动 UI 的字段标注。

### 嵌套观察示例

```typescript
@ObservedV2
class Address {
  @Trace city: string = '北京';
}

@ObservedV2
class Person {
  @Trace name: string = '张三';
  @Trace address: Address = new Address();     // ← 嵌套的对象
}

@ComponentV2
struct Demo {
  @Local person: Person = new Person();

  build() {
    Column() {
      Text(this.person.name)                    // ✅ 改 name 会刷新
      Text(this.person.address.city)            // ✅ 改 address.city 也会刷新！
      Button('改城市').onClick(() => {
        this.person.address.city = '上海';       // ✅ 深层修改，UI 会更新
      })
    }
  }
}
```

这是 V2 相较 V1 最主要的能力提升。

### 数组里的对象

```typescript
@ObservedV2
class Task {
  @Trace title: string = '';
  @Trace done: boolean = false;
}

@ComponentV2
struct Demo {
  @Local tasks: Task[] = [new Task(), new Task()];

  build() {
    Column() {
      Repeat(this.tasks).each((r: RepeatItem<Task>) => {
        Row() {
          Text(r.item.title)
          Checkbox().select(r.item.done)
            .onChange((v: boolean) => {
              r.item.done = v;         // ✅ 会刷新（因为 Task 是 @ObservedV2 + @Trace）
            })
        }
      }).key((t: Task) => t.title)
    }
  }
}
```

**如果 `Task` 是普通 class（没有 `@ObservedV2`）**，`r.item.done = v` 就不会刷新，
必须写 `this.tasks = [...this.tasks]` 强制触发。

### 本项目的另一个例子

`pages/AiChatPage.ets` 的聊天历史：

```typescript
@ObservedV2
class AiChatHistoryStore {
  @Trace sessions: ChatSession[] = [];
  @Trace activeSessionId: string = '';
}
```

**注意**：`ChatSession` 本身是 `interface`（不是 class），所以里面的字段改了**不会**触发更新。
本项目的做法是**整体替换数组**：

```typescript
private syncActiveSession(messages: ChatMessage[] = this.messages, refreshActivity: boolean = true): void {
  const updated: ChatSession = {
    id: current.id,
    title: current.title,
    messages: this.cloneMessages(messages),      // ← 深拷贝
    updatedAt: refreshActivity ? Date.now() : current.updatedAt
  };

  if (!refreshActivity) {
    this.historyStore.sessions = this.historyStore.sessions.map(
      (session: ChatSession): ChatSession => session.id === activeId ? updated : session
    );     // ← map 返回新数组，整体替换
    return;
  }

  // ...
  this.historyStore.sessions = [updated, ...remaining].slice(0, MAX_CHAT_SESSIONS);
  //  ↑ 整体替换
}
```

**这是「不可变数据（immutable）」风格**：不改原对象，而是造一个新的替换掉。
优点是行为可预测，缺点是有拷贝开销。数据量不大时推荐这么做。

### `@Trace` 的限制

| 限制 | 说明 |
|---|---|
| 只能用在 `@ObservedV2` 类里 | 普通 class 里加了没用 |
| 不能用在 `struct` 里 | struct 用 `@Local` |
| 静态字段不能加 | `@Trace static x` ❌ |
| 深层类每层都要 `@ObservedV2` | 漏一层就断了 |

## 5.11 `AppStorageV2`：全局共享状态

### 定义（SDK 实测）

```typescript
export declare class AppStorageV2 {
  static connect<T extends object>(
    type: TypeConstructorWithArgs<T>,                          // 类型（构造函数）
    keyOrDefaultCreator?: string | StorageDefaultCreator<T>,   // key 或 默认值工厂
    defaultCreator?: StorageDefaultCreator<T>                  // 默认值工厂
  ): T | undefined;

  static remove<T>(keyOrType: string | TypeConstructorWithArgs<T>): void;
  static keys(): Array<string>;
}
```

### 三种调用形式

```typescript
// 形式 1：只给类型（用类名做 key）
const m = AppStorageV2.connect(GlobalInfoModel);

// 形式 2：类型 + key（不创建，只连接。没有就返回 undefined）
const m = AppStorageV2.connect(GlobalInfoModel, StorageKey.GLOBAL_INFO);

// 形式 3：类型 + key + 默认值工厂（没有就创建）最常用
const m = AppStorageV2.connect(GlobalInfoModel, StorageKey.GLOBAL_INFO, () => new GlobalInfoModel());
```

**返回类型是 `T | undefined`**，所以必须兜底：

```typescript
@Local globalInfoModel: GlobalInfoModel =
  AppStorageV2.connect(GlobalInfoModel, StorageKey.GLOBAL_INFO, () => new GlobalInfoModel())
  ?? new GlobalInfoModel();
```

### 核心机制：所有连接同一个 key 的组件，共享同一个对象实例

```
        AppStorageV2
    ┌─────────────────────┐
    │ 'kanxiaoban_Global' │──→ 唯一的 GlobalInfoModel 实例
    └─────────────────────┘
       ↑     ↑     ↑
       │     │     │
  MainPage  Login  TabPageView    ← 都拿到同一个对象
```

**任何一个地方改了 `@Trace` 字段，所有连接的组件都会重新渲染。**

### 本项目的使用地图

| 文件 | 连接的 key | 用途 |
|---|---|---|
| `util/WindowUtil.ets` | `UI_CONTEXT` + `GLOBAL_INFO` | **写入**：把窗口指标写进去 |
| `pages/MainPage.ets` | `GLOBAL_INFO` | 读断点、角色、状态栏高度 |
| `pages/LoginPage.ets` | `GLOBAL_INFO` | 读键盘高度，**写角色** |
| `pages/AiChatPage.ets` | `GLOBAL_INFO` + `aiChatHistoryStore` | 读断点/键盘 + 聊天历史 |
| `pages/HealthExpandPage.ets` | `GLOBAL_INFO` | 读状态栏高度 |
| `pages/ResidentDetailPage.ets` | `GLOBAL_INFO` | 读状态栏高度 |
| `pages/MineDetailPage.ets` | `GLOBAL_INFO` | 读断点 |
| `component/TabPageView.ets` | `GLOBAL_INFO` | 读断点、状态栏、导航条高度 |
| `component/WaterFlowView.ets` | `GLOBAL_INFO` | 读断点 |
| `util/PreferenceManager.ets` | `UI_CONTEXT` | 拿 Context 建 preferences |

### key 的定义（`common/CommonConstants.ets`）

```typescript
export enum StorageKey {
  UI_CONTEXT = 'kanxiaoban_UIContext',
  GLOBAL_INFO = 'kanxiaoban_GlobalInfoModel',
  MATERIAL_LEVEL = 'kanxiaoban_CustomMaterialLevel',   // 目前未使用
}
```

**用枚举而不是裸字符串**：打错字编译器会报错。

### 完整的数据流

```
① 系统事件（旋转屏幕/键盘弹出/折叠屏展开）
        ↓
② WindowUtil 的监听器被触发
   windowClass.on('windowSizeChange', ...)
   windowClass.on('avoidAreaChange', ...)
        ↓
③ WindowUtil 从 AppStorageV2 拿到 GlobalInfoModel 实例
   const globalInfoModel = AppStorageV2.connect(GlobalInfoModel, StorageKey.GLOBAL_INFO, () => new GlobalInfoModel());
        ↓
④ 修改 @Trace 字段
   globalInfoModel.statusBarHeight = uiContext.px2vp(area.topRect.height);
   globalInfoModel.widthBreakpoint = uiContext.getWindowWidthBreakpoint();
        ↓
⑤ 所有 connect 了同一个 key 的组件收到通知，重新渲染
   MainPage / TabPageView / LoginPage / AiChatPage / ...
        ↓
⑥ 组件根据新的 widthBreakpoint 切换手机布局 / 宽屏布局
```

这是本项目一多适配机制的核心链路，第 09 章展开说明。

### 存 `UIContext` 的技巧

`UIContext` 本身不是你定义的类，但也能存：

```typescript
// util/WindowUtil.ets（存）
import { AppStorageV2, UIContext, window } from '@kit.ArkUI';

const uiContext: UIContext = WindowUtil.windowClass.getUIContext();
AppStorageV2.connect(UIContext, StorageKey.UI_CONTEXT, () => uiContext);

// util/PreferenceManager.ets（取）—— 在非 UI 类里也能拿到 Context
const uiContext: UIContext | undefined = AppStorageV2.connect(UIContext, StorageKey.UI_CONTEXT);
if (!uiContext) {
  Logger.error(TAG, `initPreference failed, cause uiContext is undefined.`);
  return;
}
this.preferences = preferences.getPreferencesSync(uiContext.getHostContext() as Context, { name: storeName });
```

该写法解决的问题是：工具类不是组件，没有 `this.getUIContext()`，需通过 `AppStorageV2` 中转获取。

### ⚠️ 本项目的一个不必要写法

`util/WindowUtil.ets` 里每次改完都会再 connect 一次：

```typescript
globalInfoModel.statusBarHeight = ...;
AppStorageV2.connect(GlobalInfoModel, StorageKey.GLOBAL_INFO, () => globalInfoModel);   // ← 这行
```

**这行其实是多余的**。因为 `globalInfoModel` 已经是 storage 里那个实例的引用，
改它的 `@Trace` 字段就已经触发更新了，不需要再 connect。

不过它也**没有害处**（connect 已存在的 key 会直接返回现有实例）。
知道这一点就行，新代码不用照抄。

## 5.12 `PersistenceV2`：持久化状态

### 定义

```typescript
export declare class PersistenceV2 extends AppStorageV2 {
  static globalConnect<T extends object>(type: ConnectOptions<T>): T | undefined;
  static save<T>(keyOrType: string | TypeConstructorWithArgs<T>): void;
  static notifyOnError(callback: PersistenceErrorCallback | undefined): void;
}
```

### 用法

```typescript
@ObservedV2
class Settings {
  @Trace theme: string = 'light';
  @Trace fontSize: number = 16;
}

// 连接（第一次会从磁盘读，之后在内存）
const settings = PersistenceV2.globalConnect({
  type: Settings,
  key: 'app_settings',
  defaultCreator: () => new Settings()
}) ?? new Settings();

// 改了之后要手动存盘
settings.theme = 'dark';
PersistenceV2.save('app_settings');

// 错误处理
PersistenceV2.notifyOnError((key: string, reason: string, message: string) => {
  Logger.error(TAG, `持久化失败 ${key}: ${reason} ${message}`);
});
```

### `@Type` 装饰器（序列化复杂类型时需要）

```typescript
export declare const Type: TypeDecorator;
```

```typescript
@ObservedV2
class Container {
  @Type(Item)                      // ← 告诉序列化器数组元素的真实类型
  @Trace items: Item[] = [];
}
```

不加 `@Type`，反序列化后数组元素会变成普通对象（丢失类方法）。

### `AppStorageV2` vs `PersistenceV2`

| | `AppStorageV2` | `PersistenceV2` |
|---|---|---|
| 存哪 | 内存 | 内存 + 磁盘 |
| App 重启后 | 丢失 | 保留 |
| 性能 | 快 | 写盘有开销 |
| 适合 | 窗口指标、当前会话、运行时状态 | 用户设置、登录态、草稿 |

### 本项目的选择

**本项目全部用 `AppStorageV2`，没用 `PersistenceV2`**。

因为它是一个**纯本地交互原型**：重启后重新登录、数据重置，是符合预期的。
`PreferenceManager`（基于 `@kit.ArkData` 的 preferences）虽然写好了，但目前也没被真正使用。

## 5.14 V1 与 V2 对照表

| V1 | V2 | 差别 |
|---|---|---|
| `@Component` | `@ComponentV2` | — |
| `@State x = 0` | `@Local x = 0` | V2 观察更精确，无隐式深拷贝 |
| `@Prop x` | `@Param x` | V2 明确只读；V1 `@Prop` 是单向拷贝 |
| `@Link x` | `@Param x` + `@Event onXChange` | V2 没有双向绑定，改用回调 |
| `@Provide` | `@Provider()` | 加括号 |
| `@Consume` | `@Consumer()` | 加括号 |
| `@Observed` | `@ObservedV2` | V2 支持深层观察 |
| `@ObjectLink` | 直接用 `@Trace` | V2 不需要 ObjectLink |
| `@Watch('cb')` | `@Monitor('x')` | 装饰位置从属性变方法 |
| （无） | `@Computed` | V2 新增 |
| （无） | `@Once` | V2 新增 |
| `AppStorage` | `AppStorageV2` | API 完全不同 |
| `PersistentStorage` | `PersistenceV2` | API 完全不同 |
| `LocalStorage` | （V2 无对应，用 `@Provider`） | — |

### 迁移示例：`@Link` 怎么用 V2 写

```typescript
// V1：双向绑定
@Component
struct Child {
  @Link value: string;      // 改了会同步回父
}

// V2：拆成「参数 + 事件」
@ComponentV2
struct Child {
  @Param value: string = '';
  @Event onValueChange: (v: string) => void = () => {};

  private change(newVal: string): void {
    this.onValueChange(newVal);      // 通知父组件改
  }
}

// 父组件
Child({
  value: this.myValue,
  onValueChange: (v: string) => { this.myValue = v; }
})
```

**V2 为什么去掉双向绑定**：单向数据流更容易追踪。
「谁改了这个值」在 V2 里永远只有一个答案（数据的拥有者），调试简单得多。

## 5.15 「界面不刷新」排查流程

按顺序检查：

### ① 变量有没有装饰器？

```typescript
count: number = 0;          // ❌ 改了不刷新
@Local count: number = 0;   // ✅
```

### ② 是不是在改 `@Param`？

```typescript
@Param value: string = '';
this.value = 'x';           // ❌ 编译报错（只读）
```

**改法**：让父组件改（通过 `@Event`），或者加 `@Once`。

### ③ 类字段有没有 `@Trace`？

```typescript
@ObservedV2
class M {
  name: string = '';        // ❌ 改了不刷新
  @Trace name2: string = ''; // ✅
}
```

### ④ 嵌套对象每一层都是 `@ObservedV2` 吗？

```typescript
@ObservedV2
class A {
  @Trace b: B = new B();
}

class B {                   // ❌ 少了 @ObservedV2，这一层断了
  @Trace c: string = '';    //    加了 @Trace 也没用
}
```

### ⑤ 数组元素是 `@ObservedV2` 吗？

```typescript
@Local list: Item[] = [];

this.list[0].name = 'x';    // ❌ Item 不是 @ObservedV2 → 不刷新
this.list = [...this.list]; // ✅ 强制整体替换
```

### ⑥ `ForEach`/`Repeat` 的 key 变了吗？

```typescript
// ❌ 数据换了但 key 没变，框架以为没变
ForEach(this.items, (item) => { }, (item, index) => `${index}`)

// ✅
ForEach(this.items, (item) => { }, (item) => item.id)
```

### ⑦ `this` 丢了吗？

```typescript
// ❌ 普通函数的 this 不是组件
setTimeout(function() { this.count++; }, 100);

// ✅ 箭头函数
setTimeout(() => { this.count++; }, 100);
```

### ⑧ `@Consumer` 找到 `@Provider` 了吗？

别名拼写错了会静默失败。检查两边字符串是否完全一致。

### ⑨ `@Monitor` 的路径写对了吗？

```typescript
@Monitor('globalInfoModel.keyboardHeigt')   // ← 拼写错误，静默失效
```

### ⑩ 改的对象是不是 `AppStorageV2` 里的那个实例？

```typescript
// ❌ 新建了一个，不是 storage 里那个
const m = new GlobalInfoModel();
m.role = '医师';

// ✅
const m = AppStorageV2.connect(GlobalInfoModel, StorageKey.GLOBAL_INFO, () => new GlobalInfoModel());
m!.role = '医师';
```

## 5.16 本项目的状态管理规范

### 规范 1：全局状态只放 `GlobalInfoModel`

**能放的四类**：

- 会话（当前角色 `role`）
- 环境（`deviceWidth` / `deviceHeight` / `aspectRatio`）
- 窗口（`statusBarHeight` / `naviIndicatorHeight` / `keyboardHeight` / `foldExpanded`）
- 断点（`widthBreakpoint` / `heightBreakpoint`）

**不能放的**：

- ❌ 业务记录（长者列表、任务列表、消息列表）
- ❌ 表单状态（搜索关键词、筛选条件）
- ❌ UI 开关（弹窗开没开、哪一项被选中）

这些统统留在组件的 `@Local` 里。

**为什么**：全局状态一膨胀，任何一处修改都会引发全 App 重渲染，性能雪崩，而且没人知道谁改了什么。

### 规范 2：`role` 是显示用的，不是权限

```typescript
@Trace public role: string = '护工';
```

它只用来选择渲染哪个工作台：

```typescript
// pages/MainPage.ets
if (this.globalInfoModel.role === '管理') {
  WideAdminWorkspace({ ... })
} else if (this.globalInfoModel.role === '医师') {
  WideDoctorWorkspace({ ... })
} else {
  WideCaregiverWorkspace({ ... })
}
```

**绝对不要**基于这个字符串做权限判断（「因为 role 是管理所以允许删除」）。
这是一个本地原型，`role` 是用户在登录页自己选的，随便改。

### 规范 3：禁用一切 V1 装饰器

`@State` `@Prop` `@Link` `@Observed` `@ObjectLink` `@Watch` `@Provide` `@Consume` `@StorageLink` `@StorageProp` `@LocalStorageLink` `@LocalStorageProp` —— **全部禁止**。

### 规范 4：只给影响 UI 的字段加装饰器

```typescript
private timerId: number = -1;              // ✅ 不影响 UI，不加
@Local isHealthExpandShow: boolean = false; // ✅ 影响 UI，加
```

### 规范 5：`@Event` 必须有默认空函数

```typescript
@Event onClose: () => void = () => {};      // ✅
@Event onClose: () => void;                  // ❌ 父不传就崩
```

## 5.17 完整实例：本项目的状态流转

### 场景：用户在登录页选择「医师」角色并登录，然后旋转平板

```typescript
// ① LoginPage 连接全局状态
@Local globalInfoModel: GlobalInfoModel =
  AppStorageV2.connect(GlobalInfoModel, StorageKey.GLOBAL_INFO, () => new GlobalInfoModel()) ?? new GlobalInfoModel();

// ② 用户点角色菜单，写入全局
.bindMenu(this.roleOptions.map((role: string): MenuElement => ({
  value: role,
  action: () => {
    this.selectedRole = role;              // 本地状态（用于显示）
    this.globalInfoModel.role = role;      // ★ 写入全局状态（@Trace，触发所有连接方更新）
  }
})))

// ③ 点登录
private async handleLogin(): Promise<void> {
  if (!this.account || !this.password) return;
  this.isLoading = true;                   // @Local，按钮变成转圈
  setTimeout(async () => {
    this.isLoading = false;
    this.globalInfoModel.role = this.selectedRole;    // 再确认一次
    await router.replaceUrl({ url: 'pages/MainPage' });
  }, 800);
}

// ④ MainPage 连接同一个全局状态（拿到同一个对象实例）
@Local globalInfoModel: GlobalInfoModel =
  AppStorageV2.connect(GlobalInfoModel, StorageKey.GLOBAL_INFO, () => new GlobalInfoModel()) ?? new GlobalInfoModel();

// ⑤ 根据 role 渲染对应工作台
@Builder
private wideShell() {
  if (this.globalInfoModel.role === '管理') { WideAdminWorkspace({ ... }) }
  else if (this.globalInfoModel.role === '医师') { WideDoctorWorkspace({ ... }) }
  else { WideCaregiverWorkspace({ ... }) }
}

// ⑥ 用户旋转平板 → WindowUtil 的监听器触发
windowClass.on('windowSizeChange', (windowSize: window.Size) => WindowUtil.setWindowSize(windowSize));

// ⑦ WindowUtil 更新断点（@Trace 字段）
public static setWindowSize(windowSize?: window.Size | window.Rect) {
  const globalInfoModel = AppStorageV2.connect(GlobalInfoModel, StorageKey.GLOBAL_INFO, () => new GlobalInfoModel()) ?? new GlobalInfoModel();
  globalInfoModel.deviceWidth = uiContext.px2vp(windowSize.width);
  globalInfoModel.deviceHeight = uiContext.px2vp(windowSize.height);
  globalInfoModel.widthBreakpoint = uiContext.getWindowWidthBreakpoint();   // ★
  globalInfoModel.heightBreakpoint = uiContext.getWindowHeightBreakpoint();
}

// ⑧ MainPage 的 build() 里读到新断点，切换布局
build() {
  Stack() {
    HdsNavigation(this.pathStack) {
      if (this.isWideLayout()) { this.wideShell() }      // ← 宽屏
      else { this.phoneTabs() }                          // ← 手机
    }
  }
}

private isWideLayout(): boolean {
  return BreakpointUtil.isWide(this.globalInfoModel.widthBreakpoint);
}
```

整条链路中不存在任何手动通知环节，这是声明式与响应式状态管理的核心价值。
