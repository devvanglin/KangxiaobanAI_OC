## 14.1 项目概述

**康小伴 AI（KangxiaobanAI）** —— HarmonyOS NEXT 原生的**智慧养老护理工作台**。

| 项 | 值 |
|---|---|
| 包名 | `com.gxoc.kxbai` |
| 模块名 | `kanxiaoban`（type: `entry`） |
| 版本 | `1.0.0`（versionCode `1000000`） |
| SDK | `6.1.1(24)`（target = compatible） |
| 运行时 | HarmonyOS |
| 设备 | `phone` / `tablet` / `2in1` |
| 入口 Ability | `KanxiaobanAbility` |
| 首屏 | `pages/LoginPage` |
| 产物 | `products/entry/build/default/outputs/default/kanxiaoban-default-signed.hap` |

### 项目定位

**这是一个高保真的本地交互原型，不是生产系统。**

| 方面 | 实际情况 |
|---|---|
| 数据 | 全部是硬编码 mock，写在组件的私有方法里 |
| 网络 | **没有任何网络层** |
| 鉴权 | 登录接受**任何非空**账号密码，`setTimeout(800ms)` 后放行 |
| 角色 | 用户在登录页自己下拉选，**纯显示用，不是权限** |
| AI | 本地确定性文本，**不是真模型** |
| 持久化 | `PreferenceManager` 写好了但基本没用；状态存内存，重启丢失 |

**因此**：

- ❌ 不要把「本地数组增删」描述成「已保存 / 已提交服务器」
- ❌ 不要基于 `role` 字符串做任何授权逻辑
- ✅ 汇报时如实说明这是原型

## 14.3 七个核心机制

### 机制 1：状态管理 V2（唯一体系）

```typescript
// 组件：@ComponentV2 + @Local/@Param/@Event/@Monitor/@Computed/@Provider/@Consumer
// 数据类：@ObservedV2 + @Trace
// 全局：AppStorageV2.connect(...)
```

**禁用**：`@State` `@Prop` `@Link` `@Observed` `@ObjectLink` `@Watch` `@Provide` `@Consume`。

### 机制 2：单一全局状态类

```typescript
// model/GlobalInfoModel.ets
@ObservedV2
export class GlobalInfoModel {
  @Trace public foldExpanded: boolean = false;
  @Trace public widthBreakpoint: WidthBreakpoint = WidthBreakpoint.WIDTH_SM;
  @Trace public heightBreakpoint: HeightBreakpoint = HeightBreakpoint.HEIGHT_SM;
  @Trace public naviIndicatorHeight: number = 0;
  @Trace public statusBarHeight: number = 0;
  @Trace public keyboardHeight: number = 0;
  @Trace public deviceHeight: number = 0;
  @Trace public deviceWidth: number = 0;
  @Trace public role: string = '护工';
  public needDynamicHideBar: boolean = false;   // 无 @Trace
  public aspectRatio: number = 0;               // 无 @Trace
}
```

**只放四类**：会话（role）/ 环境（device*）/ 窗口（*Height, *Breakpoint）/ 折叠态。
**业务数据一律留在组件里。**

**连接方式**（全项目 10 处，写法完全一致）：

```typescript
@Local globalInfoModel: GlobalInfoModel =
  AppStorageV2.connect(GlobalInfoModel, StorageKey.GLOBAL_INFO, () => new GlobalInfoModel())
  ?? new GlobalInfoModel();
```

（有几处省略了第三个参数：`AppStorageV2.connect(GlobalInfoModel, StorageKey.GLOBAL_INFO) ?? new GlobalInfoModel()`，
因为它们运行时 `WindowUtil` 一定已经创建过了。）

### 机制 3：设备状态泵（`WindowUtil`）

**单一数据源**。所有断点、安全区、键盘高度都由它写入 `GlobalInfoModel`。

```
EntryAbility.onWindowStageCreate
  → loadContent 回调
    → WindowUtil.initialize(windowStage)
      ├── getMainWindowSync()
      ├── getUIContext() → 存进 AppStorageV2[UI_CONTEXT]
      ├── setImmersiveMode(false) → 全屏 + 透明系统栏
      └── registerBreakpoint()
          ├── 首次计算尺寸/断点/安全区
          ├── on('windowSizeChange')  → setWindowSize()
          └── on('avoidAreaChange')   → setAvoidArea() / keyboardHeight
```

**铁律：组件永远从 `GlobalInfoModel` 读，不要自己查窗口。**

### 机制 4：双布局分叉

```typescript
// 第 1 层：手机 vs 宽屏
if (BreakpointUtil.isWide(bp)) { wideShell() } else { phoneTabs() }

// 第 2 层：角色
if (role === '管理') { WideAdminWorkspace }
else if (role === '医师') { WideDoctorWorkspace }
else { WideCaregiverWorkspace }

// 第 3 层：平板 vs PC
compactWidth: BreakpointUtil.isTablet(bp)

// 第 4 层：XL 特判
admissionCompactWidth: bp !== WidthBreakpoint.WIDTH_XL

// 第 5 层：具体数值
new BreakpointType<number>({ sm: 16, md: 24, lg: 28, xl: 32 }).getValue(bp)
```

### 机制 5：三套导航机制

| 机制 | 数量 | 用在哪 |
|---|---|---|
| `router` | 2 个页面 | 只有 Login ↔ Main |
| `NavPathStack` | 2 个目的地 | AboutPage / GeneralSettingsPage |
| 浮层 | 3 个 cover + 1 个 Stack + N 个 sheet | 详情、展开、AI 聊天、各种面板 |

### 机制 6：一镜到底（4 处）

| 起点 | 终点 | ID |
|---|---|---|
| `HealthListCard`（健康卡片） | `HealthExpandPage` | `'healthCard'`（固定） |
| `TabPageView.residentListRow` | `ResidentDetailPage` | `resident_geo_${id}`（动态） |
| `TabPageView.aiReminderCard` | `AiChatPage` | `'aiReminderCard'`（固定） |
| `TabPageView.quickActionContent` | `taskExpandCover` | `quick_expand_geo_${index}`（索引） |

**统一配方**：起点 `{follow:true}` + 终点无 follow + 两边 `.transition(OPACITY)` +
`animateTo(interpolatingSpring(0,1,328,36))` 开 / `(0,1,342,38)` 关 +
`bindContentCover(..., {modalTransition: ModalTransition.NONE})` + 起点渲染空占位。
