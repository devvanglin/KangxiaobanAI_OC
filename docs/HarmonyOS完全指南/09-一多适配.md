# 第 09 章 · 一多适配（一次开发，多端部署）

> 「一多」= **一次开发，多端部署**（One Development, Multi-deployment）。
>
> 同一份代码，在手机、折叠屏、平板、PC、车机、手表上都能用，而且**每种设备上都好用**。
>
> 这是本项目的核心设计模式，也是理解 `KangxiaobanAI` 整体架构的关键。

---

## 9.1 「一多」与「响应式」的区别

### 层次 1：响应式（Responsive）—— 同一套 UI 拉伸缩放

```
手机：  [卡片][卡片]
平板：  [卡片][卡片][卡片][卡片]        ← 还是那个卡片，只是一行放更多
```

这是**最浅层**的适配，改改列数、边距就行。

### 层次 2：一多（Multi-deployment）—— 不同设备用**不同的信息架构**

```
手机：  底部 4 个 Tab，单列列表，点进去看详情
        ↓ 完全不同的组织方式 ↓
平板：  左侧导航栏 + 中间列表 + 右侧详情（三栏同时可见）
```

这不是等比拉伸，而是信息架构的重新设计。

**本项目走的是层次 2。**

## 9.2 断点系统（Breakpoint）

### 宽度断点（SDK 实测定义）

```typescript
declare enum WidthBreakpoint {
  WIDTH_XS = 0,     // 窗口宽度 < 320vp
  WIDTH_SM = 1,     // 320vp ≤ 宽度 < 600vp     ← 手机竖屏
  WIDTH_MD = 2,     // 600vp ≤ 宽度 < 840vp     ← 折叠屏展开 / 小平板
  WIDTH_LG = 3,     // 840vp ≤ 宽度 < 1440vp    ← 平板 / 小尺寸 PC 窗口
  WIDTH_XL = 4      // 宽度 ≥ 1440vp            ← 大屏 PC
}
```

### 高度断点（按**宽高比**，不是绝对高度！）

```typescript
declare enum HeightBreakpoint {
  HEIGHT_SM = 0,    // 窗口 aspectRatio < 0.8       ← 很宽很扁（横屏）
  HEIGHT_MD = 1,    // 0.8 ≤ aspectRatio < 1.2      ← 接近正方形
  HEIGHT_LG = 2     // aspectRatio ≥ 1.2            ← 很高很窄（竖屏）
}
```

**⚠️ 注意**：`HeightBreakpoint` 判断的是**宽高比**（这里的 aspectRatio = 高/宽），不是像素高度。
新手很容易以为 `HEIGHT_LG` 是「屏幕很高」，其实是「形状很竖」。

### 重要认知：断点看的是**窗口**，不是**屏幕**

在 PC 上，用户可以把窗口拖成任意大小。
一个 1080p 的显示器，App 窗口可能只有 500vp 宽 → 那就是 `WIDTH_SM`（手机布局）。

**所以断点判断必须实时响应窗口变化，不能在启动时算一次就完事。**

### 怎么拿到当前断点

```typescript
const uiContext = this.getUIContext();
const w: WidthBreakpoint = uiContext.getWindowWidthBreakpoint();
const h: HeightBreakpoint = uiContext.getWindowHeightBreakpoint();
```

**但本项目不在组件里直接调这个**，而是通过 `WindowUtil` 统一泵到 `GlobalInfoModel`（见 9.4）。

## 9.3 本项目的断点工具（`util/BreakpointSystem.ets`）

### 全文（81 行）

```typescript
export interface BreakpointTypeOptions<T> {
  xs?: T;    // 可选
  sm: T;     // 必填
  md: T;     // 必填
  lg: T;     // 必填
  xl?: T;    // 可选
}

export class BreakpointType<T> {
  private xs: T;
  private sm: T;
  private md: T;
  private lg: T;
  private xl: T;

  public constructor(param: BreakpointTypeOptions<T>) {
    this.xs = param.xs ?? param.sm;      // ★ xs 不传就用 sm 的值
    this.sm = param.sm;
    this.md = param.md;
    this.lg = param.lg;
    this.xl = param.xl ?? param.lg;      // ★ xl 不传就用 lg 的值
  }

  public getValue(currentBreakpoint: WidthBreakpoint): T {
    if (currentBreakpoint === WidthBreakpoint.WIDTH_XS) return this.xs;
    if (currentBreakpoint === WidthBreakpoint.WIDTH_SM) return this.sm;
    if (currentBreakpoint === WidthBreakpoint.WIDTH_MD) return this.md;
    if (currentBreakpoint === WidthBreakpoint.WIDTH_XL) return this.xl;
    return this.lg;      // 默认（WIDTH_LG）
  }
}

/**
 * 断点判定工具：统一 wide/tablet/pc 判定，避免散落维护。
 * - wide  = MD / LG / XL（平板及以上）
 * - tablet = MD（平板）
 * - pc    = LG / XL（PC 桌面）
 */
export class BreakpointUtil {
  static isWide(breakpoint: WidthBreakpoint): boolean {
    return breakpoint === WidthBreakpoint.WIDTH_MD ||
      breakpoint === WidthBreakpoint.WIDTH_LG ||
      breakpoint === WidthBreakpoint.WIDTH_XL;
  }

  static isTablet(breakpoint: WidthBreakpoint): boolean {
    return breakpoint === WidthBreakpoint.WIDTH_MD;
  }

  static isPc(breakpoint: WidthBreakpoint): boolean {
    return breakpoint === WidthBreakpoint.WIDTH_LG ||
      breakpoint === WidthBreakpoint.WIDTH_XL;
  }

  static isExtraWide(breakpoint: WidthBreakpoint): boolean {
    return breakpoint === WidthBreakpoint.WIDTH_LG ||
      breakpoint === WidthBreakpoint.WIDTH_XL;
  }
}
```

### `BreakpointType<T>` 怎么用

**它是一个「按断点挑值」的容器**。泛型 `T` 可以是任何类型。

**用法 1：数值（内边距）**

```typescript
// component/TabPageView.ets
private pagePadding(): number {
  return new BreakpointType<number>({
    sm: 16,   // 手机：16vp
    md: 24,   // 平板：24vp
    lg: 28,   // PC：28vp
    xl: 32    // 大屏：32vp
  }).getValue(this.globalInfoModel.widthBreakpoint);
}
```

**用法 2：资源引用**

```typescript
// component/WaterFlowView.ets
const horizontalMargin = new BreakpointType({
  sm: $r('sys.float.padding_level8'),    // 16vp
  md: $r('sys.float.padding_level12'),   // 24vp
  lg: $r('sys.float.padding_level16'),   // 32vp
}).getValue(this.globalInfoModel.widthBreakpoint)
```

**用法 3：嵌套判断（宽度断点 + 高度断点组合）**

```typescript
// component/WaterFlowView.ets
@Computed
get getBannerItemsCount(): number {
  return new BreakpointType({
    sm: 1,
    md: this.globalInfoModel.heightBreakpoint === HeightBreakpoint.HEIGHT_LG ? 1 : 2,
    //  ↑ 平板宽度下，如果形状很竖（竖屏）就 1 个，横屏就 2 个
    lg: 2,
  }).getValue(this.globalInfoModel.widthBreakpoint);
}
```

**用法 4：布局参数**

```typescript
private bottomPadding(): number {
  return this.isWideLayout() ? 36 : 124;     // 简单场景直接三元也行
}
```

### `BreakpointUtil` 的四个判定

| 方法 | 覆盖断点 | 语义 |
|---|---|---|
| `isWide(bp)` | MD / LG / XL | 「宽屏形态」（平板及以上）→ 用多栏布局 |
| `isTablet(bp)` | MD | 平板（600~840vp）→ 布局要更紧凑 |
| `isPc(bp)` | LG / XL | PC → 可以放侧边栏 + 顶栏 |
| `isExtraWide(bp)` | LG / XL | 同 `isPc`（两个名字，同一个实现） |

> **注意**：`isPc` 和 `isExtraWide` 实现完全一样，是历史遗留的重复。
> 用哪个都行，但同一段代码里保持一致。

### 第二步：`initialize` 做四件事

```typescript
public static initialize(windowStage: window.WindowStage) {
  try {
    // ① 拿到主窗口
    WindowUtil.windowClass = windowStage.getMainWindowSync();

    // ② 拿到 UIContext 并存进 AppStorageV2（供非 UI 代码使用）
    const uiContext: UIContext = WindowUtil.windowClass.getUIContext();
    WindowUtil.uiContext = uiContext;
    AppStorageV2.connect(UIContext, StorageKey.UI_CONTEXT, () => uiContext);

    // ③ 开启沉浸式（内容延伸到状态栏、系统栏透明）
    WindowUtil.setImmersiveMode(false);

    // ④ 注册断点监听
    WindowUtil.registerBreakpoint(WindowUtil.windowClass);
  } catch (err) {
    Logger.error(TAG, `WindowUtil initialize failed. Cause: ${err.code} ${err.message}`);
  }
}
```

### 第三步：`registerBreakpoint` 注册两个监听器

```typescript
private static registerBreakpoint(windowClass: window.Window) {
  try {
    // ① 先算一次当前尺寸
    WindowUtil.getDeviceSize();

    // ② 拿到全局状态对象
    const globalInfoModel: GlobalInfoModel =
      AppStorageV2.connect(GlobalInfoModel, StorageKey.GLOBAL_INFO, () => new GlobalInfoModel()) ?? new GlobalInfoModel();

    // ③ 初始化状态栏和导航条高度
    const systemAvoidArea: window.AvoidArea = windowClass.getWindowAvoidArea(window.AvoidAreaType.TYPE_SYSTEM);
    globalInfoModel.statusBarHeight = WindowUtil.uiContext.px2vp(systemAvoidArea?.topRect?.height ?? 0);

    const bottomArea: window.AvoidArea = windowClass.getWindowAvoidArea(window.AvoidAreaType.TYPE_NAVIGATION_INDICATOR);
    globalInfoModel.naviIndicatorHeight = WindowUtil.uiContext.px2vp(bottomArea?.bottomRect?.height ?? 0);

    AppStorageV2.connect(GlobalInfoModel, StorageKey.GLOBAL_INFO, () => globalInfoModel);

    // ④ ★监听窗口尺寸变化（旋转屏幕、折叠屏展开、PC 拖窗口）
    windowClass.on('windowSizeChange', (windowSize: window.Size) => WindowUtil.setWindowSize(windowSize));

    // ⑤ ★监听避让区变化（状态栏/导航条/键盘）
    windowClass.on('avoidAreaChange', (avoidAreaOption) => {
      if (avoidAreaOption.type === window.AvoidAreaType.TYPE_SYSTEM ||
        avoidAreaOption.type === window.AvoidAreaType.TYPE_NAVIGATION_INDICATOR) {
        WindowUtil.setAvoidArea(avoidAreaOption.type, avoidAreaOption.area);
      } else if (avoidAreaOption.type === window.AvoidAreaType.TYPE_KEYBOARD) {
        const globalInfoModel: GlobalInfoModel =
          AppStorageV2.connect(GlobalInfoModel, StorageKey.GLOBAL_INFO, () => new GlobalInfoModel()) ?? new GlobalInfoModel();
        globalInfoModel.keyboardHeight = WindowUtil.uiContext.px2vp(avoidAreaOption.area?.bottomRect?.height ?? 0);
        AppStorageV2.connect(GlobalInfoModel, StorageKey.GLOBAL_INFO, () => globalInfoModel);
      }
    });
  } catch (err) {
    Logger.error(TAG, `getWindowAvoidArea failed. error message: ${err.message}`);
  }
}
```

### 第四步：`setWindowSize` 更新断点

```typescript
public static setWindowSize(windowSize?: window.Size | window.Rect) {
  const globalInfoModel: GlobalInfoModel =
    AppStorageV2.connect(GlobalInfoModel, StorageKey.GLOBAL_INFO, () => new GlobalInfoModel()) ?? new GlobalInfoModel();

  if (windowSize) {
    const vpHeight = WindowUtil.uiContext.px2vp(windowSize.height);    // ★px → vp
    const vpWidth = WindowUtil.uiContext.px2vp(windowSize.width);
    globalInfoModel.deviceHeight = vpHeight;
    globalInfoModel.deviceWidth = vpWidth;
    if (vpHeight > 0) {
      globalInfoModel.aspectRatio = vpWidth / vpHeight;               // 注意：这里是 宽/高
    }
  }

  // ★ 核心两行：让系统算断点
  globalInfoModel.widthBreakpoint = WindowUtil.uiContext.getWindowWidthBreakpoint();
  globalInfoModel.heightBreakpoint = WindowUtil.uiContext.getWindowHeightBreakpoint();

  // 特殊形态判定（是否需要动态隐藏标题栏）
  if ((globalInfoModel.widthBreakpoint === WidthBreakpoint.WIDTH_SM &&
    (globalInfoModel.aspectRatio > CommonConstants.ASPECT_SQUARE_PORTRAIT)) ||
    (globalInfoModel.widthBreakpoint === WidthBreakpoint.WIDTH_MD &&
      (globalInfoModel.aspectRatio > CommonConstants.ASPECT_LANDSCAPE_SQUARE))) {
    globalInfoModel.needDynamicHideBar = true;
  } else {
    globalInfoModel.needDynamicHideBar = false;
  }

  AppStorageV2.connect(GlobalInfoModel, StorageKey.GLOBAL_INFO, () => globalInfoModel);
}
```

**两个阈值常量**（`common/CommonConstants.ets`）：

```typescript
export class CommonConstants {
  public static ASPECT_LANDSCAPE_SQUARE: number = 9 / 7.2;    // ≈ 1.25
  public static ASPECT_SQUARE_PORTRAIT: number = 9 / 10.8;    // ≈ 0.833
}
```

含义：当窗口变得「太扁」时（比如手机横屏、平板横屏），
屏幕竖直空间很少，标题栏占地方，所以标记 `needDynamicHideBar = true`。

> ⚠️ **注意**：`needDynamicHideBar` 目前**没有加 `@Trace`**，
> 而且当前代码里没有地方消费它。这是一个**已实现但未接线**的能力。

```
    └─────────────────────────────────────────────────────────┘

    │  组件在 build() 里读断点，选择渲染哪套 UI                   │
    │  if (BreakpointUtil.isWide(bp)) { 宽屏 } else { 手机 }    │
    └─────────────────────────────────────────────────────────┘
```

** 规则：永远从 `GlobalInfoModel` 读，不要自己去查窗口。**

```typescript
// ❌ 不要这样
const bp = this.getUIContext().getWindowWidthBreakpoint();

// ✅ 要这样
const bp = this.globalInfoModel.widthBreakpoint;
```

**为什么**：统一数据源。如果每个组件自己查，会出现「有的组件已经更新了、有的还没」的不一致状态。

### ⚠️ 一个已知缺陷

`WindowUtil` 注册了两个监听器（`windowSizeChange`、`avoidAreaChange`），
但**没有对应的 `off()` 反注册**。

理论上 App 生命周期内只注册一次、不需要注销，所以目前没有实际问题。
但如果你以后要加新的监听器，**请成对写 `on` / `off`**：

```typescript
public static release(): void {
  WindowUtil.windowClass?.off('windowSizeChange');
  WindowUtil.windowClass?.off('avoidAreaChange');
}
```

```typescript
private pagePadding(): number {
  return new BreakpointType<number>({ sm: 16, md: 24, lg: 28, xl: 32 })
    .getValue(this.globalInfoModel.widthBreakpoint);
}

private bottomPadding(): number {
  return this.isWideLayout() ? 36 : 124;
  //     宽屏没有 TabBar，只留 36；手机要避开 TabBar，留 124
}

private contentTopPadding(): number {
  if (this.isWideLayout()) return 0;              // 宽屏没有 HDS 标题栏
  return this.topPadding() + this.titleBarHeight();
}

private expandMaxWidth(): number {
  // 展开页在大屏上的最大内容宽度
}
```

### 分叉层级总结

```
第 1 层：手机 vs 宽屏          → MainPage.isWideLayout()
第 2 层：角色（护工/医师/管理）  → MainPage.wideShell()
第 3 层：平板 vs PC            → compactWidth 参数
第 4 层：XL 特殊处理           → admissionCompactWidth
第 5 层：具体数值              → BreakpointType<T>
```

每一层只负责一个维度的判断，职责边界清晰，是本项目架构的核心设计。

```typescript
import { mediaquery } from '@kit.ArkUI';

    this.isWide = result.matches;
```

**老一代做法**，现在推荐用 `getWindowWidthBreakpoint()`。

### 技术 6：`deviceInfo` 判断设备类型

```typescript
import { deviceInfo } from '@kit.BasicServicesKit';

const type: string = deviceInfo.deviceType;   // 'phone' | 'tablet' | '2in1' | 'wearable' | 'tv' | 'car'
```

**⚠️ 不推荐用它做布局判断**。原因：
- 平板上 App 可能在小窗口运行 → 应该用手机布局
- PC 上窗口可能拉得很宽 → 应该用宽屏布局

**设备类型 ≠ 窗口尺寸。永远按窗口断点判断布局。**

`deviceInfo` 只适合判断「有没有某种硬件能力」（比如有没有摄像头、支不支持手写笔）。

### 技术 7：多 Product 多 Module（`MusicHome` 示例的做法）

```
MusicHome/
├── products/
│   ├── default/     ← 手机
│   ├── pc/          ← PC
│   ├── tv/          ← 电视
│   └── watch/       ← 手表
├── features/        ← 共享的功能模块
│   ├── player/
│   ├── playlist/
│   └── recommendation/
└── common/
    └── musicbasic/  ← 共享基础库
```

**每种设备一个 product，共享 features/common。**

`build-profile.json5` 里配置：

```json5
{
  "app": {
    "products": [
      { "name": "default", "targets": [...] },
      { "name": "pc", "targets": [...] },
      { "name": "tv", "targets": [...] }
    ]
  }
}
```

构建时指定：

```bash
hvigorw assembleHap -p product=tv
```

**什么时候需要这么做**：设备差异大到「代码都没法共用」（比如手表只有 466×466 圆屏，电视要遥控器操作）。

**本项目只有一个 product（`default`）**，因为手机/平板/PC 的差异用断点就能覆盖。

## 9.7 一多适配实操清单

### 做一个新界面时，按这个顺序想

```
1. 这个界面在手机上是什么样？（单列、点进详情）
2. 在平板上呢？信息架构要不要变？（列表+详情同屏？）
3. 在 PC 上呢？要不要加侧边栏、右键菜单、键盘快捷键？
4. 三种形态是「同一套 UI 缩放」还是「不同的实现」？
   ├─ 同一套 → 用 BreakpointType<T> 调数值就行
   └─ 不同 → 写两个 @Builder，用 if 分叉
5. 有没有需要键盘/鼠标支持的？（focusable / onHover / onKeyEvent）
6. 深色模式检查过了吗？
7. 大屏上内容有没有限宽？（constraintSize maxWidth）
```

### PC / 平板必须补的交互

**本项目在 `WideSlidingCapsule.ets` 里做了完整示范**：

```typescript
@Local hoveredIndex: number = -1;      // 鼠标悬停
@Local focusedIndex: number = -1;      // 键盘焦点

// 键盘激活（回车/空格）
private activateWithKeyboard(event: KeyEvent, action: () => void): void {
  if (event.type === KeyType.Down &&
    (event.keyCode === KeyCode.KEYCODE_ENTER || event.keyCode === KeyCode.KEYCODE_SPACE)) {
    action();
  }
}

// 在组件上
Row({ space: ... }) { }
  .backgroundColor(this.selectedIndex !== item.index && this.hoveredIndex === item.index ?
    $r('sys.color.interactive_hover') : Color.Transparent)          // ← 悬停高亮
  .border({ width: this.focusedIndex === item.index ? 2 : 0,
            color: $r('app.color.brand_blue') })                     // ← 焦点边框
  .focusable(true)                                                   // ← 可聚焦
  .focusOnTouch(true)
  .accessibilityText(this.accessibilityLabel(item))                  // ← 无障碍
  .accessibilityRole(AccessibilityRoleType.BUTTON)
  .accessibilitySelected(this.selectedIndex === item.index)
  .animation({ duration: 180, curve: Curve.EaseOut })
  .onFocus(() => { this.focusedIndex = item.index; })
  .onBlur(() => { if (this.focusedIndex === item.index) this.focusedIndex = -1; })
  .onHover((isHover: boolean) => { this.hoveredIndex = isHover ? item.index : -1; })
  .onKeyEvent((event: KeyEvent) => { this.activateWithKeyboard(event, () => this.onSelect(item.index)); })
  .onClick(() => { this.onSelect(item.index); })
```

**PC 交互检查清单**：

```
□ .focusable(true)        —— 能不能 Tab 键切到它
□ .onFocus / .onBlur      —— 聚焦时有没有视觉反馈
□ .onHover                —— 鼠标悬停有没有反馈
□ .onKeyEvent             —— 回车/空格能不能激活
□ .stateStyles({ hover })  —— 或者用 stateStyles
□ 右键菜单                 —— .bindContextMenu(builder, ResponseType.RightClick)
□ 无障碍标签               —— .accessibilityText / .accessibilityRole
```

## 9.9 常见问题

### Q1：断点变了但界面没变？

检查：
1. 是不是自己调了 `getWindowWidthBreakpoint()` 而不是读 `GlobalInfoModel`？
2. `GlobalInfoModel.widthBreakpoint` 有没有 `@Trace`？（有）
3. 组件有没有 `AppStorageV2.connect` 到同一个 key？

### Q2：状态栏高度是 0？

`WindowUtil.initialize()` 还没跑完就渲染了。
本项目的做法是 `loadContent` 的回调里才调 `initialize`，所以首帧可能是 0。
`@Trace` 会在拿到真值后触发重绘，所以最终是对的，但**首帧可能闪一下**。

### Q3：状态栏高度大得离谱（比如 108）？

忘了 `px2vp`。系统返回的是 px。

### Q4：PC 上窗口很宽，但界面还是手机布局？

检查 `module.json5` 的 `deviceTypes` 有没有包含 `2in1`：

```json5
"deviceTypes": ["phone", "tablet", "2in1"]
```

### Q5：`BreakpointType` 的 `xs` 和 `xl` 可以不传吗？

可以。`xs` 不传自动用 `sm`，`xl` 不传自动用 `lg`。

### Q6：怎么判断是不是折叠屏？

```typescript
import { display } from '@kit.ArkUI';
const foldable: boolean = display.isFoldable();
const status: display.FoldStatus = display.getFoldStatus();
```

本项目预留了 `GlobalInfoModel.foldExpanded` 字段，但没接线。

### Q7：横屏时布局乱了？

手机横屏后宽度可能达到 `WIDTH_MD`，触发宽屏布局。
如果不想这样，需要额外判断 `heightBreakpoint`：

```typescript
private isRealWide(): boolean {
  return BreakpointUtil.isWide(this.globalInfoModel.widthBreakpoint) &&
    this.globalInfoModel.heightBreakpoint !== HeightBreakpoint.HEIGHT_SM;
  //  ↑ 排除「很扁」的形态（手机横屏）
}
```

**本项目没做这个判断**（`isWideLayout()` 只看宽度），所以手机横屏会进宽屏布局。
这是一个可以改进的点。

## 9.10 本章速查

```typescript
import { BreakpointType, BreakpointUtil } from '../util/BreakpointSystem';

// —— 读断点（永远从 GlobalInfoModel 读）——
@Local globalInfoModel: GlobalInfoModel =
  AppStorageV2.connect(GlobalInfoModel, StorageKey.GLOBAL_INFO, () => new GlobalInfoModel()) ?? new GlobalInfoModel();

private isWideLayout(): boolean {
  return BreakpointUtil.isWide(this.globalInfoModel.widthBreakpoint);
}

// —— 断点常量 ——
WidthBreakpoint.WIDTH_XS   // < 320vp
WidthBreakpoint.WIDTH_SM   // 320 ~ 600vp    手机
WidthBreakpoint.WIDTH_MD   // 600 ~ 840vp    折叠屏展开/小平板
WidthBreakpoint.WIDTH_LG   // 840 ~ 1440vp   平板/PC
WidthBreakpoint.WIDTH_XL   // >= 1440vp      大屏 PC

HeightBreakpoint.HEIGHT_SM // aspectRatio(高/宽) < 0.8    很扁
HeightBreakpoint.HEIGHT_MD // 0.8 ~ 1.2                  接近方形
HeightBreakpoint.HEIGHT_LG // >= 1.2                     很竖

// —— 判定工具 ——
BreakpointUtil.isWide(bp)        // MD/LG/XL
BreakpointUtil.isTablet(bp)      // MD
BreakpointUtil.isPc(bp)          // LG/XL
BreakpointUtil.isExtraWide(bp)   // LG/XL（同 isPc）

// —— 按断点取值 ——
new BreakpointType<number>({ sm: 16, md: 24, lg: 28, xl: 32 })
  .getValue(this.globalInfoModel.widthBreakpoint)

// —— 布局分叉 ——
build() {
  if (this.isWideLayout()) { this.wideLayout() }
  else { this.phoneLayout() }
}

// —— 大屏限宽 ——
Row() {
  Column() { }.width('100%').constraintSize({ maxWidth: 960 })
}.width('100%').justifyContent(FlexAlign.Center)

// —— PC 交互 ——
.focusable(true).focusOnTouch(true)
.onHover((h: boolean) => { this.hovered = h; })
.onFocus(() => { }).onBlur(() => { })
.onKeyEvent((e: KeyEvent) => {
  if (e.type === KeyType.Down && (e.keyCode === KeyCode.KEYCODE_ENTER || e.keyCode === KeyCode.KEYCODE_SPACE)) {
    this.activate();
  }
})
```
